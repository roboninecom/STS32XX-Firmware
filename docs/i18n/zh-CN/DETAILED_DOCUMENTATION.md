# 详细文档

从**[快速入门](QUICKSTART.md)**指南开始，进行刷写、测试、重播和重力补偿。有关各个命令指南，请参阅[工具](tools/README.md)。

GD32F130-based STS3215舵机固件，有两种控制电机的方式：

- **传统模式** 使用标准 STS 命令来表示位置、速度和电机功率。默认情况下它是启用的。
- **扩展模式**增加了平滑运动、可调节位置控制以及运动和重力补偿。连接的计算机发送设置和目的地；每个伺服系统在本地计算其运动。

本文档解释了这些功能的工作原理，然后提供了 **扩展协议 v9.0** 的命令和寄存器参考。扩展设置保存在临时内存中，并且必须在重置或重新启动后再次发送。控制软件必须支持版本9；旧版扩展客户端不兼容。

<a id="legacy-mode"></a>
## 传统模式

传统模式支持标准STS寄存器接口，包括电机功率、操作模式、位置和速度命令以及状态读数。现有的STS软件可以使用寄存器**0–86**，而无需启用扩展。

在传统位置模式下，无需新位置命令即可启用电机电源，即使在保存的限制之外，也能保持测量位置。它不会重播旧目标或将轴移动到最近的限制。新位置命令仍受限于已保存的限制。

该扩展使用自己的运动和控制设置。不应在两种模式之间直接复制增益值，因为它们的比例不同。对标准命令的支持并不能保证所有伺服型号具有相同的物理行为。

<a id="how-extension-mode-works"></a>
## 扩展模式如何工作

[在 YouTube 上观看录制的概述](https://youtu.be/AsxFs24vXQs) | [MP4](../../../assets/readme/videos/overview.mp4)

**主机**是连接到伺服系统的计算机或控制器。它发送一个**目标**：目的地和速度限制。加速度和补偿设置在启用电机电源之前配置。每个舵机则：

1. 计划顺利前往目的地。
2. 测量其位置并估计其速度。
3. 调整电机输出以遵循计划的运动。
4. 运动完成时保持目的地。

任意时刻的计划位置和速度称为**参考**。控制器将它们与测量的运动进行比较，因此参考位置和实际位置可能不同。

本文档中使用的一些术语：

| 期限 | 含义 |
| --- | --- |
| 编码器数量 | 位置测量单元；名义上每转 4096 计数 |
| 努力 | 带符号 motor-output 命令：其符号设置方向，其大小设置输出强度 |
| 增益 | 确定控制器响应强度的设置 |
| 前馈 | 根据预期需求计算额外的电机输出，而不是等待位置或速度错误 |
| 反馈意见 | 伺服返回的测量值和状态 |
| 注册 | 由数字标识的设置或读数 |
| 会议 | 一段分机控制，由主机提供的号码标识 |

作用力以 PWM 单位表示，该单位用于控制电机的电力输出。该扩展允许任一方向的输出限制高达 **1000**。这些值不是扭矩或电流的直接测量值。

<a id="s-curve-motion"></a>
## S-curve运动

[![s-curve运动](../../../assets/readme/illustrations/s-curve.png)](https://youtu.be/92mDt4rbobY)的概念图

[在 YouTube 上观看](https://youtu.be/92mDt4rbobY) | [MP4](../../../assets/readme/videos/s-curve.mp4)

使加速和制动更加平缓。该曲线说明了随时间变化的加速度。概念图，不是测量的硬件数据。

S-curve 使加速度逐渐增大和减小。伺服系统不会突然施加完全加速或制动，而是轻松进出运动的每个部分。这可以减少机械震动和振动。

从休息到休息的完整运动有以下几个阶段：

| 舞台 | 会发生什么 |
| --- | --- |
| 1 | 加速度逐渐增大 |
| 2 | 舵机以稳定的速度加速 |
| 3 | 加速度逐渐减小至零 |
| 4 | 舵机以稳定速度移动 |
| 5 | 制动逐渐增强 |
| 6 | 伺服制动以稳定的速度进行 |
| 7 | 随着舵机停止制动逐渐减弱 |

当没有足够的距离来达到所请求的速度或加速度时，短距离移动会跳过阶段。加速和减速时适用相同的加速度限制。

`ramp_time_ms` 设置控制加速度从零上升到极限所需的时间。较长的坡道提供更温和的变化，但通常需要更多的时间和距离来加速或停止。

**加加速度**是指加速度变化的速率。该规划器限制了加加速度，因此加速度变化平稳。混蛋本身仍然可以在阶段之间突然改变。其大致大小为：

```text
jerk = 1000 × acceleration / ramp_time_ms    [counts/s³]
```

<a id="changing-a-destination-during-movement"></a>
### 移动过程中更改目的地

新目标从当前计划的运动继续，保留其位置、速度和加速度。再次发送相同的目的地不会重新启动移动。移动时保持相同的请求速度限制；一旦计划的运动停止，它就可以更改为下一步的运动。加速和斜坡时间属于配置，需要关闭电机电源并撤防会话才能更改。

保存的 Legacy 位置限制以外的目标会被**调整到最近的边界**。请求速度也受其配置上限约束。伺服电机在每次移动中使用配置的加速度。速度为零或配置的加速度为零均无效。

整个计划的运动必须保持在位置限制之内。因此，如果伺服电机已经接近极限太快而无法在其中停止，即使目的地本身是允许的，新的目标也会被拒绝。

到达目的地后，伺服电机在电机通电的情况下自动保持目的地。由于摩擦、负载、输出限制或调整，测量的位置可能仍然存在一些误差。保持继续修正位置误差；它不会将电机输出冻结在固定值。

每个伺服系统都计划自己的运动。一起发送多个目标并不能保证所有伺服系统同时到达。

<a id="shared-position-limits"></a>
### 共享仓位限制

旧版和扩展控制使用相同的 position-limit 寄存器：**9–10** 包含最小值，**11–12** 包含最大值。每个都是校正编码器计数中的无符号 16 位值，包括伺服配置的方向和位置校正。没有单独的扩展 position-limit 设置。

校准将编码器计数分配给物理位置。 [校准工具](tools/settings/README.md#choose-the-reference-pose)将捕获的参考位姿读取为2048，然后测量行程限制。该计数不会自动成为 zero-degree 关节角度，并且测量的行程中点不会替换捕获的参考。重力模型和可视化需要匹配的 count-to-angle 映射。

固件在启动控制时读取这些寄存器。启用位置限制后，最小值必须小于最大值，最大值不得超过 32767，且测得的位置必须在此范围内。否则启动失败，电机不会开始运动。规划器将整个运动过程（包括制动）保持在读取的范围内。

**相等的最小值和最大值会禁用行程限制**，与传统行为相匹配。扩展命令仍然保持在 −32767 到 32767 计数支持的位置范围内。

对任一限制的接受写入都会结束活动的扩展会话并关闭电机电源，包括仅在 RAM 中应用的写入。准备一个新会话以使用更改后的值。正常的旧设置持久性仍然适用。

<a id="pid-controller"></a>
## PID控制器

[![pid控制概念图](../../../assets/readme/illustrations/pid-tuning.png)](https://youtu.be/TEpvaAMlfrg)

[在 YouTube 上观看](https://youtu.be/TEpvaAMlfrg) | [MP4](../../../assets/readme/videos/pid-tuning.mp4)

调整伺服系统纠正位置误差的方式。灰色曲线表示振荡；白色曲线说明了更阻尼的响应。虚线是目标。概念图，不是测量的硬件数据。

PID 控制器调整电机输出以遵循计划的运动。它的三种设置有不同的作用：

| 设置 | 它的作用 | 主要权衡 |
| --- | --- | --- |
| **P — 位置修正** | 将电机拉向计划位置；较大的错误产生更多的纠正 | 较高的 P 可以减少误差，但也会引起振荡 |
| **I——累计修正** | 当错误仍然存在时建立额外的纠正 | 可以减少持久误差，但可能会增加超调或稳定时间 |
| **D——速度修正** | 对计划速度和测量速度之间的差异做出反应；按住时抵抗移动 | 可以改善阻尼，但对嘈杂的速度读数的过度响应可能会导致输出不均匀 |

计算公式为：

```text
position error = planned position − measured position
speed error = planned speed − filtered measured speed

motor output = Kp × position error
             + Kd × speed error
             + accumulated I correction
             + gravity compensation
             + velocity feedforward
```

结果仅限于配置的最大输出。电机保护可以进一步减少它。反馈报告请求的输出和应用的输出，以便主机可以看到电机何时受到限制。

使用最近的位置读数和可调节滤波器对测量的速度进行平滑处理。 `velocity_filter_q8` 设置越大，对变化的响应速度越快，但消除的测量噪声越少。

<a id="preventing-excessive-accumulated-correction"></a>
### 防止累积校正过多

I 的贡献有其自身的局限性。控制器还可以防止其继续沿着电机输出已经受到限制的方向构建；这通常称为 **anti-windup**。它仍然可以减少以帮助电机从该极限恢复。将 `Ki` 设置为零会禁用并清除 I 校正。

当伺服电机接近静止状态至少 50 ms 并且位置误差在一个编码器计数范围内时，I 停止累加。 P、D 和两种形式的前馈保持活动状态。关闭电机输出会清除 I 校正。

<a id="velocity-feedforward"></a>
## 速度前馈

[![速度前馈的概念图](../../../assets/readme/illustrations/velocity-feedforward.png)](https://youtu.be/osGGs-nhk9I)

[在 YouTube 上观看](https://youtu.be/osGGs-nhk9I) | [MP4](../../../assets/readme/videos/velocity-feedforward.mp4)

根据伺服系统内部计算的计划速度添加电机输出。两条曲线随着时间的推移从左向右发展。概念图，不是测量的硬件数据。

速度前馈提供了在出现跟踪误差之前预计运动所需的一些输出。它是根据计划速度在**伺服系统内部**计算得出的：

```text
velocity feedforward = velocity gain × planned speed
```

每个方向都有一个增益，并且对结果输出有限制。两个增益都是非负的；运动方向决定输出符号。其输出限制必须不大于主motor-output限制。

由于伺服电机知道自己的计划速度，因此补偿会自动跟随加速和制动，并在计划运动停止时变为零。主机仅提供其设置；它不需要发送连续的velocity-feedforward值。

当电机电源关闭且会话撤防时，将此功能与`0xA0`中的其他设置一起配置。将增益及其输出限制设置为零以禁用它。

<a id="gravity-compensation"></a>
## 重力补偿

[![重力补偿概念图](../../../assets/readme/illustrations/gravity-compensation.png)](https://youtu.be/25sc41PTDIA)

[在 YouTube 上观看](https://youtu.be/25sc41PTDIA) | [MP4](../../../assets/readme/videos/gravity-compensation.mp4)

主机计算贡献，伺服电机应用它。向下的箭头代表重量；向上的箭头代表支撑。概念图，不是测量的硬件数据。

重力补偿提供支撑手臂及其负载重量所需的输出。即使电机保持静止（速度前馈为零），它也很有用。

**主机计算重力补偿**并向每个舵机发送带符号的输出值。计算可以使用关节角度、臂尺寸、连杆重量和有效负载。主机必须将估计的负载转换为伺服电机的输出单位。固件不包含手臂的型号。

方向很重要：正扩展输出随着编码器计数的增加而变化。 Arm 的 joint-angle 约定可能会以相反的方向运行，因此主机的转换必须考虑到这一点。

每个重力更新都包含所需的输出值。 **转换速率**（补偿变化的速度，以每秒输出单位为单位）是主要配置的一部分，并且在整个会话期间保持固定。

伺服系统逐渐将其补偿更改为请求值，并将其添加到控制器输出中。所有贡献仍然受到配置的输出限制和电机保护的影响。

**如果重力更新停止到达，伺服系统将以其配置的转换速率继续执行最后请求的补偿，然后保持该值。** 没有到期计时器。当手臂姿势或负载发生变化时，主机应更新补偿。将 torque-enable 寄存器 **40** 设置为零可清除补偿并关闭电机输出。

<a id="starting-and-stopping-extension-mode"></a>
## 启动和停止扩展模式

以下序列使用稍后记录的寄存器编号和命令。选择准备会议；启用电机电源启动控制。

1. 找到连接的伺服电机 ID 并读取每个伺服电机的功能。检查 `ARMC` 和版本 `9.0`。重置或更改固件后重复此检查。
2. 通过将传统 torque-enable 寄存器 **40** 设置为 `0` 来关闭电机电源。完成任何现有会话并应用任何永久旧设置。
3. 写入并读回完整配置 (`0xA0`)，包括速度前馈设置和重力转换速率。
4. 将 `mode=1` 和新的非零会话号写入 `0xB8`（总共3 字节）。这样就选择了扩展模式，为下次启动做准备；电源仍然关闭。
5. 将寄存器 **40** 设置为 `1`。固件检查传感器、保护状态、配置和保存的位置限制，然后捕获测量的位置作为初始保持目标。命令计数器、I 校正和重力补偿从零开始。读取`0xC1`并等待正确的会话、当前可用的测量、电机驱动器启用和输出准备就绪。
6. 发送目标和任何重力更新。读取反馈以检查哪些命令被接受以及伺服电机遵循这些命令的紧密程度。
7. 伺服系统完成最后一次移动并保持目的地，直到给出新的目标。将寄存器 **40** 设置为 `0` 以关闭电机电源并结束会话。要返回传统模式，请保持电源关闭并将`mode=0, session=0`写入`0xB8`。

如果启动失败，寄存器**40**返回到`0`。仅其正常写入确认并不能确认启动成功：检查寄存器回读和反馈。每次启动尝试都会消耗准备好的会话。启动失败、torque-off 或保护关闭后，请纠正原因并在再次启用扭矩之前用新的会话编号写入`0xB8`。在控制运行时重复扭矩启用可保留其目标、补偿和命令计数器。

移动或调整动力电机的命令需要准备好硬件、没有报告的故障，并且传感器读数不超过 **2 ms** 旧。控制器通常每 **1 ms** 更新一次，并接受最多 2 ms 的间隔。较长的间隙会导致电机输出被禁用。

使用扩展时，避免对操作模式寄存器 **33** 或运动寄存器 **41–47** 进行传统写入：它们会关闭电机电源并离开扩展模式。保存永久设置也会结束扩展控制。将寄存器 **40** 设置为 `0` 会选择扩展模式，为另一个会话设置做好准备。

<a id="if-host-commands-stop-arriving"></a>
### 如果主机命令停止到达

伺服系统完成最后接受的移动并保持该目的地。重力补偿继续接近其最后请求的值并保持在那里。不需要重复消息来保持会话活动，并且主机通信丢失本身不会改变目标或关闭电机电源。

要更改伺服系统的位置，请发送另一个目标。要释放电机，请将扭矩启用设置为零。传感器新鲜度检查、电机保护和固件看门狗在移动和保持时保持活动状态。

<a id="extension-protocol"></a>
## 扩展协议

本节描述主机和伺服电机之间交换的确切消息。它旨在供读者连接自己的软件。

<a id="message-format-and-number-encoding"></a>
### 消息格式和数字编码

每条消息都是一个数据包：包含目的地、命令、数据以及用于检测传输错误的校验和的字节序列。扩展命令使用标准的STS数据包格式：

```text
Request:  FF FF ID LENGTH INSTRUCTION PARAMETERS... CHECKSUM
Response: FF FF ID LENGTH LEGACY_ERROR EXT_STATUS DATA... CHECKSUM
```

- 请求`LENGTH = parameter_bytes + 2`。
- 响应`LENGTH = data_bytes + 3`；扩展状态占据第一个响应参数，与正常的遗留错误字节分开。
- `CHECKSUM = ~(ID + LENGTH + instruction_or_error + all_parameter_bytes) & 0xFF`。响应总和包括`EXT_STATUS`和任何数据。
- 占用多个字节的字段首先发送最低有效字节（**little-endian**）。例如，数字256以两个字节作为`00 01`发送。
- `u8`、`u16`、`u32`为非负整数，占用1、2、4字节。 `i16`和`i32`占用2和4字节，也可以表示负数。带符号扩展值使用**二进制补码**：例如，−1 在 `i16` 字段中是 `FF FF`。这与有符号值的传统编码不同。
- **Q8** 表示在传输之前将值乘以 256，因此分数可以表示为整数。读取时除以256。例如，位置1000计数作为256000发送，增益4.5作为1152发送。
- 位置以编码器计数表示，速度以 counts/s 表示。主机处理关节角度的任何转换，包括方向或零位置的变化。
- **单播**是指发送至一个伺服系统的消息。 **广播**使用ID`0xFE`并到达所有舵机。广播扩展命令永远不会生成回复。

示例：从伺服ID1读取8字节功能块：

```text
FF FF 01 04 90 90 08 D2
```

**选择器**标识完整的寄存器块，例如配置或反馈。使用扩展名 READ/WRITE 和下面列出的确切块大小访问它。不支持仅读取或写入块的一部分，并且旧版 READ/WRITE 命令无法访问这些块。

<a id="instructions"></a>
### 使用说明

下面的参数大小不包括数据包标头和校验和。在回复中，`EXT_STATUS`报告扩展命令是否成功，与`LEGACY_ERROR`（舵机的正常错误字节）分开。成功读取会将请求的数据添加到`EXT_STATUS`之后；写入、其他命令和失败的读取没有额外的数据。

| 说明 | 名称 | 参数 | 广播 |
| --- | --- | --- | --- |
| `0x90` | READ | `selector:u8, count:u8` | 没有有用的回应 |
| `0x91` | WRITE | `selector:u8, block...` | 不接受 |
| `0x99` | GRAVITY | 6 字节，如下 | 不接受 |
| `0x9A` | TARGETS | `session:u16` + 1–6 9 字节条目 | 已接受 |

指令编号`0x92`、`0x93`、`0x94`、`0x95`、`0x96`、`0x97`和`0x98`，以及选择器`0xA1`、`0xA3`、`0xB0`、`0xBA`、`0xE0`和`0xF0`，已保留，不得使用。

| 分机状态 | 含义 |
| --- | --- |
| `0` | OK |
| `1` | 长度、选择器或字段值无效 |
| `2` | 当前状态下无法接受命令 |
| `3` | 保留 |
| `4` | 保留 |
| `5` | 不支持的指令 |

会话不匹配会返回状态失败。检查遗留错误字节和扩展状态。

<a id="sessions-and-sequence-numbers"></a>
### 会话和序列号

主机为每个会话分配一个从1到65535的编号，并将其包含在控制命令中。这让伺服电机检查命令是否属于当前会话。为每次启动选择一个新号码；设置编号不会永久存储。

**序列号**按顺序对接受的命令进行计数，允许主机和伺服电机识别丢失、重复或out-of-order命令。

TARGETS 有一个per-servo 运动序列计数器。 GRAVITY有一个单独的柜台。当扭矩使能开始控制时，两者都从零开始；通常先发送**1**。数字通过 65535 增加，然后换行至 **0**，但不会结束会话。允许有间隙：在10之后，即使11丢失或拒绝，舵机也可以接受12。在不更改当前命令的情况下，相同或较旧的数字将被拒绝。

为了进行精确比较，请计算 `distance = (incoming − accepted) & 0xFFFF`。仅当 `1 ≤ distance ≤ 32767` 时命令才较新。恰好 32768 的跳跃是不明确的并且被拒绝。保持与最后接受的命令的间隙低于32768；如果命令历史不确定，请关闭扭矩，准备新会话ID，然后再次启用扭矩。不要重复使用早期会话或计数器周期中的排队数据包。

验收仍然需要有效的字段、当前传感器读数和可行的运动。被拒绝的命令不会推进其计数器。这些命令取代绝对目标；它们不是航路点队列。要访问每个航点，请等待每个到达点，然后再发送下一个目的地。

发送组目标时，读取每个舵机的反馈以验证其接受的序列。每个舵机独立决定是否接受其目标；当其他人开始行动时，一个人可能会拒绝它。

<a id="targets--0x9a"></a>
### TARGETS — `0x9A`

前两个参数字节包含共享会话。以下每个条目都有此布局；偏移量是相对于该条目的开头的：

| 偏移量 | 类型 | 领域 |
| --- | --- | --- |
| 0 | `u8` | 伺服ID、1–253 |
| 1 | `u16` | 该伺服系统的较新运动序列 |
| 3 | `i32` | 目标位置，Q8计数 |
| 7 | `u16` | 最大速度，counts/s，非零 |

参数长度为`2 + 9 × entry_count`，最多56字节。 ID 必须是唯一的。每个伺服系统在处理自己的条目之前都会检查**所有**条目的格式和必需字段。未列出的伺服系统不执行任何操作。列出的伺服系统会检查其会话、顺序、准备情况以及运动是否可以保持在其限制范围内。接受的目标会立即启动并保持活动状态，直到被替换或解除武装。值的上限为配置的限制，如 S-curve 运动中所述。

<a id="gravity--0x99"></a>
### GRAVITY — `0x99`

| 偏移量 | 类型 | 字段/约束 |
| --- | --- | --- |
| 0 | `u16` | 当前会话 |
| 2 | `u16` | 较新的重力序列 |
| 4 | `i16` | 所需的重力作用；幅度 ≤ 配置的输出限制 |

参数长度正好是6字节。需要在电机电源打开、硬件准备就绪、没有报告的故障以及最近的传感器读数的情况下进行武装会话。它不会推进运动序列。所请求的值在更换或撤防之前保持活动状态。

## 扩展寄存器

**偏移**是字段的起始字节，在其块内从零开始计数。以下偏移量为十进制；选择器使用十六进制表示法（`0x...`）。所有写入都使用指令`0x91`；读取时使用 `0x90` 和精确的字节数。

| 选择器 | 块 | 访问 | 字节 |
| --- | --- | --- | --- |
| `0x90` | 能力 | 阅读 | 8 |
| `0xA0` | 配置 | Read/write | 24 |
| `0xB8` | 控制器选择和会话设置 | 写 | 3 |
| `0xC1` | 运营反馈 | 阅读 | 32 |
| `0xC2` | 调整反馈 | 阅读 | 54 |

<a id="capabilities--0x90"></a>
### 能力 — `0x90`

| 偏移量 | 类型 | 价值/意义 |
| --- | --- | --- |
| 0–3 | 4 字节 | ASCII `ARMC` |
| 4 | `u8` | 主要版本：9 |
| 5 | `u8` | 小版本：0 |
| 6 | `u8` | 保留：0 |
| 7 | `u8` | 正常控制器更新间隔：1 ms |

协议版本定义了可用的块及其确切长度。选择和会话设置共享一个 write-only 块，如下所述。

<a id="configuration--0xa0"></a>
### 配置 — `0xA0`

| 偏移量 | 类型 | 领域 | 单位/有效范围 |
| --- | --- | --- | --- |
| 0 | `u16` | `kp_q8` | 增益×256； 0–65535 |
| 2 | `u16` | `kd_q8` | 增益×256； 0–65535 |
| 4 | `u16` | `ki_q8` | 增益×256； 0–65535 |
| 6 | `u16` | `integral_limit` | 努力； 0–`effort_limit` |
| 8 | `u16` | `effort_limit` | 努力； 1–1000 |
| 10 | `u16` | `velocity_limit` | Counts/s; 1–65535 |
| 12 | `u16` | `acceleration_limit` | Counts/s²； 1–30000 |
| 14 | `u8` | `velocity_filter_q8` | Speed-filter响应； 1–255，越高响应越快 |
| 15 | `u8` | `ramp_time_ms` | 加速斜坡； 1–255 毫秒 |
| 16 | `u16` | `velocity_ff.positive_gain_q8` | 输出/(count/s)×256; 0–65535 |
| 18 | `u16` | `velocity_ff.negative_gain_q8` | 输出/(count/s)×256; 0–65535 |
| 20 | `u16` | `velocity_ff.effort_limit` | 努力； 0–主`effort_limit` |
| 22 | `u16` | `gravity_slew` | 报酬变化，努力units/s； 1–10000 |

增益以所需值乘以 256 的形式发送。它们的单位为 P 的 output/count、D 的输出 /(count/s) 和 I 的输出 /(count·s)。例如，P = 4.5 每个错误计数生成 4.5 输出单位，并作为 1152 发送。

伺服系统具有**一种活动配置**。写入它需要关闭电机电源并撤防会话。每次写入都会替换整个配置，包括前馈设置。无效的设置会拒绝整个写入而不更改任何内容。阅读 `0xA0` 检查已接受的设置。

Velocity-feedforward 收益是非负的。零前馈输出限制要求两个增益都为零。相同的前馈输出限制适用于两个方向，并且不得超过主输出限制。

复位后，在启用电机电源之前配置伺服。在主机上保留保存的设置和替代调整值；改变在手臂支撑和电机电源关闭的情况下运行之间的增益。

<a id="selection-and-session-setup--0xb8"></a>
### 选择和会话设置 — `0xB8`

| 偏移量 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 模式：`0`传统，`1`扩展 |
| 1 | `u16` | 会话：`0`用于旧版，`1–65535`用于扩展 |

确切的负载长度是 **3 字节**，会话按 little-endian 顺序排列。例如，会话`0x1234`的扩展模式为`01 34 12`；传统模式是`00 00 00`。无效组合拒绝整个写入而不改变状态。两种模式都需要关闭电机电源并替换任何早期的会话设置。仅选择并不能开始控制或占领保持位置。

旧版 torque-enable 寄存器 **40** 在写入 `1` 时启动准备好的扩展会话。它需要可用的电机输出、有效的配置、读数不超过2毫秒的初始化传感器、没有需要关闭的故障以及可用的已保存的旧位置限制。启用这些限制后，测量的位置必须在这些限制内。这些检查发生在启用时，因此会考虑设置和启用之间的移动或故障。

Torque-off 取消运行控制和未使用的设置。传感器故障、保护关闭、position-limit 或encoder-offset 更改、校准和保存永久设置也会使会话设置无效。读取反馈，检查控制是否真正开始；没有单独的 ARM 命令。前`0xBA`选择器和前one-byte选择有效负载被拒绝。

反馈描述了记录的测量结果。如果伺服电机的状态在主机读取之前发生变化，则某些字段可能会描述较早的状态。当测量值超过 2 毫秒时，控制器不再被选择、布防、驱动或准备就绪，或其 session/sequence 编号不再匹配时，位 0 将被清除。一起检查位0、年龄、会话和接受的序列。

<a id="tuning-feedback--0xc2"></a>
### 调整反馈 — `0xC2`

字节 0–31 具有完全相同的 `0xC1` 布局。剩余的字节是：

| 偏移量 | 类型 | 领域/单位 |
| --- | --- | --- |
| 32 | `i32` | 参考位置，Q8计数 |
| 36 | `i32` | 参考速度，Q8 counts/s |
| 40 | `i16` | 在其配置的限制之后、电机保护之前请求的输出 |
| 42 | `i16` | P 贡献、努力 |
| 44 | `i16` | D 贡献、努力 |
| 46 | `i16` | 整体贡献、努力 |
| 48 | `i16` | 当前应用的重力补偿，努力 |
| 50 | `i16` | 局部速度前馈、努力 |
| 52 | `u16` | 累计额外控制器延迟，ms；最大65535 |

每当控制器更新花费的时间超过正常 1 毫秒 (`elapsed_ms − 1`) 时，延迟计数器就会添加额外时间。它不计算丢失的消息。报告的 P 和 D 贡献仅限于 ±32767，因此添加显示的值可能无法重现完整的内部计算。

伺服系统仅在被要求时才发送反馈。正常监控时使用`0xC1`，调整需要附加值时使用`0xC2`。读取`0xC2`已经包含了所有`0xC1`，因此读取这两个会不必要地增加流量。单独的阅读可以指代不同的时刻；比较它们的时间戳和样本数。
