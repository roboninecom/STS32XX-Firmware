<a id="quick-start"></a>
# त्वरित शुरुआत

GD32F130-based STS TTL सर्वो के लिए। नीचे दिए गए कमांड macOS/Linux शेल सिंटैक्स का उपयोग करते हैं और रिपॉजिटरी रूट से चलते हैं। एक्सटेंशन मोशन टूल के लिए फर्मवेयर v9 की आवश्यकता होती है; लेगेसी रीप्ले फ़ैक्टरी फ़र्मवेयर का भी समर्थन करता है।

<a id="1-install"></a>
## 1. स्थापित करें

Node.js 20+ और Python 3.10+ स्थापित करें; वैकल्पिक सिमुलेशन व्यूअर को Python 3.12 की आवश्यकता है।

```sh
npm ci
python3 -m venv tools/flash/.venv
tools/flash/.venv/bin/python -m pip install -r tools/flash/requirements.txt
export SERVO_PORT=/dev/cu.usbmodemYOUR_ADAPTER
```

पोर्ट को अपने से बदलें, जैसे लिनक्स पर `/dev/ttyUSB0`। उदाहरण मोटर ID **1** और बॉड **1000000** का उपयोग करते हैं; इन्हें अपने सर्वो से मिलान करने के लिए समायोजित करें।

<a id="2-back-up-and-flash"></a>
## 2. बैकअप लें और फ़्लैश करें

**फ़र्मवेयर फ्लैश करने से सर्वो क्षतिग्रस्त हो सकता है या कैलिब्रेशन मिट सकता है।** तंत्र को सुरक्षित करें, स्थिर बिजली आपूर्ति दें, टॉर्क अक्षम करें और सीरियल पोर्ट इस्तेमाल करने वाले अन्य प्रोग्राम बंद करें। फ्लैश करने से पहले सेटिंग्स लॉक हों और अलार्म साफ़ हों। सामान्य कस्टम फ़र्मवेयर फ्लैश करते समय अलग-अलग ID वाली मोटरें जुड़ी रह सकती हैं: एक बार में एक ID फ्लैश करें और बस पर power-cycle न करें। रिकवरी के लिए केवल वही सर्वो जुड़ा होना चाहिए जिसे रिकवर करना है।

```sh
npm run settings -- discover --port "$SERVO_PORT"
npm run settings -- backup --port "$SERVO_PORT" --id 1
```

**एसेट्स** के अंतर्गत [v0.1-पूर्वावलोकन रिलीज](https://github.com/roboninecom/STS32XX-Firmware/releases/tag/v0.1-preview) से **कस्टम फर्मवेयर ZIP** डाउनलोड करें। इसकी फर्मवेयर छवि और `release.json` को एक साथ `tools/flash/releases/custom/` में निकालें। फ्लैशिंग के लिए GitHub के **सोर्स कोड** संग्रह का उपयोग न करें।

```sh
tools/flash/.venv/bin/python tools/flash/flash.py inspect \
  --manifest tools/flash/releases/custom/release.json
tools/flash/.venv/bin/python tools/flash/flash.py flash \
  --manifest tools/flash/releases/custom/release.json --port "$SERVO_PORT" --id 1
```

संकेत मिलने पर `FLASH` टाइप करें और सत्यापन समाप्त होने तक पावर कनेक्ट रखें। प्रत्येक मोटर ID के लिए फ़्लैश कमांड दोहराएं, हर बार सत्यापन की प्रतीक्षा करें। सत्यापन विफल होने पर [फ़्लैशिंग और पुनर्प्राप्ति](tools/flash/README.md) देखें।

**फ़ैक्टरी फ़र्मवेयर ZIP** फ़ैक्टरी फ़र्मवेयर पर लौटने के लिए है, नीचे दिए गए मोशन टूल के लिए नहीं। इसे एक अलग फ़ोल्डर में निकालें और फ्लैश करने के बाद [फ़ैक्टरी सेटिंग्स रेस्टोरेशन](tools/flash/README.md#restore-factory-settings) का पालन करें। प्रत्येक फ़र्मवेयर छवि को उसकी अपनी `release.json` के साथ रखें।

<a id="3-calibrate-joint-offsets-and-limits"></a>
## 3. संयुक्त ऑफसेट और सीमाओं को कैलिब्रेट करें

बंधी हुई संयुक्त यात्रा वाले तंत्र के लिए, अंशांकन के लिए मोटर आईडी का चयन करें:

```sh
npm run settings -- calibrate --port "$SERVO_PORT" --ids 1,2,3 \
  --file tools/settings/calibrations/arm.json
```

उदाहरण आईडी को अपने से बदलें; सभी खोजी गई मोटरों (छह तक) का उपयोग करने के लिए `--ids` को छोड़ दें। SO-101 और SO-102 के लिए, [लेबल संदर्भ मुद्रा छवियां](tools/settings/README.md#reference-pose-images) देखें। कमांड के दो चरण हैं:

1. कलाई रोल और ग्रिपर सहित प्रत्येक चयनित जोड़ को तंत्र के संदर्भ मुद्रा में रखें। बिना किसी नए सेटअप के लिए, प्रत्येक जोड़ की यात्रा के मध्य में एक दोहराने योग्य मुद्रा चुनें। स्थिर रहें और ऑफ़सेट सहेजने के लिए **Enter** दबाएँ ताकि वे उस मुद्रा में 2048 पढ़ें।
2. प्रत्येक चयनित जोड़ को एक सिरे से दूसरे सिरे तक घुमाएँ, सिरों पर कुछ देर रुकें। लाइव तालिका की समीक्षा करें और सीमाएँ बचाने के लिए **Enter** दबाएँ।

पूरे तंत्र का समर्थन करें; जबरदस्ती मत रोको. टॉर्क बंद रहता है. फ़ाइल स्वचालित रूप से अपडेट हो जाती है और मोटर बैकअप बरकरार रहता है। यदि दूसरा चरण विफल हो जाता है, तो पहले चरण के ऑफसेट सहेजे रहते हैं: गति सक्षम करने से पहले अंशांकन समाप्त करें। मापा गया मध्यबिंदु कैप्चर किए गए संदर्भ को प्रतिस्थापित नहीं करता है। 2048 केवल एक एनकोडर संदर्भ है; यह अनुकरण या गुरुत्वाकर्षण के लिए कोई भौतिक कोण स्थापित नहीं करता है। देखें [संदर्भ मुद्रा चुनना](tools/settings/README.md#choose-the-reference-pose)। पोज़ रिकॉर्ड करने या ग्रेविटी कंपंसेशन फिट करने से पहले ऐसा करें। सत्यापित अंशांकन वाले मौजूदा हथियारों को settings-preserving फ्लैश के बाद पुन: अंशांकन की आवश्यकता नहीं है।

<a id="4-check-communication"></a>
## 4. संचार की जाँच करें

टॉर्क बंद रखें. कनेक्टेड मोटरों पर `--ids` सेट करें।

```sh
npm test
npm run bus-benchmark -- --port "$SERVO_PORT" --ids 1 --repetitions 100
npm run telemetry -- --port "$SERVO_PORT" --ids 1 --samples 1000 --interval-ms 20 \
  --output tools/diagnostics/results/first-check
```

`npm test` ऑफ़लाइन है. अन्य कमांड हार्डवेयर पढ़ते हैं और रिपोर्ट पथ प्रिंट करते हैं। हर बार एक नई टेलीमेट्री आउटपुट निर्देशिका का उपयोग करें; यदि आपकी आपूर्ति डिफ़ॉल्ट 8–16 वी सीमा से बाहर है तो `--voltage-min` और `--voltage-max` समायोजित करें। प्रस्ताव से पहले विफलताओं और चिह्नित रीडिंग का निरीक्षण करें। factory/custom तुलना के लिए, [हार्डवेयर परीक्षण गाइड](tools/hw-diff-tests/README.md) का पालन करें: इसका पूरा सुइट मोटर चलाता है और सहेजी गई सेटिंग्स और रीसेट टेम्पलेट्स को प्रतिस्थापित करता है।

<a id="5-record-and-replay-poses"></a>
## 5. पोज़ रिकॉर्ड करें और दोबारा चलाएं

टॉर्क जारी करने से पहले तंत्र का समर्थन करें। इसे हाथ से हिलाएं, प्रत्येक मुद्रा को सहेजने के लिए एक नाम दर्ज करें, फिर `done` टाइप करें। एक हाथ के लिए सभी आवश्यक मोटर आईडी का उपयोग करें।

```sh
npm run record-poses -- --port "$SERVO_PORT" --ids 1
cp tools/poses/replay.example.json tools/poses/controller.local.json
```

संपादित करें `tools/poses/controller.local.json`: `followerPort` सेट करें, प्रत्येक मोटर के लिए `profiles` प्रविष्टि प्रदान करें, और उपयुक्त लाभ, प्रयास सीमा, गति और त्वरण चुनें। उदाहरण मान उदाहरणात्मक हैं. उदाहरण एक साझा प्रोफ़ाइल का संदर्भ देता है; अपने फायदे के लिए उस प्रोफ़ाइल को कॉपी करें और उसका पथ अपडेट करें, या सेटिंग्स इनलाइन करें। पथ नियंत्रक फ़ाइल से संबंधित हैं। पहले सहेजे गए अंशांकन और स्थिति सीमा की जाँच करें। फॉलोअर बस में बिल्कुल कॉन्फ़िगर की गई मोटरें होनी चाहिए। रीप्ले संचालित और बिना शक्ति वाली मोटरों को संभालता है और बदली हुई सेटिंग्स को स्वचालित रूप से लागू करता है।

`POSES.json` को रिकॉर्डर के सहेजे गए पथ से बदलें:

```sh
npm run replay -- tools/poses/controller.local.json POSES.json
npm run replay -- tools/poses/controller.local.json POSES.json --run
```

पहला आदेश पूर्वावलोकन; `--run` गति को सक्षम बनाता है। **सामान्य समापन से मोटरें संचालित होती हैं, जिससे अंतिम लक्ष्य बना रहता है। Ctrl+C कोई आपातकालीन रोक नहीं है।** [रीप्ले सेटिंग्स](tools/poses/README.md#replay-poses) देखें।

मुआवजे के बिना, मोटर्स की सहेजी गई विरासत PID सेटिंग्स का उपयोग करके तुलना करने के लिए:

```sh
npm run replay-legacy -- POSES.json --port "$SERVO_PORT" --run
```

किसी नियंत्रक फ़ाइल की आवश्यकता नहीं है. read-only पूर्वावलोकन के लिए `--run` को हटा दें। गति और त्वरण सेटिंग्स के लिए [लीगेसी रीप्ले](tools/poses/README.md#legacy-replay) देखें।

<a id="6-enable-gravity-compensation"></a>
## 6. गुरुत्वाकर्षण मुआवज़ा सक्षम करें

`tools/poses/controller.local.json` के लिए, यह top-level फ़ील्ड जोड़ें:

```json
"gravityModel": "../../host/arm-control/models/arm-upright-empty.json"
```

शामिल मॉडल एक खाली ग्रिपर के साथ कैलिब्रेटेड, सीधा **SO-ARM-102** के लिए है। मोटरें 1–6 और सभी छह प्रोफाइल शामिल करें। मोटर्स 2–4 मुआवजा प्राप्त करें; अन्य को शून्य प्राप्त होता है। एनकोडर अंशांकन का मिलान होना चाहिए; परिवर्तित माउंटिंग, ज्यामिति या पेलोड के लिए एक मान्य मॉडल की आवश्यकता होती है। केवल बेमेल को बायपास करने के लिए अंशांकन न बदलें। एक अलग तंत्र या अंशांकन के लिए, एक मिलान मॉडल को फिट और मान्य करें।

[SO-101 और SO-102 नियंत्रक प्रोफाइल](host/arm-control/profiles/README.md) में PID, वेग फीडफॉरवर्ड और मिलान गुरुत्वाकर्षण मॉडल शामिल हैं। उपयोग से पहले उनकी सीमाएं पढ़ें; वे फिट किए गए हथियारों के अंशांकन से बंधे हैं।

रीप्ले, टेलीऑपरेशन और ट्यूनिंग इसी क्षेत्र का उपयोग करते हैं। उपकरण चलने के दौरान गुरुत्वाकर्षण मापी गई स्थिति का अनुसरण करता है; बाहर निकलने के बाद, केवल अंतिम प्रयास ही बचा रहता है। मॉडल आवश्यकताओं के लिए [गुरुत्वाकर्षण गाइड](host/arm-control/README.md) देखें।

<a id="7-tune-and-view-motion"></a>
## 7. गति को ट्यून करें और देखें

[ट्यूनिंग प्लान](../../../tools/tuning/example.json) और [नियंत्रक उदाहरण](../../../tools/tuning/controller.example.json); को कॉपी और संपादित करें; योजना का `config` पथ अपनी नियंत्रक फ़ाइल पर सेट करें। पहली बार दौड़ने के लिए, छोटी सुरक्षित चालों, `"stage": "baseline"` और `"candidates": []` का उपयोग करें।

```sh
npm run tune -- inspect PLAN.json
npm run tune -- preflight PLAN.json
npm run tune -- run PLAN.json
```

केवल `run` हार्डवेयर को स्थानांतरित करता है। [ट्यूनिंग ऑर्डर](tools/tuning/README.md#tuning-order) का पालन करें: बेसलाइन → गुरुत्वाकर्षण → वेग फीडफॉरवर्ड → P/D और फ़िल्टरिंग → यदि आवश्यक हो तो इंटीग्रल → acceleration/ramp समय → संयुक्त गति → सत्यापन।

विज़ुअलाइज़ेशन के लिए, [सिमुलेशन व्यूअर](tools/simulation/README.md) इंस्टॉल करें, फिर रीप्ले या ट्यूनिंग द्वारा मुद्रित event-log पथ का उपयोग करें:

```sh
tools/simulation/.venv/bin/python tools/simulation/viewer.py live EVENTS.ndjson --model so101
tools/simulation/.venv/bin/python tools/simulation/viewer.py play EVENTS.ndjson --model so101
```

अन्य बंडल आर्म मॉडल के लिए `--model so102` का उपयोग करें। व्यूअर गाइड में reference-pose कन्वेंशन की जाँच करें। कमांड macOS विंडो लॉन्चर को स्वचालित रूप से संभालता है। दर्शक मापी गई गति प्रदर्शित करता है; यह ट्यूनिंग परिणामों की भविष्यवाणी नहीं करता है. अलग लीडर और फॉलोअर एडाप्टर का उपयोग करके hand-operated नियंत्रण के लिए, [टेलीऑपरेशन](tools/teleoperation/README.md) देखें।
