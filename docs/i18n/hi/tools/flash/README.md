<a id="flash-firmware"></a>
# फ़्लैश फ़र्मवेयर

संगत **GD32F130 STS TTL सर्वो** पर कस्टम या फ़ैक्टरी फ़र्मवेयर फ़्लैश करें। एक अपलोडर दोनों को संभालता है; रिलीज़ मेनिफेस्ट एप्लिकेशन जांच का चयन करता है।

**चेतावनी: फ्लैशिंग फर्मवेयर आपके सर्वो को नुकसान पहुंचा सकता है, अंशांकन मिटा सकता है या इसे अनुपयोगी बना सकता है। इस उपकरण का उपयोग अपने जोखिम पर करें। पुनर्प्राप्ति की गारंटी नहीं है।**

प्रकाशक की फ़र्मवेयर छवि और मिलान `release.json` का उपयोग करें, जिसे उसी फ़ोल्डर में रखा गया है। कच्चे फर्मवेयर बिल्ड समर्थित नहीं हैं। फ़्लैश करने से पहले रिलीज़ की हार्डवेयर संगतता की जाँच करें।

<a id="install"></a>
## स्थापित करें

**पायथन 3.10 या नए** की आवश्यकता है। रिपॉजिटरी रूट से चलाएँ:

```sh
python3 -m venv tools/flash/.venv
source tools/flash/.venv/bin/activate
python -m pip install -r tools/flash/requirements.txt
```

विंडोज़ पर, इसके बजाय `tools\flash\.venv\Scripts\Activate.ps1` से सक्रिय करें।

<a id="choose-firmware"></a>
## फ़र्मवेयर चुनें

| फ़र्मवेयर | प्रकट |
| --- | --- |
| कस्टम एक्सटेंशन v9 | प्रकाशक की छवि और `release.json` को एक साथ `tools/flash/releases/` में डाउनलोड करें। |
| फ़ैक्टरी **SCServo21-GD32-TTL 3.10**, मॉडल **9.3** | इसकी छवि के साथ, [`factory/release.json`](../../../../../tools/flash/factory/release.json) पर बंडल किया गया। |

फ़ैक्टरी छवि केवल मिलान हार्डवेयर के लिए है। चयनित मेनिफेस्ट का उपयोग `inspect`, `flash` या `recover` के साथ करें; किसी अलग फ़ैक्टरी कमांड या मोड की आवश्यकता नहीं है।

<a id="prepare"></a>
## तैयारी करो

- सामान्य फ़्लैशिंग केवल चयनित मोटर ID को रीसेट करती है। अद्वितीय आईडी वाले मोटर जुड़े रह सकते हैं; उन्हें क्रमिक रूप से फ़्लैश करें जबकि अन्य सामान्य रूप से चलते रहें। स्थानांतरण के दौरान power-cycle बस न चलाएं या कोई अन्य अपलोडर न चलाएं।
- **रिकवरी** के लिए, केवल इच्छित सर्वो को कनेक्ट करें। पुनर्प्राप्ति ID द्वारा मोटर का चयन नहीं करती है, और बूटलोडर स्थानांतरण पर ध्यान नहीं दिया जाता है।
- तंत्र को सुरक्षित करें, स्थिर मोटर शक्ति का उपयोग करें, और सीरियल पोर्ट का उपयोग करके अन्य प्रोग्राम बंद करें।
- सामान्य फ्लैशिंग के लिए, टॉर्क को अक्षम करें, लॉक सेटिंग्स लिखें और अपने सामान्य नियंत्रण उपकरण का उपयोग करके किसी भी सक्रिय अलार्म को साफ़ करें। सर्वो की वर्तमान ID और बॉड दर जानें।
- महत्वपूर्ण अंशांकन और सेटिंग्स का बैकअप लें। सर्वो में सहेजी गई सेटिंग्स से प्रारंभ करें; पुनरारंभ के बाद अस्थायी परिवर्तन गायब हो सकते हैं।

पोर्ट और ID को अपने मानों से बदलें। डिफ़ॉल्ट बॉड दर **1,000,000** है; उदाहरण के लिए, यदि आवश्यक हो तो `--baud 500000` जोड़ें। विशिष्ट पोर्ट macOS पर `/dev/cu.usbmodem…`, Linux पर `/dev/ttyUSB0` और विंडोज़ पर `COM3` हैं।

```sh
python tools/flash/settings.py backup \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2 \
  --file backups/servo-2-settings.json
```

इस सटीक सर्वो के लिए यह बैकअप रखें। मौजूदा बैकअप फ़ाइलें अधिलेखित नहीं हैं.

<a id="flash"></a>
## फ्लैश

डाउनलोड की गई कस्टम रिलीज़ को जांचें और फ़्लैश करें:

```sh
python tools/flash/flash.py inspect \
  --manifest tools/flash/releases/release.json

python tools/flash/flash.py flash \
  --manifest tools/flash/releases/release.json \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2
```

बंडल किए गए फ़ैक्टरी फ़र्मवेयर को स्थापित करने के लिए, इसके बजाय इसके मेनिफेस्ट का चयन करें। इस ऑपरेशन के लिए सर्वो को अलग करें: फ़ैक्टरी स्टार्टअप बस में किसी अन्य मोटर के साथ विरोध करते हुए इसके ID को 1 में बदल सकता है।

```sh
python tools/flash/flash.py flash \
  --manifest tools/flash/factory/release.json \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2
```

`inspect` सर्वो से कनेक्ट किए बिना फ़ाइल आकार, चेकसम और मेनिफेस्ट की जांच करता है। संकेत मिलने पर `FLASH` टाइप करें। कमांड समाप्त होने तक पावर कनेक्ट रखें। टूल सर्वो की जांच करता है, उसकी सेटिंग्स स्नैपशॉट सहेजता है, फर्मवेयर अपलोड करता है, फिर एप्लिकेशन की जांच करता है और सेटिंग्स की तुलना करता है। सफल सत्यापन से टॉर्क अक्षम हो जाता है।

फ़ैक्टरी फ़्लैश के बाद, टूल पिछले ID/baud की जाँच करता है, फिर ID **1** पर **1,000,000** बॉड की जाँच करता है, यदि आवश्यक हो, और कार्यशील कनेक्शन को प्रिंट करता है। निकास कोड **2** का अर्थ है कि फ़ैक्टरी फ़र्मवेयर ने प्रतिक्रिया दी लेकिन सेटिंग्स बदल गईं। दोबारा फ्लैश करने के बजाय नीचे दी गई सेटिंग्स को सुधारना जारी रखें।

<a id="recover-an-unresponsive-servo"></a>
## एक अनुत्तरदायी सर्वो पुनर्प्राप्त करें

सबसे पहले बिजली, वायरिंग, ID और बॉड रेट की जांच करें। यदि पुनर्प्राप्ति की आवश्यकता है, तो **केवल इच्छित सर्वो** को कनेक्ट करें और चयनित मेनिफेस्ट का उपयोग करें। उदाहरण के लिए, फ़ैक्टरी फ़र्मवेयर से पुनर्प्राप्त करने के लिए:

```sh
python tools/flash/flash.py recover \
  --manifest tools/flash/factory/release.json \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 1
```

पुष्टि के बाद, **power-cycle संकेत मिलने पर सर्वो**, USB एडॉप्टर को कनेक्टेड छोड़ दें। टूल बूटलोडर के लिए 60 सेकंड तक प्रतीक्षा करता है।

पुनर्प्राप्ति के बाद अपेक्षित ID और बॉड दर का उपयोग करें। पुनर्प्राप्ति अपलोड करने से पहले वर्तमान मॉडल या बैकअप सेटिंग्स की जांच नहीं कर सकती है, इसलिए हार्डवेयर संगतता की पुष्टि स्वयं करें। बाद में टॉर्क को सक्षम करने से पहले अंशांकन और स्थिति सीमा की जांच करें।

<a id="restore-factory-settings"></a>
## फ़ैक्टरी सेटिंग्स पुनर्स्थापित करें

फ़ैक्टरी फ़र्मवेयर पर लौटने के बाद, इस सर्वो के बैकअप को पुनर्स्थापित करें, भले ही सेटिंग्स शुरू में सही दिखें। फ़ैक्टरी फ़र्मवेयर built-in डिफ़ॉल्ट का उपयोग कर सकता है जब इसकी सहेजी गई सेटिंग्स अमान्य हों; सामान्य रजिस्टर लेखन इसे ठीक नहीं कर सकता है।

फ़्लैश करने के बाद मुद्रित **वर्तमान** ID/baud का उपयोग करें। उदाहरण के लिए, यदि अब इसका उत्तर ID 1 है:

```sh
python tools/flash/settings.py restore \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 1 \
  --file backups/servo-2-settings.json
```

पुष्टि करने के लिए `RESTORE` टाइप करें। यह फ़ैक्टरी **3.10** का समर्थन करता है और पता लगाए गए कस्टम फ़र्मवेयर को अस्वीकार करता है। यह सेटिंग्स को पुनर्स्थापित करता है, **सहेजे गए रीसेट टेम्पलेट को प्रतिस्थापित करता है**, सहेजी गई सेटिंग्स की मरम्मत करता है, राइट्स को लॉक करता है और सर्वो को पुनरारंभ करता है। यह किसी भी ID/baud परिवर्तन का पालन करता है और मोशन कमांड भेजे बिना रीडबैक को सत्यापित करता है।

फिर **power-cycle सर्वो** और **पुनर्स्थापित** ID/baud का उपयोग करके सत्यापित करें:

```sh
python tools/flash/settings.py verify \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2 \
  --file backups/servo-2-settings.json
```

सत्यापन पास होने तक टॉर्क को बंद रखें। आप `--file` के रूप में before-flash स्नैपशॉट युक्त एक सामान्य फ़्लैश `report.json` भी प्रदान कर सकते हैं। सेटिंग्स खो जाने के बाद लिया गया बैकअप मूल अंशांकन को पुनर्प्राप्त नहीं कर सकता है। वैध बैकअप के बिना, सटीक मॉडल के लिए सेटिंग्स प्राप्त करें और इस सर्वो को पुन: कैलिब्रेट करें।

विफलता पर, मरम्मत सेटिंग्स को फिर से लॉक करने का प्रयास करती है लेकिन आंशिक लेखन को पूर्ववत नहीं करती है या स्वचालित रूप से मरम्मत का पुनः प्रयास नहीं करती है। जांच से पहले रिपोर्ट सुरक्षित रख लें.

<a id="results-and-options"></a>
## परिणाम और विकल्प

फ़्लैश रिपोर्ट `backups/flash/` के अंतर्गत सहेजी जाती हैं; `backups/settings/` के अंतर्गत सेटिंग रिपोर्ट। दोनों में उपलब्ध सेटिंग्स स्नैपशॉट शामिल हैं। एक सफल अपलोड में एप्लिकेशन जांच शामिल है; यह पूरी फ़र्मवेयर छवि को वापस नहीं पढ़ता है। सेटिंग्स स्वचालित रूप से पुनर्स्थापित नहीं होती हैं.

- `--output DIRECTORY`: चुनें कि रिपोर्ट कहाँ सहेजी गई हैं।
- `--yes`: पुष्टिकरण संकेत छोड़ें; सभी जाँचें अभी भी चल रही हैं।
- `--help`: कमांड विकल्प दिखाएं।

यदि फ़ाइल सत्यापन विफल हो जाता है, तो एक मिलान रिलीज़ जोड़ी प्राप्त करें। यदि फ्लैशिंग बाधित होती है, तो सर्वो को पुनर्प्राप्ति की आवश्यकता हो सकती है। यदि स्थानांतरण समाप्त हो जाता है लेकिन सत्यापन विफल हो जाता है, तो रिपोर्ट का निरीक्षण करें और पुनः प्रयास करने से पहले ID, बॉड दर और सेटिंग्स की जांच करें।

रिलीज़ लेखकों के लिए, [release.example.json](../../../../../tools/flash/release.example.json) एक कस्टम मेनिफेस्ट और [factory/release.json](../../../../../tools/flash/factory/release.json) एक फ़ैक्टरी मेनिफेस्ट दिखाता है। कस्टम उदाहरण प्रयोग करने योग्य फ़र्मवेयर रिलीज़ नहीं है।
