# पोज़ रिकॉर्ड करें और दोबारा चलाएं

टॉर्क बंद करके नामित स्थितियों को रिकॉर्ड करें, फिर उन्हें सहेजी गई लीगेसी सेटिंग्स या ट्यून की गई एक्सटेंशन सेटिंग्स के साथ दोबारा चलाएं। कमांड रिपॉजिटरी रूट से चलते हैं।

| आदेश | इनपुट | फ़र्मवेयर |
| --- | --- | --- |
| `npm run record-poses` | मैनुअल पोजिशनिंग | फैक्टरी या कस्टम |
| `npm run replay` | नामित पोज़ या टेलीऑपरेशन सत्र | एक्सटेंशन v9 |
| `npm run replay-legacy` | नामित पोज़ | फ़ैक्टरी या कस्टम v9 |

<a id="record-poses"></a>
## पोज़ रिकॉर्ड करें

Node.js 20 या नया इंस्टॉल करें, फिर रिपॉजिटरी रूट से चलाएं:

```sh
npm install
npm run record-poses -- --port /dev/ttyUSB0 --ids 1,2,3
```

अपने सेटअप के लिए पोर्ट और आईडी बदलें। वैकल्पिक झंडे `--baud` (डिफ़ॉल्ट 1000000), `--output DIR`, और `--timeout-ms` (डिफ़ॉल्ट 1000) हैं।

पहले [ऑफ़सेट और सीमा अंशांकन](../settings/README.md#calibrate-joint-offsets-and-limits) समाप्त करें। रिकॉर्ड किए गए पोज़ आंदोलन के मार्ग बिंदु हैं; `home` या `reference` नामक पोज़ कैप्चर करने से मोटर अंशांकन नहीं बदलता है।

1. तंत्र को सहारा दें ताकि टॉर्क निकलने पर यह गिर न सके।
2. पुष्टिकरण प्रॉम्प्ट पर Enter दबाएँ। रिकॉर्डर चयनित मोटरों पर टॉर्क को निष्क्रिय कर देता है और सत्यापित करता है कि यह बंद है। अन्य मोटरें नहीं बदली गईं।
3. तंत्र को हिलाएँ, उसे स्थिर रखें, फिर पोज़ कैप्चर करने के लिए Enter दबाएँ। आप इसके बजाय एक अद्वितीय नाम टाइप कर सकते हैं; अनाम पोज़ `position-1`, `position-2` आदि बन जाते हैं।
4. आवश्यकतानुसार दोहराएँ। समाप्त करने के लिए `done` टाइप करें या बीच में रोकने के लिए Ctrl+C दबाएँ।

रिकॉर्डिंग के बाद टॉर्क बंद रहता है। पढ़ना अनुक्रमिक है, इसलिए प्रत्येक मुद्रा एक स्थिर तंत्र का एक स्नैपशॉट है, न कि एक सिंक्रनाइज़ गति माप। गुम रीडिंग, अलार्म या सक्षम मोटर सत्र को रोक देता है। बाहर निकलने पर, उपकरण फिर से टॉर्क को अक्षम करने का प्रयास करता है और किसी भी विफल सत्यापन की रिपोर्ट करता है।

<a id="saved-files"></a>
## सहेजी गई फ़ाइलें

प्रत्येक सत्र के लिए `tools/poses/recordings/` में एक नई JSON फ़ाइल बनाई जाती है। प्रत्येक सफल कैप्चर उस फ़ाइल को परमाणु रूप से बदल देता है; यदि बाद में कैप्चर विफल हो जाता है तो पहले सहेजे गए पोज़ उपलब्ध रहते हैं। रिकॉर्डिंग्स को Git द्वारा अनदेखा कर दिया जाता है।

`sts-poses` संस्करण 1 प्रारूप मोटर ID द्वारा स्थिति की पहचान करता है, सरणी क्रम से नहीं:

```json
{
  "format": "sts-poses",
  "version": 1,
  "units": "encoder-counts",
  "ids": [1, 3],
  "readMode": "sequential",
  "poses": [
    {
      "name": "home",
      "capturedAt": "2026-10-24T12:00:00.000Z",
      "durationMs": 4.2,
      "positions": {"1": 2048, "3": 3100}
    }
  ]
}
```

फ़ाइलों में सत्र समय, सीरियल पोर्ट और बॉड दर भी शामिल हैं। पढ़ना प्रारंभ होने पर टाइमस्टैम्प चिह्न लगाएं; `durationMs` पूर्ण अधिग्रहण को मापता है। गणनाएं रिपोर्ट की गई स्थिति पर हस्ताक्षरित हैं, जिसमें पहले से ही मोटर की ऑफसेट और दिशा सेटिंग शामिल है, बिना कोणों में रूपांतरण के। फ़ाइल में कोई गति, त्वरण या प्लेबैक समय सेटिंग नहीं है, और कोई अंशांकन स्नैपशॉट नहीं है। Re-record एनकोडर अंशांकन बदलने के बाद की मुद्रा; रीप्ले यह पता नहीं लगा सकता कि पुरानी पोज़ फ़ाइल विभिन्न ऑफसेट का उपयोग करती है।

<a id="replay-poses"></a>
## पोज़ को फिर से खेलना

मूल के बगल में [replay.example.json](../../../../../tools/poses/replay.example.json) कॉपी करें, उदाहरण के लिए `tools/poses/controller.local.json` के रूप में। `followerPort` सेट करें और प्रति रिकॉर्ड की गई मोटर पर एक `profiles` प्रविष्टि प्रदान करें। आईडी रिकॉर्डिंग से आती हैं; किसी नेता या संयुक्त मानचित्रण की आवश्यकता नहीं है। उदाहरण साझा किए गए [मोटर प्रोफ़ाइल](../../../../../host/arm-control/profile.example.json) का संदर्भ देता है। अपनी सेटिंग्स के लिए उस प्रोफ़ाइल को कॉपी करें और उसका पथ अपडेट करें, या सेटिंग्स को इनलाइन रखें। सभी प्रोफ़ाइल और गुरुत्वाकर्षण पथ नियंत्रक फ़ाइल से संबंधित हैं। उदाहरण लाभ प्रारूप को स्पष्ट करते हैं; अपने तंत्र पर परीक्षण की गई सेटिंग्स का उपयोग करें।

```sh
npm run replay -- CONFIG.json POSES.json
npm run replay -- CONFIG.json POSES.json --run
```

पहला कमांड सेटिंग्स को बदले बिना पूर्ण पथ का पूर्वावलोकन करता है और सहेजी गई सीमा तक सीमित लक्ष्यों की रिपोर्ट करता है। `--run` गति शुरू करता है, जिसमें वर्तमान स्थिति से पहली मुद्रा तक का दृष्टिकोण शामिल है। केवल फॉलोअर पोर्ट खुला है. पोर्ट खुलने से पहले 64 MiB तक की फ़ाइलें स्वीकार और सत्यापित की जाती हैं।

[साझा नियंत्रक](../../host/arm-control/README.md) प्रोफाइल लागू करता है, मौजूदा संचालित सत्रों को संभालता है, और `gravityModel` कॉन्फ़िगर होने पर गुरुत्वाकर्षण मुआवजे की आपूर्ति करता है। **सामान्य पूर्णता और Ctrl+C एक पावर्ड होल्ड बनाए रखता है।** दोष नियंत्रक की सफाई का उपयोग करते हैं; Ctrl+C कोई आपातकालीन रोक नहीं है. वैकल्पिक top-level `durationMs` प्लेबैक जल्दी समाप्त होता है; पूरी फ़ाइल को दोबारा चलाने के लिए इसे छोड़ दें।

प्रत्येक पोज़ को एक ग्रुप कमांड में भेजा जाता है। यात्रा दूरी के साथ संयुक्त गति पैमाना, रीप्ले गति और प्रत्येक मोटर की गति सीमा के अधीन। प्रत्येक मोटर अपना स्वयं का S-curve उत्पन्न करती है, इसलिए आगमन अनुमानित है और वेपॉइंट मिश्रित नहीं हैं। प्लेबैक योजनाकारों के समाप्त होने और सभी मापी गई स्थितियों के `toleranceCounts` में प्रवेश करने की प्रतीक्षा करता है, फिर होल्ड शुरू होता है। `moveTimeoutMs` से अधिक की चाल विफल हो जाती है। मैन्युअल रूप से रिकॉर्ड किए गए टाइमस्टैम्प प्लेबैक गति निर्धारित नहीं करते हैं।

| `replay` सेटिंग | डिफ़ॉल्ट | मतलब |
| --- | --- | --- |
| `speed` | 1000 | अधिकतम गति, 1–65535 एनकोडर counts/s। |
| `holdMs` | 1000 | आगमन के बाद रुकें, 0–600000 एमएस। |
| `repeat` | 1 | पास की संख्या, 1–1000; प्रत्येक पास पहली मुद्रा में लौट आता है। |
| `moveTimeoutMs` | 30000 | आगमन का समय समाप्त, 1–600000 एमएस। |
| `toleranceCounts` | 10 | अनुमत मापी गई स्थिति त्रुटि, 0–32767 मायने रखती है। |

<a id="replay-a-recorded-session"></a>
## रिकॉर्ड किए गए सत्र को दोबारा चलाएं

लीडर को कनेक्ट किए बिना टेलीऑपरेशन लॉग दोबारा चलाएं:

```sh
npm run replay -- CONFIG.json SESSION.ndjson
npm run replay -- CONFIG.json SESSION.ndjson --run
```

रिकॉर्डिंग में लीडर सीमा और संयुक्त मैपिंग के साथ `preflight` होना चाहिए, इसके बाद मोनोटोनिक टाइमस्टैम्प और सभी लीडर पोजीशन के साथ `command` इवेंट होना चाहिए। वर्तमान कॉन्फ़िगरेशन में समान संयुक्त मानचित्रण का उपयोग करें। रिकॉर्ड किए गए नेता की स्थिति को रिकॉर्ड किए गए नेता की सीमा और अनुयायी की वर्तमान सीमा के माध्यम से मैप किया जाता है। वर्तमान प्रोफ़ाइल और गुरुत्वाकर्षण लागू होते हैं; ऐतिहासिक सेटिंग्स और प्रयासों का पुन: उपयोग नहीं किया जाता है। विफल लॉग में एक इच्छित कमांड कभी भी मोटरों तक नहीं पहुंच पाया होगा।

प्लेबैक रिकॉर्ड किए गए अंतराल को सुरक्षित रखता है; प्रसंस्करण में catch-up बर्स्ट भेजने के बजाय स्ट्रेच टाइमिंग में देरी होती है। विराम के दौरान फीडबैक और गुरुत्वाकर्षण अपडेट जारी रहते हैं। `replay.repeat`, `moveTimeoutMs` और `toleranceCounts` लागू; `speed` और `holdMs` केवल नामित पोज़ पर लागू होते हैं। अंतिम फ़्रेम पूरा होने से पहले आना चाहिए.

<a id="legacy-replay"></a>
## विरासत पुनरावृत्ति

एक्सटेंशन वेलोसिटी फीडफॉरवर्ड या गुरुत्वाकर्षण मुआवजे के बिना मोटर्स की सहेजी गई PID सेटिंग्स का उपयोग करें। किसी नियंत्रक फ़ाइल की आवश्यकता नहीं है और लगातार सेटिंग्स अपरिवर्तित हैं। मोटर्स को पूर्ण स्थिति मोड और यूनिट एनकोडर रिज़ॉल्यूशन की आवश्यकता होती है।

```sh
npm run replay-legacy -- POSES.json --port /dev/ttyUSB0
npm run replay-legacy -- POSES.json --port /dev/ttyUSB0 --run
```

पहला आदेश पूर्वावलोकन; `--run` चाल. आईडी पोज़ फ़ाइल से आती हैं; एडॉप्टर पर अन्य मोटरें अकेली रह जाती हैं। कस्टम फर्मवेयर लीगेसी मोड में स्विच हो जाता है। सेटअप संक्षेप में प्रत्येक चयनित मोटर को अक्षम कर देता है और re-enables, उसकी वर्तमान स्थिति को पहले सीडिंग करता है।

| विकल्प | डिफ़ॉल्ट | मतलब |
| --- | --- | --- |
| `--speed` | 1000 | अधिकतम गति, 1–32767 एनकोडर counts/s। |
| `--acceleration` | 5000 | Counts/s², 100–25400 100 के गुणज में। सहेजी गई सीमाएँ लागू होती हैं. |
| `--hold-ms` | 1000 | प्रत्येक नियोजित चाल के बाद रुकें, 0–600000 एमएस। |
| `--baud` | 1000000 | एडाप्टर बॉड दर. |

प्रत्येक मुद्रा लगभग एक साथ आगमन के लिए एक समूह कमांड और distance-scaled गति का उपयोग करती है। लक्ष्य सहेजी गई स्थिति सीमा तक सीमित हैं। प्लेबैक आंतरिक गति प्रोफाइल के समाप्त होने की प्रतीक्षा करता है, फिर रुक जाता है; इसमें शून्य मापित स्थिति त्रुटि की आवश्यकता नहीं है। 30 सेकंड से अधिक समय तक चलने वाली चाल विफल हो जाती है।

समापन अंतिम मुद्रा में टॉर्क बरकरार रखता है। एक्सटेंशन रीप्ले के विपरीत, **Ctrl+C प्रयास torque-off**, जैसे विफलताएं होती हैं। सफाई विफलताओं की सूचना दी गई है।

<a id="logs-and-visualization"></a>
## लॉग और विज़ुअलाइज़ेशन

दोनों रीप्ले कमांड अंशांकन, स्रोत पहचान, कमांड और फीडबैक सहित लॉग को अनदेखा `logs/motion/` में सहेजते हैं। [टेलीमेट्री व्यूअर](../simulation/README.md) को एक बार प्रारंभ करें, फिर दूसरे टर्मिनल में रीप्ले चलाएं:

```sh
mkdir -p logs/motion
tools/simulation/.venv/bin/python tools/simulation/viewer.py live logs/motion --model so102
```

अन्य बंडल मॉडल और मिलान एनकोडर मैपिंग के लिए `--model so101` का उपयोग करें। एक्सटेंशन रीप्ले दर्शक द्वारा दिखाए गए गतिशील संदर्भ के लिए विस्तृत फीडबैक पढ़ता है। ट्रैफ़िक कम करने के लिए, `--compact` जोड़ें; मापी गई गति और क्षतिपूर्ति सक्रिय रहती है, लेकिन छाया मध्यवर्ती योजनाकार स्थितियों के बजाय गंतव्य दिखाती है। PID शर्तें और लागू मुआवजा योगदान भी छोड़े गए हैं। [प्रतिक्रिया और समय](../../host/arm-control/README.md#checks-and-timing) देखें।
