<a id="sts32xx-servo-driver"></a>
# STS32XX सर्वो ड्राइवर

STS सीरियल सर्वो और STS32XX फर्मवेयर **v9 मोशन एक्सटेंशन** के लिए Node.js ड्राइवर। यह एक सीरियल कनेक्शन के माध्यम से खोज, रजिस्टर एक्सेस, सेटिंग्स ऑपरेशन, S-curve मोशन कमांड, गुरुत्वाकर्षण मुआवजा और फीडबैक प्रदान करता है। **Node.js 20 या नया** और एक संगत सीरियल एडाप्टर की आवश्यकता है।

लीगेसी ऑपरेशन इस पैकेज में शामिल STS नियंत्रण तालिका का उपयोग करते हैं। एक्सटेंशन संचालन के लिए कस्टम फ़र्मवेयर v9 की आवश्यकता होती है; फ़ैक्टरी फ़र्मवेयर उन्हें प्रदान नहीं करता है। पैकेज Node.js के लिए है, ब्राउज़र वेब सीरियल के लिए नहीं।

<a id="install"></a>
## स्थापित करें

इस भंडार से:

```sh
npm ci
npm run test:driver
npm pack --workspace sts32xx-servo-driver --pack-destination /tmp
```

किसी अन्य Node.js प्रोजेक्ट में, अंतिम कमांड द्वारा निर्मित संग्रह स्थापित करें:

```sh
npm install /tmp/sts32xx-servo-driver-0.1.0.tgz
```

यह एनपीएम रजिस्ट्री में प्रकाशित किए बिना काम करता है। संग्रह में पुस्तकालय, उदाहरण, README और लाइसेंस शामिल हैं। सीरियल निर्भरताएँ npm के माध्यम से स्थापित होती हैं; फ़र्मवेयर, लॉग और परीक्षण परिणाम शामिल नहीं हैं।

कॉमनजेएस:

```js
const { StsServo } = require('sts32xx-servo-driver');
```

ES मॉड्यूल:

```js
import driver from 'sts32xx-servo-driver';
const { StsServo } = driver;
```

मौजूदा रिपोजिटरी उपकरण सीधे `host/servo-driver` आयात करना जारी रख सकते हैं। पैकेज के मुख्य निर्यात का उपयोग करें; आंतरिक फ़ाइल पथ इसके सार्वजनिक API का हिस्सा नहीं हैं।

<a id="connect-and-read"></a>
## जुड़ें और पढ़ें

```js
const { StsServo } = require('sts32xx-servo-driver');

const servo = new StsServo({
  serial: { path: '/dev/cu.usbmodemYOUR_ADAPTER', baudRate: 1000000 },
});

async function main() {
  try {
    const found = await servo.connect();
    for (const id of found.ids) {
      const values = await servo.bus.read(id,
        ['presentPosition', 'presentVoltage', 'servoStatus']);
      console.log(id, values, found.alarms.get(id) ?? []);
    }
  } finally {
    await servo.close();
  }
}
main().catch(console.error);
```

उपयुक्त के रूप में `/dev/ttyUSB0`, `COM3` या अपने एडॉप्टर के वास्तविक पोर्ट का उपयोग करें। डिस्कवरी चयनित बॉड पर प्रतिक्रियाशील आईडी ढूंढती है; यह मोटर सेटिंग्स नहीं बदलता या अन्य बॉड दरों को स्कैन नहीं करता। आईडी अद्वितीय होनी चाहिए. उच्चतम संभव ID और चयनित बॉड के लिए वेट खाता है। `connect()` पोर्ट खोलता है और मोटरें खोजता है; `open()` केवल पोर्ट खोलता है। बस और विस्तार विधियों के लिए खोजी गई आईडी की आवश्यकता होती है।

रजिस्टर मान कच्ची इकाइयों का उपयोग करते हैं। उदाहरण के लिए, `presentVoltage: 120` का अर्थ है 12 V. `ControlTable` पते, एन्कोडिंग, रेंज और डिस्प्ले स्केल का वर्णन करता है। Multi-byte फ़ील्ड little-endian एन्कोडिंग का उपयोग करते हैं; हस्ताक्षरित विरासत मान साइन बिट्स का उपयोग करते हैं।

<a id="main-api"></a>
## मुख्य API

हार्डवेयर के साथ संचार करने वाले सभी ऑपरेशन रिटर्न का वादा करते हैं।

| API | प्रयोजन |
| --- | --- |
| `servo.connect()` / `servo.close()` | Open/discover या सीरियल कनेक्शन बंद करें। |
| `servo.bus.discover()` | ज्ञात आईडी की सूची ताज़ा करें. |
| `servo.bus.scan()` | known-ID सूची को बदले बिना खोजें। |
| `servo.bus.verify(ids)` | ज्ञात मोटरों को अलग-अलग पिंग करें। |
| `servo.bus.read(id, keys, options)` | नामित रजिस्टर पढ़ें; रजिस्टर नाम से कुंजीबद्ध एक ऑब्जेक्ट लौटाता है। |
| `servo.bus.write(id, values, options)` | नामित रजिस्टरों का एक ऑब्जेक्ट लिखें। |
| `servo.bus.readMany(ids, keys, options)` | समूह अनुरोधों का उपयोग करके कई मोटरें पढ़ें। |
| `servo.bus.syncWrite(entries, options)` | एक समूह में `{ id, values }` के आकार की प्रविष्टियाँ लिखें। |
| `servo.bus.device(id)` | `read`, `write` और reset/calibration विधियों से एक सुविधाजनक वस्तु प्राप्त करें। |
| `servo.settings.read(id)` | सतत विरासत सेटिंग पढ़ें. |
| `servo.settings.save(id, values)` | सामान्य सेटिंग्स को अनलॉक करें, सहेजें, सत्यापित करें और पुनः लॉक करें। |
| `servo.arm` | नीचे दिए गए v9 तरीकों तक पहुंचें। |

सेटिंग्स 250 एमएस अनुरोध टाइमआउट का उपयोग करके बचत करती हैं। लिखित पावती खो जाने के बाद, ड्राइवर दृढ़ता की प्रतीक्षा करता है और पुनः प्रयास करने से पहले रजिस्टर को वापस पढ़ता है। Already-appliedलिखित को दोहराया नहीं जाता। अस्थायी संचार विफलताओं में तीन प्रयास तक होते हैं; लगातार विफलताएँ अभी भी एक त्रुटि की रिपोर्ट करती हैं और मोटर को फिर से लॉक करने का प्रयास करती हैं। टाइमआउट को ओवरराइड करने के लिए `{ timeoutMs }` से `settings.save` तक पास करें।

विरासत उदाहरण, स्थिति मोड में एक सुरक्षित मोटर के लिए जिसे स्थानांतरित करने का इरादा है:

```js
await servo.bus.write(id, { targetPosition: 2048 },
  { timeoutMs: 100, rejectOnAlarm: true });
```

सहेजी गई सेटिंग्स के आधार पर, एक लीगेसी लक्ष्य लेखन स्वचालित रूप से टॉर्क को सक्षम कर सकता है। लगातार लिखने से अंशांकन, सीमा या लाभ बदल सकते हैं। सेटिंग्स बदलने से पहले टॉर्क को अक्षम करें। सेटिंग्स API गार्ड ID, बॉड और response-level बदलती हैं; पूर्ण backup/restore के लिए रिपॉजिटरी में [सेटिंग्स CLI](../../tools/settings/README.md) का उपयोग करें। फ़ैक्टरी रीसेट, reset-template और अंशांकन आदेश `servo.protocol` के माध्यम से उजागर होते हैं; उन्हें केवल तभी कॉल करें जब वे परिवर्तन इच्छित हों।

<a id="v9-control-lifecycle"></a>
## v9 नियंत्रण जीवनचक्र

1. टॉर्क ऑफ से शुरुआत करें। क्षमताएं और कॉन्फ़िगरेशन पढ़ें.
2. टॉर्क बंद होने पर `arm.configure()` के साथ एक मान्य कॉन्फ़िगरेशन लागू करें।
3. नए गैर-शून्य सत्र ID के साथ एक्सटेंशन मोड का चयन करें।
4. लीगेसी रजिस्टर 40 का उपयोग करके टॉर्क सक्षम करें, तब तक फीडबैक पढ़ें जब तक कि सत्र सशस्त्र, ताज़ा, drive-enabled और output-ready न हो जाए।
5. लक्ष्य और गुरुत्व अद्यतन भेजें। ताज़ा फीडबैक में उनकी स्वीकृत अनुक्रम संख्याओं को सत्यापित करें।
6. जब एप्लिकेशन मोटर को रिलीज़ करने का इरादा रखता है तो `torqueEnable: 0` लिखें।

```js
const options = { timeoutMs: 100, rejectOnAlarm: true };
const caps = await servo.arm.capabilities(id, options);
if (caps?.major !== 9) throw new Error('Extension v9 is required');

// config must contain values validated for this motor and mechanism.
await servo.arm.configure(id, config, options);
await servo.arm.select(id, true, session, options);
await servo.bus.write(id, { torqueEnable: 1 }, options);
// Check readiness using servo.arm.feedback() before sending motion.

await servo.arm.setTargets([
  { id, target: { sequence: 1, positionQ8: 2048 * 256, speedLimit: 100 } },
], session, options);

await servo.arm.updateGravity(id,
  { session, sequence: 1, gravityEffort: -20 }, options);
```

यह स्निपेट कॉल दिखाता है; [पूर्ण प्रस्ताव उदाहरण](../../../../../host/servo-driver/examples/v9-move.js) में सत्यापन, तत्परता मतदान, स्वीकृति जांच और torque-off सफाई शामिल है। यदि लेखन स्वीकृतियाँ अक्षम हैं, तो विरासत लेखन को `expectResponse: false` और रीडबैक सत्यापन की आवश्यकता है। पूरा उदाहरण इसे स्वचालित रूप से संभालता है।

फर्मवेयर अंतिम लक्ष्य रखता है और नवीनतम गुरुत्वाकर्षण प्रयास को तब तक बरकरार रखता है जब तक कि प्रतिस्थापित या टॉर्क अक्षम न हो जाए। कोई दिल की धड़कन, कमांड टाइमआउट या गुरुत्वाकर्षण समाप्ति नहीं है। **सीरियल कनेक्शन बंद करने से मोटर बंद या रिलीज नहीं होती है।** तंत्र के अनुरूप एप्लिकेशन क्लीनअप चुनें; भरी हुई बांह को छोड़ने से वह गिर सकता है। फर्मवेयर में सेंसर और मोटर सुरक्षा सक्रिय रहती है।

टॉर्क सक्षम मापी गई स्थिति को कैप्चर करता है। विरासत लक्ष्य लेखन के साथ एक विस्तार सत्र को न जोड़ें। टॉर्क बंद होने या किसी खराबी के कारण सत्र समाप्त हो जाता है; पुनः आरंभ करने से पहले एक नया सत्र तैयार करें। टॉर्क बंद के साथ लीगेसी मोड का चयन करने के लिए, `arm.select(id, false, 0)` का उपयोग करें।

<a id="extension-methods"></a>
### विस्तार के तरीके

| विधि | परिणाम या प्रभाव |
| --- | --- |
| `capabilities(id, options)` | `{ major, minor, tickMs }` किसी मान्यता प्राप्त हस्ताक्षर के लिए; असमर्थित फ़र्मवेयर अनुरोध को अस्वीकार कर सकता है या टाइम आउट कर सकता है। |
| `configuration(id, options)` | वर्तमान RAM कॉन्फ़िगरेशन पढ़ें। |
| `configure(id, config, options)` | कॉन्फ़िगरेशन लिखें और एन्कोडेड बाइट्स को रीडबैक द्वारा सत्यापित करें। |
| `select(id, enabled, session, options)` | v9 नियंत्रण तैयार करें, या `false, 0` के साथ लीगेसी मोड का चयन करें। |
| `setTargets(entries, session, options)` | एक से छह अद्वितीय मोटरों वाला एक प्रसारण भेजें। |
| `updateGravity(id, command, options)` | अपने स्वयं के क्रम संख्या के साथ हस्ताक्षरित गुरुत्वाकर्षण प्रयास भेजें। |
| `feedback(id, options)` | एक सुसंगत परिचालन नमूना पढ़ें. |
| `tuning(id, options)` | परिचालन प्रतिक्रिया और संदर्भ प्रस्ताव तथा व्यक्तिगत प्रयास की शर्तें पढ़ें। |
| `invalidate(id)` | बाहरी पावर चक्र या फ़र्मवेयर परिवर्तन के बाद कैश्ड क्षमताओं को साफ़ करें; सभी को साफ़ करने के लिए ID को हटा दें। |

ड्राइवर अपने प्रोटोकॉल API के माध्यम से खोज, ID परिवर्तन, कनेक्शन परिवर्तन और रीसेट पर क्षमताओं को स्वचालित रूप से अमान्य कर देता है।

<a id="configuration-and-units"></a>
### विन्यास और इकाइयाँ

प्रत्येक कॉन्फ़िगरेशन फ़ील्ड स्पष्ट है. यह ऑब्जेक्ट प्रारूप को दर्शाता है, अनुशंसित ट्यूनिंग प्रोफ़ाइल को नहीं:

```js
const config = {
  kpQ8: 256, kdQ8: 0, kiQ8: 0,
  integralLimit: 0, effortLimit: 100,
  velocityLimit: 100, accelerationLimit: 500,
  velocityFilterQ8: 64, rampTimeMs: 30,
  velocityFeedforward: {
    positiveGainQ8: 0, negativeGainQ8: 0, effortLimit: 0,
  },
  gravitySlewEffortPerS: 1000,
};
```

| खेत | इकाइयाँ और सीमाएँ |
| --- | --- |
| `kpQ8`, `kdQ8`, `kiQ8` | लाभ को 256 से गुणा किया गया; पूर्णांक 0–65535. |
| `effortLimit`, `integralLimit` | PWM प्रयास इकाइयाँ; समग्र सीमा 1–1000, अभिन्न सीमा 0-समग्र सीमा। |
| `velocityLimit`, लक्ष्य `speedLimit` | एनकोडर counts/s; 1–65535. |
| `accelerationLimit` | Counts/s²; 1–30000, त्वरण और ब्रेकिंग द्वारा साझा किया गया। |
| `rampTimeMs` | S-curve त्वरण रैंप समय; 1–255 एमएस. |
| `velocityFilterQ8` | फ़िल्टर गुणांक 256 से गुणा किया गया; 1–255. |
| वेग फ़ीडफ़ॉरवर्ड लाभ | Direction-specific लाभ 256 से गुणा किया गया; 0–65535. इसकी प्रयास सीमा समग्र सीमा से अधिक नहीं हो सकती। इसे अक्षम करने के लिए लाभ और सीमा दोनों को शून्य पर सेट करें। |
| `gravitySlewEffortPerS` | प्रति सेकंड गुरुत्वाकर्षण प्रयास परिवर्तन; 1–10000. |
| लक्ष्य `positionQ8` | एनकोडर स्थिति को 256 से गुणा किया गया; −32767×256 से 32767×256. |
| `gravityEffort` | हस्ताक्षरित PWM प्रयास; −1000 से 1000. फ़र्मवेयर अपनी प्रयास सीमाएँ लागू करता है। |

यात्रा सीमाएँ सहेजी गई विरासत स्थिति सीमाओं से आती हैं। फ़र्मवेयर लक्ष्य को सक्रिय सीमा तक सीमित करता है। कॉन्फ़िगरेशन RAM स्थिति है, स्थायी ट्यूनिंग प्रोफ़ाइल नहीं। स्थानीय वेग फ़ीडफ़ॉरवर्ड फ़र्मवेयर गति संदर्भ का अनुसरण करता है; एप्लिकेशन गुरुत्वाकर्षण मुआवजे की आपूर्ति अलग से करता है।

एक्सटेंशन लक्ष्य आईडी 1–253 हैं। एक सत्र 1–65535 है. प्रत्येक मोटर लक्ष्य और गुरुत्वाकर्षण अनुक्रम को अलग-अलग ट्रैक करती है। 65535 से 0 तक लपेटते हुए, प्रत्येक नए कमांड के लिए संबंधित क्रम को बढ़ाएं; 32767 तक फॉरवर्ड गैप स्वीकार किए जाते हैं। अनुक्रम 1 के साथ एक नया सत्र शुरू करें। प्रसारण पूरा होने का मतलब है कि पैकेट भेजा गया था, ऐसा नहीं कि हर मोटर ने इसे स्वीकार कर लिया। बाद के फीडबैक में `acceptedSequence`, `gravitySequence` और `session` की जाँच करें।

<a id="feedback-and-errors"></a>
### प्रतिक्रिया और त्रुटियाँ

`feedback()` में Q8 इकाइयों में मापा गया position/velocity, लागू प्रयास, वर्तमान ADC डेल्टा, कच्चा वोल्टेज, मान्य तापमान, दोष, सत्र और स्वीकृत अनुक्रम शामिल हैं। यह निर्धारित करने के लिए कि कोई नमूना प्रयोग योग्य है या नहीं, `fresh`, `ageMs`, `sampleSequence`, `armed`, `driveEnabled` और `outputReady` का उपयोग करें। तापमान तभी प्रयोग योग्य है जब `temperatureValid` सत्य हो। `running: false` का अर्थ है कि योजनाकार अब आगे नहीं बढ़ रहा है; यह शून्य स्थिति त्रुटि की गारंटी नहीं देता.

`tuning()` संदर्भ जोड़ता है position/velocity, अनुरोधित प्रयास, P/D/I शब्द, गुरुत्वाकर्षण प्रयास, वेग फीडफॉरवर्ड और ओवररन गिनती।

पढ़ने और लिखने के विकल्पों में `timeoutMs` और `rejectOnAlarm` शामिल हैं। लीगेसी अलार्म अन्यथा मान्य उत्तरों को डिफ़ॉल्ट रूप से अस्वीकार नहीं करते हैं; पास `rejectOnAlarm: true` जब अलार्म को किसी ऑपरेशन को रद्द करना चाहिए। टाइप की गई त्रुटियों में `RequestTimeoutError`, `MissingResponseError`, `ServoStatusError`, `SettingsVerificationError` और `InvalidPacketError` शामिल हैं। अतिरिक्त संदर्भ `error.details` में है; एक्सटेंशन अस्वीकृतियों में `extensionStatus` शामिल है।

शेड्यूलर अनुरोधों को क्रमबद्ध करता है और प्राथमिकताओं और विशिष्ट लेनदेन का समर्थन करता है। आदेशों की प्रतीक्षा करें और समन्वित गति के लिए समूह लक्ष्यों का उपयोग करें। उत्तर देने का समय समाप्ति क्रमबद्ध लेखन ख़त्म होने के बाद शुरू होता है; परिवहन संचालन की अपनी समय सीमा होती है। ये टाइमआउट मोटर व्यवहार को नहीं बदलते हैं। लीगेसी पैकेट में कोई अनुक्रम संख्या नहीं होती है, इसलिए असामान्य रूप से देर से आए उत्तर को हमेशा उसी प्रतिक्रिया आकार वाले बाद के अनुरोध से अलग नहीं किया जा सकता है।

Low-level निर्यात में `SerialTransport`, `StsProtocol`, `RequestScheduler`, `PacketEncoder`, `PacketDecoder`, `RegisterCodec`, `RegisterLayout`, `ArmCodec`, स्थिरांक और त्रुटियां शामिल हैं। वे high-level बस API से अलग रहते हैं।

<a id="runnable-examples"></a>
## चलाने योग्य उदाहरण

इस निर्देशिका से, या स्थापित पैकेज में शामिल उदाहरण फ़ाइलों का उपयोग करके:

```sh
node examples/discover.js /dev/cu.usbmodemYOUR_ADAPTER
node examples/v9-feedback.js /dev/cu.usbmodemYOUR_ADAPTER 2
node examples/v9-move.js /dev/cu.usbmodemYOUR_ADAPTER 2 2048 100 /path/to/config.json
```

पहले दो उदाहरण केवल पढ़े गए। गति उदाहरण के लिए उपरोक्त फ़ील्ड के साथ JSON कॉन्फ़िगरेशन की आवश्यकता होती है और 1 Mbaud का उपयोग किया जाता है। इसे मुफ़्त यात्रा के साथ सुरक्षित, अनलोडेड मोटर पर चलाएं। यह चाल, त्रुटि या सुशोभित Ctrl+C के बाद टॉर्क को अक्षम कर देता है। यह स्टार्टअप के लिए 3 सेकंड और मूव के लिए 30 सेकंड तक प्रतीक्षा करता है। वैकल्पिक अंतिम तर्क: हस्ताक्षरित गुरुत्वाकर्षण प्रयास, डिफ़ॉल्ट शून्य। हाथ पर भार उठाने के लिए इसका उपयोग न करें।
