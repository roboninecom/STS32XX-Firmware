# 自動チューニング

候補設定の有界バッチを実行し、繰り返しの動きと長いホールドを比較し、machine-readableのレコメンデーションを取得します。リプレイと遠隔操作と同じv9ドライバ、コントローラ、キャリブレーションされた重力モデルを使用してください。EEPROMに設定は書き込まれず、当選候補は自動的にインストールされません。

<a id="start"></a>
## 開始

リポジトリルートから、Node.jsをインストールします。 20+ 依存関係 `npm install`コピー `controller.example.json` そして `example.json` オリジナル以外にも `controller.local.json` そして `plan.local.json`計画を立てる `config` です `controller.local.json`次に、ポート、モーターID、プロファイル、安全なジョイントトラベルペア、メカニズムの制限を編集します。 [モータープロファイル](../../../../../host/arm-control/profile.example.json);あなた自身の設定のためにそれをコピーし、そのパスを更新し、またはプロファイルをインライン化する. すべてのサポートモーターをインクルードします。 `{ "followerId": ID }` で `joints`; リーダーマッピングは不要です。 [校正](../settings/README.md#choose-the-reference-pose) テスト位置を選択する前に、補正されたエンコーダ数を使用する。新しいオフセットは、物理意味を変える。テストペア、記録、および再調整後の重力モデルを更新します。重力の場合、追加します。 `gravityModel` まさにそのとおりです [共有コントローラガイド](../../host/arm-control/README.md).

計画の`config`パスは計画と相対的である。コントローラのプロファイルと`gravityModel`パスは、そのコントローラファイルと相対的である。同じコントローラ構成をポーズリプレイに使用できる。チューニングのために`durationMs`を省略する:計画はバッチ予算を所有している。起動とプロファイルの変更のメカニズムを確保する。プロファイルを変更すると、モーターが一時的にリリースされる。新しい設定では、構成されたすべてのフォロワーがリリースされる。

```sh
npm run tune -- inspect tools/tuning/plan.local.json
npm run tune -- preflight tools/tuning/plan.local.json
npm run tune -- run tools/tuning/plan.local.json
```

このツールは、既存のファームウェアホールドターゲットでジョイントをサポートする。宣言されたテストペアを移動しているのは、`probeId`のみである。自動的なwhole-arm位置変更はない。現在のターゲットと測定された位置は、実行間の比較のために記録される。現在のアーム構成のためにレビューされたジョイントパスを使用する。

最初のバッチとその後のすべてのバッチに対して同じコマンドを使用します。

```sh
npm run tune -- run NEXT_PLAN.json
```

起動とプロファイルの変更は、[共有コントローラライフサイクル](../../host/arm-control/README.md#control-behaviour).同じバスで別のコントローラを実行しないでください。

`inspect`は接続しない。`preflight`はファームウェア、キャリブレーション、保存された制限、健康状態、プロファイルをモーターを変更せずに読み取る。`run`はそれらを移動させる。ターゲットは保存された位置制限に制限される。プリフライトは有効な経路を報告する。1つの位置に折りたたんだペアはチューニング練習として使用できない。

<a id="tuning-order"></a>
## 調律

1. **ベースライン:** 既存の設定でキャリブレーション、安全な動作、温度、再現性を検証する. `stage: "baseline"` を使用し、候補はありません。
2. **重力:** 緩やかなフィードバックゲインを維持し、いくつかのポーズと少なくとも2つの速度で両方の方向の遅い動きを比較する。キャリブレーションされたモデルから始めよう。`stage: "gravity"`はゲインを変更せずに識別データを収集する。
3. **速度フィードフォワード:**重力がチェックされた後、複数の速度で定常動作を使用して方向速度ゲインを比較します。
4. **P/Dとベロシティフィルタリング:*** 候補の小さな明示的なセットをスクリーニングする。高負荷と低負荷の両方のポーズを含め、その後、振動を公開するために長いホールドを使用する。小さな因子バッチはP、Dを比較し、一緒にフィルタリングできる。held-outペアで最高の組み合わせを検証する。
5. **Integral:** 永続的なエラーがある場合に限ります。移動精度と長いホールドを比較します。小さな反転を含めます。長いスイープだけで、静止した関節が摩擦を乗り越えるのを防ぐ積分限界を逃すことができます。結果がそれを可能にすることをサポートしない限り、積分ゼロを保ちます。
6. **加速度とランプ時間:** 利得固定、必要な速度で加速と平滑化を比較するために `stage: "motion"` を使用します。
7. **結合動作:** 全ての関節を運動させ、折り畳まれた構成と拡張された構成の両方を含む記録されたパスを再生します。サポートされた関節を静止して動作させることで、メカニズム全体の移動時に振動することができます。変更された関節を同じパスで再確認してから、設定を受け入れます。
8. **バリデーション:**選択した構成を凍結し、必要な速度と加速度で経路を繰り返し、その後、より長い.レコード精度、オーバーシュート、沈降、温度と各モーターの出力飽和度.ペイロードやキャリブレーションを変更した後の再チェック。

`stage` は候補フィールドを制限します。 `velocity` 許す `velocityFeedforward`; `pid` 許す `kpQ8`, `kdQ8`, `velocityFilterQ8`; `integral` 許す `kiQ8` そして `integralLimit`; `motion` 許す `accelerationLimit` そして `rampTimeMs`ベースライン、重力、検証段階は、候補の変更なしにデータを収集する。 P/D/I ベロシティゲインはファームウェアを使って Q8 単位: 分割して 256 出力制限は、バッチ全体を通じて明示的に供給されたコントローラの制限のままです。

アクセラレーションとランプタイムを一定に保ちながらゲインを比較し、必要な速度で動作設定を比較する。最大設定可能なアクセラレーションは最大です。 30,000 counts/s²;使用可能な値は負荷と工数に左右されますが、実際の参照速度と測定速度を確認してください。

積分利得とその限界は共に試験する必要があり、大きな蓄積された補正は摩擦解放後に関節を駆動し続けることができ、オーバーシュートを引き起こす。積分限界はその補正のみを境界とする。総モーター出力は`effortLimit`によって別々に制御される。安定した残差誤差を繰り返すことを好む。選択した設定が満たさない精度基準を報告する。

<a id="reuse-settings"></a>
## 再利用設定

コントローラプロファイルは別々にすることができます。 JSON 例えば ファイルは `"profiles": {"1": "motor-1.json"}`.Paths はコントローラファイルと相対的です。モーターファイルはインラインプロファイルと同じフィールドを含んでいます。 `accelerationLimit` そして `rampTimeMs` 共有デフォルトを上書きする. 同じローダーを通じてこれらのファイルを再生,遠隔操作,チューニングする. RAM 拡張機能のセットアップ中に保存されません。 EEPROM.

コントローラを、モーターごとに1つのファイル、`controller.json`、オプションの`gravity.json`、マニフェストを含む新しいディレクトリにエクスポートします。

```sh
npm run tune -- export CONFIG.json NEW_DIRECTORY
```

エクスポートはモーターに接続したり、設定を認証したりしません. リプレイ, 遠隔操作, チューニング プランでエクスポートした `controller.json` を使用します。

許容される設定を適用し、現在の位置を保持する。

```sh
npm run tune -- apply NEW_DIRECTORY/controller.json
```

起動時には、保持が有効なモーターと無効なモーターを自動的に処理します。既存のセッションでは、変更されたモーターだけを順番に短時間無効にし、再設定します。機構を支える他のモーターは保持を続け、既存の目標も維持されます。重力モデルを省略すると、保持されていた重力補償出力を消去します。再生は設定を自動で適用するため、このコマンドが必要なのは再生せずに設定だけを適用する場合です。

許容される設定、重力モデル、キャリブレーション、payload/mounting の説明と検証証拠を一緒に維持します。別のアームは独自のキャリブレーションと検証を必要とします。別のアームのエンコーダオフセットを復元しないでください。

<a id="how-a-batch-works"></a>
## バッチの動作方法

スクリーニングでは、ベースライン → 全候補 → ベースラインの順に実行します。各ブロックは、すべての位置ペアと速度を両方向で試し、繰り返しごとに最初の接近方向を入れ替えます。前後のベースラインの差が `driftRatio` を超えると、バッチは判定不能として終了し、モーターの保持を続けます。位置の変動にはエンコーダーの一カウント分の量子化を許容します。適格な候補を順位付けし、最大 `finalists` 件が、別の検証用ペアと長い保持時間を使い、共通のベースラインと再比較されます。推奨されるには、検証に合格し、対応するベースラインより良い結果を出す必要があります。

メトリクスは移動追跡を含む RMS安定した位置エラーとスパン,オーバーシュート,セットリング時間,総応答時間,飽和分数。バンド内の最終連続期間が必要で,早期交差はカウントされない。スクリーニングホールドが許可された設定時間よりも短く,居住,保持,設定メトリクスが遅延として報告される。スクリーニングすると,移動エラー,オーバーシュート,飽和がランク付けされる。推奨される前に,すべてのメトリクスをパスしなければならない。検証を行う。許容された設定時間と定常観察間隔をカバーするのに,バリデーションを十分に長持ちさせる。計画では,受け入れ制限が設けられている。成功していないが有効な応答をスコア付けできる。古いサンプル,アラーム,コントロールオーバーラン,過度追従エラー,サポートモーション,動作。 temperature/voltage 制限またはロギング障害はバッチを停止し、それを使用します。 [共有障害のクリーンアップ](../../host/arm-control/README.md#checks-and-timing)失敗したバッチは勧告を出さない。

フィードバックと重力は[共用リーダー](../../host/arm-control/README.md#checks-and-timing)を使って、計画はワイヤー使用量を推定し、50%以上の公称容量で要求を拒否します。

**プロファイルを変更すると、そのモーターのトルクが短時間解除されます。** 機構を支える他のモーターの制御は継続します。コントローラーは変更前に静止を待ち、変更後に重力補償を確認します。[プロファイルの変更](../../host/arm-control/README.md#api-and-tests)を参照してください。

すでに完了したエンドポイントホールドは、方向を反転させる前に再利用される。このツールは、重複したセットアップターゲットを送信したり、別のセットアップ遅延を追加したりしない。

通常の完了は、構成されたベースラインを復元し、最終的な重力補償でパワードホールドを保持する。Ctrl+Cはチューニングバッチを中断し、torque-offを試みる。中断前のメカニズムをサポートする。接続されていないプロセスまたは殺害されたプロセスは、最後のターゲットを保持するファームウェアを離れる可能性がある。このツールは、自動的に休息のポーズに戻ることはない。

<a id="results-and-agent-workflow"></a>
## 結果とエージェントワークフロー

実行は無視された `tools/tuning/logs/<run>/` ディレクトリの下で保存されます。

- `events.ndjson`:正確なplan/configuration、実装ハッシュ、重力モデル、キャリブレーション、プロファイルの変更、コマンド、測定、試験結果。
- `summary.json`:完成状況、比較、検証、推奨。

いくつかの明示的な候補を含む1つのプランを提出し、バッチ全体を終了させ、サマリーを検査する。障害のある条件や曖昧な結果に対して、生のイベントを使用する。これによって、パラメータごとに1つのプロセスと分析ラウンドが回避される。持続時間予算は常に作業に制限される。不完全なバッチには勧告がない。

結果を再計算するか、steady-motion識別ウィンドウを抽出します。

```sh
npm run tune -- analyse tools/tuning/logs/RUN/events.ndjson
node tools/tuning/cli.js extract tools/tuning/logs/RUN/events.ndjson > tools/tuning/logs/dataset.json
node tools/tuning/cli.js fit tools/tuning/logs/dataset.json
```

抽出には、スクリーニングと検証の両方において、完成したgravity/velocity実行、両方の方向と複数の速度が必要である。加速、飽和、測定不足、およびmoving-supportウィンドウを拒否する。フィットは、トレーニングと検証の間に軌道全体を分離し、実行時の重力ベースを使用する。測定された関節トルクやデプロイ可能なモデルではなく、レビューされていないeffort-space係数を返す。モデルのアップデートと独立ハードウェアチェックを意図的に繰り返す。

ご利用ください。 [シミュレーションビューア](../simulation/README.md) 実行中または実行後にアームを検査する同じイベントファイルで、バスのトラフィックは追加されません。
