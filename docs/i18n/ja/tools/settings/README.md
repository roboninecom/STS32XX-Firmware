# 発見、校正、設定。

検索 STS リポジトリの共有ドライバを使用し、レガシー設定をバックアップまたは復元します。 STS Node.jsが必要なコントロールテーブル 20 リポジトリルートからこれらのコマンドを実行する。 `npm ci`.

<a id="discover"></a>
## 発見

```sh
npm run settings -- discover --port /dev/cu.usbmodemYOUR_ADAPTER
```

モータIDに応答し、アラームを報告するリスト。 JSON発見は read-only 選択したボーレートをスキャンします。 1,000,000追加 `--baud 500000` Linux または Windows では、アダプターのポートなどを使用して、別のサポートレートを選択できます。 `/dev/ttyUSB0` それとも `COM3`.

モーターにはユニークなIDが必要ですが、IDを共有するモーターを識別したり、別のボーレートを使用してモーターを見つけることはできません。

<a id="back-up"></a>
## バックアップ

```sh
npm run settings -- backup --port /dev/cu.usbmodemYOUR_ADAPTER --id 2 \
  --file tools/settings/backups/servo-2.json
```

キャリブレーション、リミット、ゲイン、ID、ボーセレクタなど、共有コントロールテーブルで記述されているデバイスIDと永続的な設定をすべて保存します。バックアップはモーターを読み込むだけです。既存のファイルは上書きされません。`--file`がなければ、タイムスタンプ付きファイルは`tools/settings/backups/`の下で作成されます。これはGitによって無視されます。

<a id="restore"></a>
## 復元

復元中のモーターのみを接続し、トルクを無効にし、ロック設定し、アクティブなアラームをクリアします. ポートを使用して他のプログラムを閉じます. 同じモーターからバックアップを使用してください。

```sh
npm run settings -- restore --port /dev/cu.usbmodemYOUR_ADAPTER --id 2 \
  --file tools/settings/backups/servo-2.json
```

`--id` そして `--baud` 説明します **現在の接続**バックアップは、別のものを復元することができます ID ツールがモデルIDをチェックし、変更された設定だけを書き、保存されたレジスタ範囲が終了するのを待ち、設定を読み戻し、モーターをリロックします。トルクを有効にしたり、モーションコマンドを送信したりしません。復元に失敗すると、いくつかの設定が変更されることがあります。再試行する前にエラーを検査します。

これらのバックアップは、拡張設定やファクトリリセットテンプレートではなく、レガシー設定をカバーしています. カスタムファームウェアでファクトリファームウェアを書き込みさせた後の修復には、これを使用します。 [ファクトリー設定の復旧ツール](../flash/README.md#restore-factory-settings). そのバックアップファイルは、異なるフォーマットを使用し、このツールと互換性がありません。 JSON.

<a id="capture-offsets-then-limits"></a>
### オフセットをキャプチャし、制限します。

1つのコマンドは両方のステップをガイドします。

1. **参照ポーズ:** 選択した関節をメカニズムに合わせて繰り返しポーズで固定します。 **入力**ツールがモーターオフセットを書き込み、選択したジョイントがすべて読み込まれます。 **2048** キャプチャしたポーズで、保存したレジスタを検証します。
2. **共同制限:** 選択した関節を端から端まで移動します。各端で一時停止します。停止を強制しないでください。 **入力**ツールには制限がある **10 クリアランス数** 測定された各エンドポイントの内部。

テーブルの **Middle** は `(Min + Max) / 2` で、 丸みを帯びています。 情報的です: 保存限界は 2048 をその中間点に移動したり、オフセットを変更したりしません。 非対称制限は有効です。

起動時にモーターの保持が有効な場合、ツールはトルクを解除する前に機構を支えるよう求めます。それ以外の場合は、上記の二つの入力要求だけが表示されます。移動コマンドは送信しません。保存後もトルクは無効のままで、設定はロックされます。

参照キャプチャはいくつかの読み取りの中央値を使用する。小さな手の動きはキャリブレーションを停止せず、オフセットが保存されている間はわずかに移動しても別の確認は不要である。失敗した設定は影響を受けたモーターのそばに残って自動的に再試行する。このツールは書き込みを再試行する前に読み返されるため、認識の欠如はalready-saved設定を再度書き込むことはない。完成モーターは保持される。追加の確認は必要ない。

オフセットは、スイープの前に保存され、制限が保存されたときに変更されません。 2048エンコーダのラップアラウンドが追跡される; レンジクロス 0 それとも 4095 通常の制限や表示として保存することはできません。 `crosses zero` 中に **チェック** 少なくとも関節は動かなければいけません 64 カウントして、その制限が保存される前にフルターン未満。

仮読取エラーは、影響を受けたモーターの横に現れ、有効な読み取りが再開すると自動的にクリアされる。より速い手の動きは、speed-limitエラーをトリガーしない。すべての範囲が有効な場合にのみ保存される。それ以外の場合、記録は、測定が保持される。`reset 2`を使用して、参照ステップまたは他の関節を繰り返すことなく、M2の測定範囲のみをクリアし、その関節を再びスイープする。真の範囲の交差ゼロは、参照位置を修正する必要がある。測定をリセットしても、その物理的範囲が適合することができない。すべてのモーターエラーは、影響を受けたモーターの横に視認される。アラームまたは予期しないトルクは、その設定がクリアされるまで書き込まれ、接続が失われる。セッションは、まだ開かれ、終了した作業を維持する。自動リトライ中に、Ctrl+Cを押す。
