<a id="sts32xx-servo-driver"></a>
# STS32XX сервопривод

Драйвер Node.js для последовательных сервоприводов STS и прошивки STS32XX **расширение движения v9**. Он обеспечивает обнаружение, доступ к регистрам, операции настройки, S-curve команды движения, компенсацию гравитации и обратную связь через одно последовательное соединение. Требуется **Node.js 20 или новее** и совместимый последовательный адаптер.

Legacy операции используют управляющую таблицу STS, включенную в этот пакет. Для операций расширения требуется специальная прошивка v9; заводская прошивка их не предусматривает. Пакет предназначен для Node.js, а не для браузера Web Serial.

<a id="install"></a>
## Установить

Из этого репозитория:

```sh
npm ci
npm run test:driver
npm pack --workspace sts32xx-servo-driver --pack-destination /tmp
```

В другом проекте Node.js установите архив, созданный последней командой:

```sh
npm install /tmp/sts32xx-servo-driver-0.1.0.tgz
```

Это работает без публикации в реестре npm. В архиве находятся библиотека, примеры, README и лицензия. Последовательные зависимости устанавливаются через npm; Прошивка, логи и результаты тестов не включены.

ОбщийJS:

```js
const { StsServo } = require('sts32xx-servo-driver');
```

ES модули:

```js
import driver from 'sts32xx-servo-driver';
const { StsServo } = driver;
```

Существующие инструменты репозитория могут продолжать импортировать `host/servo-driver` напрямую. Используйте основной экспорт пакета; внутренние пути к файлам не являются частью его общедоступного API.

<a id="connect-and-read"></a>
## Подключайтесь и читайте

```js
const { StsServo } = require('sts32xx-servo-driver');

const servo = new StsServo({
  serial: { path: '/dev/cu.usbmodemYOUR_ADAPTER', baudRate: 1000000 },
});

async function main() {
  try {
    const found = await servo.connect();
    for (const id of found.ids) {
      const values = await servo.bus.read(id,
        ['presentPosition', 'presentVoltage', 'servoStatus']);
      console.log(id, values, found.alarms.get(id) ?? []);
    }
  } finally {
    await servo.close();
  }
}
main().catch(console.error);
```

Используйте `/dev/ttyUSB0`, `COM3` или фактический порт вашего адаптера по мере необходимости. Discovery находит отвечающие идентификаторы на выбранной скорости; он не изменяет настройки двигателя и не сканирует другие скорости передачи данных. Идентификаторы должны быть уникальными. Ожидание учитывает максимально возможное значение ID и выбранную скорость. `connect()` открывает порт и обнаруживает моторы; `open()` только открывает порт. Методы шины и расширения требуют обнаруженных идентификаторов.

Значения регистров используют необработанные единицы. Например, `presentVoltage: 120` означает 12 В. `ControlTable` описывает адреса, кодировки, диапазоны и масштабы отображения. В полях Multi-byte используется кодировка little-endian; подписанные Legacy значения используют знаковые биты.

<a id="main-api"></a>
## Главный API

Все операции, которые взаимодействуют с оборудованием, возвращают обещания.

| API | Цель |
| --- | --- |
| `servo.connect()` / `servo.close()` | Open/discover или закройте последовательное соединение. |
| `servo.bus.discover()` | Обновите список известных идентификаторов. |
| `servo.bus.scan()` | Откройте для себя, не заменяя список known-ID. |
| `servo.bus.verify(ids)` | Пропингуйте известные моторы по отдельности. |
| `servo.bus.read(id, keys, options)` | Чтение именованных регистров; возвращает объект с ключом по имени регистра. |
| `servo.bus.write(id, values, options)` | Напишите объект именованных регистров. |
| `servo.bus.readMany(ids, keys, options)` | Прочитайте несколько моторов, используя групповые запросы. |
| `servo.bus.syncWrite(entries, options)` | Напишите записи в форме `{ id, values }` в группе. |
| `servo.bus.device(id)` | Получите удобный объект с помощью методов `read`, `write` и reset/calibration. |
| `servo.settings.read(id)` | Прочтите постоянные Legacy настройки. |
| `servo.settings.save(id, values)` | Разблокируйте, сохраните, проверьте и снова заблокируйте обычные настройки. |
| `servo.arm` | Получите доступ к методам версии 9 ниже. |

При сохранении настроек используется таймаут запроса 250 мс. После потери подтверждения записи драйвер ожидает сохранения и считывает регистр перед повторной попыткой. Already-applied записи не повторяются. Временные сбои связи имеют до трех попыток; постоянные сбои все равно сообщают об ошибке и пытаются повторно заблокировать двигатель. Нажмите от `{ timeoutMs }` до `settings.save`, чтобы отменить тайм-аут.

Legacy пример для закрепленного двигателя в режиме положения, предназначенного для перемещения:

```js
await servo.bus.write(id, { targetPosition: 2048 },
  { timeoutMs: 100, rejectOnAlarm: true });
```

Legacy запись цели может автоматически включать крутящий момент в зависимости от сохраненных настроек. Постоянная запись может изменить калибровку, пределы или коэффициент усиления. Отключите крутящий момент перед изменением настроек. Настройки API защищают ID, скорость и response-level изменяются; используйте [настройки CLI](../../tools/settings/README.md) в репозитории для полной версии backup/restore. Сброс к заводским настройкам, reset-template и команды калибровки доступны через `servo.protocol`; звоните им только тогда, когда эти изменения предполагаются.

<a id="v9-control-lifecycle"></a>
## Жизненный цикл управления v9

1. Начните с отключения крутящего момента. Прочтите возможности и конфигурацию.
2. Примените проверенную конфигурацию с помощью `arm.configure()` при выключенном крутящем моменте.
3. Выберите режим расширения с новым ненулевым сеансом ID.
4. Включите крутящий момент, используя Legacy регистр 40, затем читайте обратную связь, пока сеанс не будет активирован, не будет обновлен, drive-enabled и output-ready.
5. Отправляйте цели и обновления гравитации. Проверьте принятые порядковые номера в свежих отзывах.
6. Напишите `torqueEnable: 0`, когда приложение намерено выпустить двигатель.

```js
const options = { timeoutMs: 100, rejectOnAlarm: true };
const caps = await servo.arm.capabilities(id, options);
if (caps?.major !== 9) throw new Error('Extension v9 is required');

// config must contain values validated for this motor and mechanism.
await servo.arm.configure(id, config, options);
await servo.arm.select(id, true, session, options);
await servo.bus.write(id, { torqueEnable: 1 }, options);
// Check readiness using servo.arm.feedback() before sending motion.

await servo.arm.setTargets([
  { id, target: { sequence: 1, positionQ8: 2048 * 256, speedLimit: 100 } },
], session, options);

await servo.arm.updateGravity(id,
  { session, sequence: 1, gravityEffort: -20 }, options);
```

Этот фрагмент показывает вызовы; [пример полного движения](../../../../../host/servo-driver/examples/v9-move.js) включает проверку, опрос готовности, приемочные проверки и очистку torque-off. Если подтверждения записи отключены, для Legacy записи требуется `expectResponse: false` и проверка обратного чтения. Полный пример обрабатывает это автоматически.

Прошивка удерживает последнюю цель и сохраняет последнее усилие силы тяжести до тех пор, пока она не будет заменена или крутящий момент не будет отключен. Нет пульса, тайм-аута команды или истечения гравитации. **Закрытие последовательного соединения не останавливает и не освобождает двигатель.** Выберите очистку приложения в соответствии с механизмом; отпускание нагруженной руки может привести к ее падению. Защита датчиков и двигателя остаются активными в прошивке.

Включение крутящего момента фиксирует измеренное положение. Не запускайте сеанс расширения с записью Legacy целей. Отключение крутящего момента или неисправность завершают сеанс; подготовьте новый сеанс перед перезапуском. Чтобы выбрать Legacy режим с отключением крутящего момента, используйте `arm.select(id, false, 0)`.

<a id="extension-methods"></a>
### Методы расширения

| Метод | Результат или эффект |
| --- | --- |
| `capabilities(id, options)` | `{ major, minor, tickMs }` для признанной подписи; неподдерживаемая прошивка может отклонить запрос или истечь тайм-аутом. |
| `configuration(id, options)` | Прочтите текущую конфигурацию RAM. |
| `configure(id, config, options)` | Запишите конфигурацию и проверьте закодированные байты путем обратного чтения. |
| `select(id, enabled, session, options)` | Подготовьте элемент управления v9 или выберите Legacy режим с помощью `false, 0`. |
| `setTargets(entries, session, options)` | Отправьте одну трансляцию, содержащую от одного до шести уникальных моторов. |
| `updateGravity(id, command, options)` | Отправьте подписанное гравитационное усилие с собственным порядковым номером. |
| `feedback(id, options)` | Прочитайте один последовательный операционный пример. |
| `tuning(id, options)` | Ознакомьтесь с обратной связью по эксплуатации, а также с эталонным движением и условиями индивидуальных усилий. |
| `invalidate(id)` | Очистка кэшированных возможностей после внешнего включения и выключения питания или изменения прошивки; опустите ID, чтобы очистить все. |

Драйвер автоматически аннулирует возможности при обнаружении, изменении ID, изменении соединения и сбросе, выданных через его протокол API.

<a id="configuration-and-units"></a>
### Конфигурация и агрегаты

Каждое поле конфигурации является явным. Этот объект иллюстрирует формат, а не рекомендуемый профиль настройки:

```js
const config = {
  kpQ8: 256, kdQ8: 0, kiQ8: 0,
  integralLimit: 0, effortLimit: 100,
  velocityLimit: 100, accelerationLimit: 500,
  velocityFilterQ8: 64, rampTimeMs: 30,
  velocityFeedforward: {
    positiveGainQ8: 0, negativeGainQ8: 0, effortLimit: 0,
  },
  gravitySlewEffortPerS: 1000,
};
```

| Поля | Единицы и пределы |
| --- | --- |
| `kpQ8`, `kdQ8`, `kiQ8` | Прибыль, умноженная на 256; целые числа 0–65535. |
| `effortLimit`, `integralLimit` | PWM единиц усилия; общий предел 1–1000, интегральный предел 0 – общий предел. |
| `velocityLimit`, цель `speedLimit` | Кодировщик counts/s; 1–65535. |
| `accelerationLimit` | Counts/с²; 1–30000, общий для ускорения и торможения. |
| `rampTimeMs` | S-curve время ускорения; 1–255 мс. |
| `velocityFilterQ8` | Коэффициент фильтра, умноженный на 256; 1–255. |
| Усиление прямой связи по скорости | Direction-specific выигрыш, умноженный на 256; 0–65535. Его ограничение усилий не может превышать общее ограничение. Установите оба усиления и ограничение на ноль, чтобы отключить его. |
| `gravitySlewEffortPerS` | Изменение силы тяжести в секунду; 1–10000. |
| Цель `positionQ8` | Положение энкодера, умноженное на 256; от −32767×256 до 32767×256. |
| `gravityEffort` | Подписано PWM усилие; от −1000 до 1000. Прошивка применяет свои ограничения. |

Ограничения на поездки основаны на сохраненных Legacy ограничениях позиций. Прошивка ограничивает цели активными пределами. Конфигурация — это состояние RAM, а не постоянный профиль настройки. Упреждение по локальной скорости соответствует заданию движения встроенного программного обеспечения; приложение предоставляет компенсацию гравитации отдельно.

Идентификаторы целей расширения: 1–253. Сеанс — 1–65535. Каждый двигатель отслеживает целевые и гравитационные последовательности отдельно. Увеличивайте соответствующую последовательность для каждой новой команды, перенося с 65535 на 0; принимаются форвардные гэпы до 32767. Начните новый сеанс с последовательности 1. Завершение широковещательной рассылки означает, что пакет был отправлен, а не то, что каждый двигатель его принял. Отметьте `acceptedSequence`, `gravitySequence` и `session` в последующих отзывах.

<a id="feedback-and-errors"></a>
### Отзывы и ошибки

`feedback()` включает измеренные position/velocity в Q8 единицах, приложенное усилие, ток ADC дельту, исходное напряжение, проверенную температуру, неисправности, сеанс и принятые последовательности. Используйте `fresh`, `ageMs`, `sampleSequence`, `armed`, `driveEnabled` и `outputReady`, чтобы определить, пригоден ли образец для использования. Температуру можно использовать только в том случае, если значение `temperatureValid` истинно. `running: false` означает, что планировщик больше не движется; это не гарантирует ошибку нулевой позиции.

`tuning()` добавляет ссылку position/velocity, запрошенное усилие, условия P/D/I, гравитационное усилие, упреждение по скорости и счетчик перебега.

Опции чтения и записи включают `timeoutMs` и `rejectOnAlarm`. Legacy сигналы тревоги по умолчанию не отклоняют действительные ответы; перейдите к `rejectOnAlarm: true`, когда сигнал тревоги должен прервать операцию. Типизированные ошибки включают `RequestTimeoutError`, `MissingResponseError`, `ServoStatusError`, `SettingsVerificationError` и `InvalidPacketError`. Дополнительный контекст находится в `error.details`; отказы от расширения включают здесь `extensionStatus`.

Планировщик сериализует запросы и поддерживает приоритеты и эксклюзивные транзакции. Ждите команд и используйте групповые цели для скоординированного движения. Тайм-аут ответа начинается после истощения последовательной записи; Транспортные операции имеют свои сроки. Эти тайм-ауты не меняют поведение двигателя. Legacy пакеты не имеют порядкового номера, поэтому необычно поздний ответ не всегда можно отличить от более позднего запроса с той же формой ответа.

Экспорт Low-level включает `SerialTransport`, `StsProtocol`, `RequestScheduler`, `PacketEncoder`, `PacketDecoder`, `RegisterCodec`, `RegisterLayout`, `ArmCodec`, константы и ошибки. Они остаются отдельными от автобуса high-level API.

<a id="runnable-examples"></a>
## Запускаемые примеры

Из этого каталога или с помощью файлов примеров, включенных в установленный пакет:

```sh
node examples/discover.js /dev/cu.usbmodemYOUR_ADAPTER
node examples/v9-feedback.js /dev/cu.usbmodemYOUR_ADAPTER 2
node examples/v9-move.js /dev/cu.usbmodemYOUR_ADAPTER 2 2048 100 /path/to/config.json
```

Первые два примера только читаются. В примере с движением требуется конфигурация JSON с полями выше и используется 1 Мбод. Запускайте его на закреплённом, ненагруженном моторе со свободным ходом. Он отключает крутящий момент после перемещения, ошибки или плавного нажатия Ctrl+C. Он ожидает до 3 секунд для запуска и 30 секунд для перемещения. Необязательный последний аргумент: гравитационное усилие со знаком, ноль по умолчанию. Не используйте его для поддержки нагрузки на руки.
