<a id="shared-arm-controller-and-gravity-compensation"></a>
# Общий контроллер руки и компенсация гравитации

Дистанционное управление в реальном времени, настройка, воспроизведение named-pose и воспроизведение timed-session используют один ведомый контроллер. Он управляет настройкой, целями, измеренной обратной связью, гравитацией и очисткой. [серводрайвер](../servo-driver/README.md) отвечает за кодирование и транспортировку пакетов.

<a id="motor-settings-files"></a>
## Файлы настроек двигателя

См. [профили SO-101 и SO-102](profiles/README.md): там приведены эталонные настройки и ограничения их применения.

`profiles` может содержать встроенные настройки или пути относительно файла контроллера:

```json
"profiles": {"1": "motor-1.json", "2": "motor-2.json"}
```

[Пример профиля](../../../../../host/arm-control/profile.example.json) используется в примерах инструментов. Скопируйте его для своих настроек и обновите ссылку или встройте профиль. Если вы перемещаете файл контроллера, отрегулируйте его профиль и траекторию гравитации. Файлы с именем `*.local.json` игнорируются Git.

Установите `acceleration` в counts/s² (1–30000) и `rampTimeMs` в миллисекундах (1–255) на контроллере. Каждый двигатель может переопределить их с помощью `accelerationLimit` и `rampTimeMs` в своем профиле. Профили — это настройки расширения RAM; сохраненные смещения энкодера и пределы перемещения остаются отдельными.

| Поле профиля | Значение |
| --- | --- |
| `kpQ8`, `kdQ8`, `kiQ8` | Коэффициент усиления контроллера, умноженный на 256. |
| `integralLimit`, `effortLimit` | Интегральные и общие пределы производительности в единицах усилия PWM. |
| `velocityLimit` | Максимальная скорость в counts/s; по умолчанию — 65535. |
| `velocityFilterQ8` | Настройка фильтра измеренной скорости, 1–255. |
| `gravitySlewEffortPerS` | Предел скорости изменения гравитационного усилия. |
| `velocityFeedforward` | `positiveGainQ8`, `negativeGainQ8`, `effortLimit`; обнулите все три, чтобы отключить. |

Полные единицы измерения и диапазоны см. в [руководстве по регистрации прошивки](../../DETAILED_DOCUMENTATION.md#configuration--0xa0)]. Это настройки per-motor, а не переключаемые профили прошивки.

Использование приложения настройки и настройки `joints: [{ "followerId": 1 }]`; добавьте одну запись для каждого управляемого двигателя. Воспроизведение Named-pose получает идентификаторы из записи и не требует массива `joints`. Только для телеоперации в реальном времени и recorded-leader повтора требуются `leaderId`, `mapping` и опционально direction/centers; см. [картирование телеопераций](../../tools/teleoperation/README.md#mapping-and-control).

<a id="enable-gravity"></a>
## Включить гравитацию

Добавьте `gravityModel` в существующую конфигурацию. Пути указаны относительно **файла конфигурации**, а не рабочего каталога. Для конфигурации, сохраненной в корне репозитория:

```json
"gravityModel": "host/arm-control/models/arm-upright-empty.json"
```

Эта строка является дополнением к полной конфигурации, а не отдельным файлом. Предоставляйте проверенные `profiles` каждому подписчику; `effortLimit` ограничивает общую мощность двигателя, а `gravitySlewEffortPerS` ограничивает скорость изменения гравитационного усилия. Установка только поворота не обеспечивает гравитацию. Без `gravityModel` при воспроизведении сбрасываются любые остаточные усилия гравитации, а затем запускаются без компенсации гравитации.

Входящие в комплект [модели рук](models/README.md) сохраняют калибровку каждой стойки, empty-gripper руки. Их коэффициенты для двигателей 2–4 используют измеренные значения энкодеров, включая связанные соединения; двигатели 1, 5 и 6 явно используют ноль. Каждому управляемому последователю нужна модель, и все соединения, используемые в ее терминах, должны контролироваться и измеряться. Модели Angle-dependent также объявляют `encoderCalibration` для каждого входа: подписанные `positionCorrection`, `resolution: 1` и `reverse` (флаг реверса энкодера). Предварительная проверка сравнивает их с регистрами двигателя и отклоняет несоответствие перед настройкой или включением крутящего момента. Восстановите соответствующую резервную копию с той же руки или обновите и проверьте модель после повторной калибровки. Снимок ссылки на 2048 сам по себе не определяет физические углы модели; см. [руководство по калибровке](../../tools/settings/README.md#choose-the-reference-pose). Для любой поставляемой модели six-motor укажите идентификаторы 1–6 и все шесть профилей. Не используйте модель повторно после изменения смещений энкодера, монтажа, геометрии или полезной нагрузки без проверки калибровки.

Используйте одно и то же поле конфигурации для каждой команды:

```sh
npm run teleoperate -- CONFIG.json
npm run replay -- CONFIG.json POSES.json
npm run replay -- CONFIG.json SESSION.ndjson
```

Эти команды предназначены только для предварительного просмотра. Добавьте `--run`, чтобы начать управление. Текущая конфигурация и измеренные положения толкателя определяют гравитацию; зарегистрированные значения гравитации и исторические достижения никогда не воспроизводятся. Модель проверяется перед использованием, а ее путь и хеш SHA-256 включаются в журнал сеанса.

<a id="control-behaviour"></a>
## Контролируйте поведение

1. Предполетная проверка прошивки, сохраненных ограничений, работоспособности, профилей и входных данных модели.
2. Все инструменты контроллера продолжают совместимый сеанс или автоматически подготавливают новый. Соответствующие профили сохраняют крутящий момент; измененные профили применяются по одному двигателю за раз. Новая настройка обеспечивает высвобождение крутящего момента, настройку и выбор, а затем включает все подготовленные двигатели вместе.
3. Гравитация измеряется, отправляется и подтверждается перед первой целью движения.
4. Во время движения и пауз один проход обратной связи обеспечивает как проверку работоспособности, так и расчет силы тяжести. Гравитация обновляется примерно каждые 50 мс. Нет второго считывателя телеметрии или контура прямой связи по скорости хоста.
5. При нормальном выходе гравитация продолжается до последнего движения, а оставшаяся гравитация прошивки поворачивается. Контроллер ожидает паузы 200 мс с тайм-аутом завершения 30 с, а затем подтверждает окончательное обновление гравитации. Крутящий момент остается включенным; Прошивка сохраняет последнюю цель и гравитационное усилие.

Для воспроизведения и телеоперации Ctrl+C останавливает новые цели и следует той же последовательности завершения. Вместо этого настройка прерывает пакет и пытается выполнить torque-off. Ctrl+C не является аварийной остановкой. Отдых означает, что планировщики остановлены, и каждое измеренное положение остается в пределах диапазона one-count в течение всего интервала 200 мс. Это не доказывает нулевую ошибку отслеживания; pose/session воспроизведение также применяет настроенный допуск прибытия.

После выхода процесс прекращает обновлять гравитацию. Если впоследствии рука будет перемещена или ее нагрузка изменится, сохраняемое усилие не адаптируется. Завершенный процесс или отключенная шина также могут оставить активными последнюю цель и усилие.

<a id="checks-and-timing"></a>
## Проверки и сроки

Гравитация использует измеренные позиции последователей, а не запрашиваемые цели. Образец обратной связи должен быть исправным, свежим и относиться к текущему сеансу. Каждое гравитационное обновление имеет свою последовательность; принятие проверяется на следующем проходе обратной связи. Перед записью все результаты сверяются с ограничениями по усилию модели и двигателя. Чрезмерный результат — это ошибка, а не обрезанное значение.

Связанные измерения являются последовательными. Сбор, постановка в очередь и последующая запись должны оставаться в пределах 100 мс от начала прохода обратной связи. Следующее обновление также должно произойти в пределах этой границы; задержка чтения, регистратора или шины вызывает сбой вместо того, чтобы молча продолжать работу со старой серьезностью. Это проверки хоста, а не тайм-ауты прошивки. Асинхронный I/O может задержать обнаружение; они не делают хост контроллером real-time.

Проверки работоспособности в реальном времени выполняются примерно каждые 250 мс без гравитации или каждые 50 мс с ней. В воспроизведении используется подробная C2 обратная связь каждые 50 мс во время удержаний и воспроизведения по времени; чеки прибытия могут опрашиваться быстрее. `--compact` заменяет меньшие пакеты C1, в которых отсутствуют промежуточные позиции планировщика и вклады PID. Программа настройки считывает подробную обратную связь для всех двигателей при запуске, затем C2 для датчика и C1 для вспомогательных двигателей. Обратная связь всегда разделяет гравитацию читателя.

Ошибки модели, отклоненные обновления, missing/stale отзывы, потеря владельца, сигналы тревоги и температуры на уровне 60 °C или выше, попытка подтверждена torque-off на каждом подготовленном подписчике. Сообщается о сбоях очистки.

Единственным исключением является пропущенный крайний срок gravity-update во время установленного удержания: контроллер сохраняет крутящий момент только в том случае, если два новых прохода обратной связи подтверждают работоспособность неподвижных двигателей в одном сеансе. Запуск по-прежнему завершается неудачей и сообщает `holdRetained: true`; он не возобновляется автоматически.

Записи журнала телеметрии включают измеренную обратную связь и последнюю запрошенную гравитацию effort/sequence. Отзывы о встроенном ПО подтверждают этот запрос на последующем образце; записанный запрос сам по себе не является доказательством принятия. `settledAt` — это консервативная оценка хоста того, когда запрошенное гравитационное разворот может завершиться.

<a id="api-and-tests"></a>
## API и тесты

`session.run` управляет последовательными соединениями, журналами сеансов и очисткой источника входного сигнала. `ArmController` принимает драйвер следящего устройства, конфигурацию, источник входного сигнала и дополнительный экземпляр `GravityModel`. Загрузите модели с помощью `await GravityModel.load(filename)`; CLI разрешает путь configuration-relative. Источники ввода обеспечивают `joints`, `preflight`, `describe`, `sample` и `play`; живой ввод дополнительно проверяет, отключен ли его лидер. Автоматизированная настройка может запросить подробную информацию о двигателе датчика через тот же считыватель. `changeProfile` проверяет стационарное управление, отпускает только этот двигатель, настраивает и re-enables его, затем снова подтверждает гравитацию. Вспомогательные двигатели остаются включенными. Измененный двигатель ненадолго теряет крутящий момент и при перезапуске фиксирует измеренное положение; используйте поддерживаемую или механически безопасную позу для изменения профиля. При ошибках профиля используется обычная очистка ошибок all-motor.

Источники отправляют позиции через контроллер и используют его обслуживаемые ожидания, поэтому длинные паузы продолжают обновлять обратную связь.

Запустите `npm run test:arm` для общего контроллера, `npm run test:poses` для recording/replay и `npm run test:teleoperation` для управления в реальном времени. В тестах используются моделируемые последовательные реакции.
