<a id="quick-start"></a>
# Быстрый старт

Для сервоприводов GD32F130-based STS TTL. Приведенные ниже команды используют синтаксис оболочки macOS/Linux и запускаются из корня репозитория. Для расширенных инструментов движения требуется прошивка v9; Legacy воспроизведение также поддерживает заводскую прошивку.

<a id="1-install"></a>
## 1. Установить

Установите Node.js 20+ и Python 3.10+; для дополнительного средства просмотра симуляций требуется Python 3.12.

```sh
npm ci
python3 -m venv tools/flash/.venv
tools/flash/.venv/bin/python -m pip install -r tools/flash/requirements.txt
export SERVO_PORT=/dev/cu.usbmodemYOUR_ADAPTER
```

Замените порт на свой, например `/dev/ttyUSB0` в Linux. В примерах используется двигатель ID **1** и скорость **1000000**; отрегулируйте их в соответствии с вашим сервоприводом.

<a id="2-back-up-and-flash"></a>
## 2. Резервное копирование и прошивка

**Прошивка может повредить сервопривод или стереть калибровку.** Закрепите механизм, обеспечьте стабильное питание, отключите удержание и закройте другие программы, использующие последовательный порт. Перед прошивкой настройки должны быть заблокированы, а аварийные флаги — сброшены. При обычной установке пользовательской прошивки моторы с уникальными ID могут оставаться подключёнными: прошивайте по одному ID, не выполняя power-cycle шины (перезапуск питания). Для восстановления должен быть подключён только восстанавливаемый сервопривод.

```sh
npm run settings -- discover --port "$SERVO_PORT"
npm run settings -- backup --port "$SERVO_PORT" --id 1
```

Загрузите **пользовательскую прошивку ZIP** из [v0.1-предварительной версии](https://github.com/roboninecom/STS32XX-Firmware/releases/tag/v0.1-preview) в разделе **Активы**. Извлеките образ прошивки и `release.json` вместе в `tools/flash/releases/custom/`. Не используйте архивы **Исходного кода** GitHub для перепрошивки.

```sh
tools/flash/.venv/bin/python tools/flash/flash.py inspect \
  --manifest tools/flash/releases/custom/release.json
tools/flash/.venv/bin/python tools/flash/flash.py flash \
  --manifest tools/flash/releases/custom/release.json --port "$SERVO_PORT" --id 1
```

Введите `FLASH` при появлении запроса и оставьте питание включенным до завершения проверки. Повторите команду flash для каждого двигателя ID, каждый раз ожидая проверки. См. [прошивка и восстановление](tools/flash/README.md), если проверка не удалась.

**Заводская прошивка ZIP** предназначена для возврата к заводской прошивке, а не для инструментов движения, указанных ниже. Распакуйте его в отдельную папку и следуйте [восстановление заводских настроек](tools/flash/README.md#restore-factory-settings) после перепрошивки. Сохраняйте каждый образ прошивки со своим собственным `release.json`.

<a id="3-calibrate-joint-offsets-and-limits"></a>
## 3. Калибровка смещений и пределов соединений

Для механизма с ограниченным ходом шарнира выберите идентификаторы двигателей для калибровки:

```sh
npm run settings -- calibrate --port "$SERVO_PORT" --ids 1,2,3 \
  --file tools/settings/calibrations/arm.json
```

Замените идентификаторы примеров на свои; опустите `--ids`, чтобы использовать все обнаруженные двигатели (до шести). Для SO-101 и SO-102 см. [помеченные эталонные изображения поз](tools/settings/README.md#reference-pose-images). Команда состоит из двух шагов:

1. Поместите каждое выбранное соединение, включая валик запястья и захват, в исходное положение механизма. Для новой установки без него выберите повторяемую позу примерно в середине хода каждого сустава. Удерживайте неподвижное положение и нажмите **Enter**, чтобы сохранить смещения, чтобы в этой позе они читались как 2048.
2. Переместите каждый выбранный сустав из конца в конец, ненадолго останавливаясь на концах. Просмотрите живую таблицу и нажмите **Ввод**, чтобы сохранить ограничения.

Поддерживайте механизм во всем; не останавливайтесь принудительно. Крутящий момент остается выключенным. Файл обновляется автоматически, и резервные копии двигателя сохраняются. Если второй шаг не удался, смещения первого шага остаются сохраненными: завершите калибровку, прежде чем включать движение. Измеренная средняя точка не заменяет полученное эталонное значение. 2048 — это только ссылка на энкодер; он не устанавливает физический угол для моделирования или гравитации. См. [выбор эталонной позы](tools/settings/README.md#choose-the-reference-pose). Сделайте это перед записью поз или установкой компенсации гравитации. Существующие манипуляторы с проверенной калибровкой не требуют повторной калибровки после вспышки settings-preserving.

<a id="4-check-communication"></a>
## 4. Проверьте связь

Не допускайте крутящего момента. Установите `--ids` для подключенных двигателей.

```sh
npm test
npm run bus-benchmark -- --port "$SERVO_PORT" --ids 1 --repetitions 100
npm run telemetry -- --port "$SERVO_PORT" --ids 1 --samples 1000 --interval-ms 20 \
  --output tools/diagnostics/results/first-check
```

`npm test` не в сети. Другие команды читают оборудование и печатают пути к отчетам. Каждый раз используйте новый каталог вывода телеметрии; отрегулируйте `--voltage-min` и `--voltage-max`, если ваше питание выходит за пределы диапазона 8–16 В по умолчанию. Перед началом движения проверьте неисправности и помеченные показания. Для сравнения factory/custom следуйте [руководству по тестированию оборудования](tools/hw-diff-tests/README.md): его полный пакет перемещает двигатели, заменяет сохраненные настройки и шаблоны сброса.

<a id="5-record-and-replay-poses"></a>
## 5. Записывайте и воспроизводите позы

Поддержите механизм, прежде чем ослаблять крутящий момент. Переместите его вручную, введите имя, чтобы сохранить каждую позу, затем введите `done`. Используйте все необходимые идентификаторы двигателей для руки.

```sh
npm run record-poses -- --port "$SERVO_PORT" --ids 1
cp tools/poses/replay.example.json tools/poses/controller.local.json
```

Отредактируйте `tools/poses/controller.local.json`: установите `followerPort`, укажите запись `profiles` для каждого двигателя и выберите подходящие усиления, пределы усилия, скорость и ускорение. Примерные значения являются иллюстративными. Пример ссылается на общий профиль; скопируйте этот профиль для своей выгоды и обновите его путь или вставьте настройки. Пути указаны относительно файла контроллера. Сначала проверьте сохраненную калибровку и пределы положения. Ведомая шина должна содержать именно сконфигурированные двигатели. Replay обрабатывает включенные и отключенные двигатели и автоматически применяет измененные настройки.

Замените `POSES.json` на сохраненный путь рекордера:

```sh
npm run replay -- tools/poses/controller.local.json POSES.json
npm run replay -- tools/poses/controller.local.json POSES.json --run
```

Первая команда предварительного просмотра; `--run` включает движение. **При нормальном завершении двигатели остаются включенными, удерживая конечную цель. Ctrl+C не является аварийной остановкой.** См. [настройки воспроизведения](tools/poses/README.md#replay-poses).

Для сравнения с использованием сохраненных настроек двигателей PID без компенсации:

```sh
npm run replay-legacy -- POSES.json --port "$SERVO_PORT" --run
```

Файл контроллера не требуется. Опустите `--run` для предварительного просмотра read-only. См. [Legacy повтор](tools/poses/README.md#legacy-replay), чтобы узнать о настройках скорости и ускорения.

<a id="6-enable-gravity-compensation"></a>
## 6. Включить компенсацию гравитации

Для `tools/poses/controller.local.json` добавьте это поле top-level:

```json
"gravityModel": "../../host/arm-control/models/arm-upright-empty.json"
```

Включенная модель предназначена для калиброванного вертикального **SO-ARM-102 с пустым захватом**. Включите двигатели 1–6 и все шесть профилей. Двигатели 2–4 получают компенсацию; остальные получают ноль. Калибровка энкодера должна совпадать; для изменения крепления, геометрии или полезной нагрузки требуется проверенная модель. Не меняйте калибровку только для того, чтобы избежать несоответствия. Для другого механизма или калибровки подберите и проверьте соответствующую модель.

[SO-101 и SO-102 профили контроллера](host/arm-control/profiles/README.md) включают PID, модели прямой связи по скорости и соответствующие гравитационные модели. Перед использованием прочтите их ограничения; они привязаны к калибровке установленного оружия.

Воспроизведение, телеоперация и настройка используют одно и то же поле. Гравитация следует за измеренными положениями во время работы инструмента; после выхода сохраняется только последнее усилие. Требования к модели см. в [руководстве по гравитации](host/arm-control/README.md)].

<a id="7-tune-and-view-motion"></a>
## 7. Настройка и просмотр движения

Скопируйте и отредактируйте [план настройки](../../../tools/tuning/example.json) и [пример контроллера](../../../tools/tuning/controller.example.json); установите путь плана `config` к файлу вашего контроллера. Для первого запуска используйте небольшие безопасные ходы `"stage": "baseline"` и `"candidates": []`.

```sh
npm run tune -- inspect PLAN.json
npm run tune -- preflight PLAN.json
npm run tune -- run PLAN.json
```

Только `run` перемещает оборудование. Следуйте [порядку настройки](tools/tuning/README.md#tuning-order): базовая линия → сила тяжести → упреждающая скорость → P/D и фильтрация → интеграл, если необходимо → acceleration/ramp время → комбинированное движение → проверка.

Для визуализации установите [просмотр симуляции](tools/simulation/README.md), затем используйте путь event-log, напечатанный при воспроизведении или настройке:

```sh
tools/simulation/.venv/bin/python tools/simulation/viewer.py live EVENTS.ndjson --model so101
tools/simulation/.venv/bin/python tools/simulation/viewer.py play EVENTS.ndjson --model so101
```

Используйте `--model so102` для другой модели руки в комплекте. Ознакомьтесь с соглашением reference-pose в руководстве для просмотра. Команда автоматически обрабатывает панель запуска окон macOS. Зритель отображает размеренное движение; он не предсказывает результаты настройки. Информацию об управлении hand-operated с использованием отдельных адаптеров ведущего и ведомого устройства см. в [телеоперации](tools/teleoperation/README.md).
