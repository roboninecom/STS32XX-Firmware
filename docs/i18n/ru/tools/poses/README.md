<a id="record-and-replay-poses"></a>
# Записывайте и воспроизводите позы

Запишите названные положения с отключенным крутящим моментом, а затем воспроизведите их либо с сохраненными Legacy настройками, либо с настроенными настройками расширения. Команды выполняются из корня репозитория.

| Команда | Ввод | Прошивка |
| --- | --- | --- |
| `npm run record-poses` | Ручное позиционирование | Завод или заказ |
| `npm run replay` | Именованные позы или сеанс телеоперации | Расширение v9 |
| `npm run replay-legacy` | Именованные позы | Заводская или кастомная версия v9 |

<a id="record-poses"></a>
## Запись позы

Установите Node.js 20 или новее, затем запустите из корня репозитория:

```sh
npm install
npm run record-poses -- --port /dev/ttyUSB0 --ids 1,2,3
```

Замените порт и идентификаторы для вашей настройки. Необязательные флаги: `--baud` (по умолчанию 1000000), `--output DIR` и `--timeout-ms` (по умолчанию 1000).

Сначала завершите [калибровку смещения и предела](../settings/README.md#calibrate-joint-offsets-and-limits)]. Записанные позы представляют собой путевые точки движения; захват позы под названием `home` или `reference` не меняет калибровку мотора.

1. Поддерживайте механизм, чтобы он не упал при отпускании крутящего момента.
2. Нажмите Enter в ответ на запрос подтверждения. Регистратор отключает крутящий момент на выбранных двигателях и проверяет его выключение. Остальные моторы не менялись.
3. Переместите механизм, удерживайте его неподвижно, затем нажмите Enter, чтобы запечатлеть позу. Вместо этого вы можете ввести уникальное имя; безымянные позы становятся `position-1`, `position-2` и т. д.
4. Повторите по мере необходимости. Введите `done`, чтобы закончить, или нажмите Ctrl+C, чтобы прервать.

После записи крутящий момент остается выключенным. Считывание происходит последовательно, поэтому каждая поза представляет собой снимок неподвижного механизма, а не измерение синхронизированного движения. Отсутствие показаний, сигнализация или включенный двигатель останавливают сеанс. При выходе инструмент снова пытается отключить крутящий момент и сообщает о любой неудачной проверке.

<a id="saved-files"></a>
## Сохраненные файлы

Новый файл JSON создается в `tools/poses/recordings/` для каждого сеанса. Каждый успешный захват заменяет этот файл атомарно; ранее сохраненные позы остаются доступными, если более поздний захват не удался. Записи игнорируются Git.

Формат версии `sts-poses` и 1 определяет позиции по двигателю ID, а не по порядку массива:

```json
{
  "format": "sts-poses",
  "version": 1,
  "units": "encoder-counts",
  "ids": [1, 3],
  "readMode": "sequential",
  "poses": [
    {
      "name": "home",
      "capturedAt": "2026-10-24T12:00:00.000Z",
      "durationMs": 4.2,
      "positions": {"1": 2048, "3": 3100}
    }
  ]
}
```

Файлы также включают время сеанса, последовательный порт и скорость передачи данных. Временные метки позы отмечают начало чтения; `durationMs` измеряет полный захват. Подсчеты представляют собой зарегистрированные позиции со знаком, уже включая смещение двигателя и настройку направления, без преобразования в углы. В файле нет настроек скорости, ускорения или времени воспроизведения, а также нет калибровочного снимка. Re-record положения после изменения калибровки энкодера; повтор не может обнаружить, что старый файл позы использует другие смещения.

<a id="replay-poses"></a>
## Воспроизведение поз

Скопируйте [replay.example.json](../../../../../tools/poses/replay.example.json) рядом с оригиналом, например, как `tools/poses/controller.local.json`. Установите `followerPort` и укажите одну запись `profiles` для каждого записанного двигателя. Идентификаторы берутся из записи; никакой лидер или совместное картографирование не требуется. В примере используется общий профиль [профиль двигателя](../../../../../host/arm-control/profile.example.json). Скопируйте этот профиль для своих собственных настроек и обновите его путь или вставьте настройки в строку. Все пути профиля и гравитации указаны относительно файла контроллера. Примеры выигрышей иллюстрируют формат; используйте настройки, проверенные на вашем механизме.

```sh
npm run replay -- CONFIG.json POSES.json
npm run replay -- CONFIG.json POSES.json --run
```

Первая команда просматривает полный путь без изменения настроек и сообщает о целях, ограниченных сохраненными пределами. `--run` начинает движение, включая подход из текущего положения к первой позе. Открыт только ведомый порт. Файлы размером до 64 MiB принимаются и проверяются до открытия порта.

[Общий контроллер](../../host/arm-control/README.md) применяет профили, обрабатывает существующие активные сеансы и обеспечивает компенсацию гравитации, если настроен `gravityModel`. **Обычное завершение и сочетание клавиш Ctrl+C сохраняют удержание.** При ошибках используется очистка контроллера; Ctrl+C не является аварийной остановкой. Необязательные top-level `durationMs` завершают воспроизведение досрочно; опустите его, чтобы воспроизвести весь файл.

Каждая поза отправляется в одной групповой команде. Скорость соединения масштабируется в зависимости от пройденного расстояния, в зависимости от скорости воспроизведения и ограничения скорости каждого двигателя. Каждый двигатель генерирует свой собственный S-curve, поэтому прибытие является приблизительным и путевые точки не смешиваются. Воспроизведение ожидает завершения планировщиков и ввода всех измеренных позиций в положение `toleranceCounts`, а затем начинается удержание. Ход, превышающий `moveTimeoutMs`, не удался. Временные метки, записанные вручную, не определяют скорость воспроизведения.

| настройка `replay` | По умолчанию | Значение |
| --- | --- | --- |
| `speed` | 1000 | Максимальная скорость, 1–65535 энкодер counts/s. |
| `holdMs` | 1000 | Пауза после прихода, 0–600000 мс. |
| `repeat` | 1 | Количество проходов, 1–1000; каждый проход возвращается в первую позу. |
| `moveTimeoutMs` | 30000 | Таймаут прибытия, 1–600000 мс. |
| `toleranceCounts` | 10 | Допустимая погрешность измерения положения, 0–32767 считается. |

<a id="replay-a-recorded-session"></a>
## Воспроизвести записанный сеанс

Воспроизвести журнал телеоперации без подключения ведущего:

```sh
npm run replay -- CONFIG.json SESSION.ndjson
npm run replay -- CONFIG.json SESSION.ndjson --run
```

Запись должна содержать `preflight` с ограничениями лидеров и объединенным сопоставлением, за которыми следуют `command` события с монотонными временными метками и всеми позициями лидеров. Используйте то же сопоставление соединений в текущей конфигурации. Записанные позиции лидера сопоставляются через записанные пределы лидера и текущие ограничения ведомого. Применяются текущие профили и гравитация; исторические условия и усилия не используются повторно. Предполагаемая команда в журнале сбоя могла никогда не дойти до двигателей.

При воспроизведении сохраняются записанные промежутки; обработка задерживает растягивание времени вместо отправки пакетов catch-up. Обратная связь и обновления гравитации продолжаются во время пауз. применяются `replay.repeat`, `moveTimeoutMs` и `toleranceCounts`; `speed` и `holdMs` применяются только к названным позам. Последний кадр должен прийти до завершения.

<a id="legacy-replay"></a>
## Legacy повтор

Используйте сохраненные настройки двигателей PID без прямой связи по скорости выдвижения или компенсации силы тяжести. Файл контроллера не требуется, а постоянные настройки не изменяются. Двигателям необходим режим абсолютного положения и разрешение энкодера.

```sh
npm run replay-legacy -- POSES.json --port /dev/ttyUSB0
npm run replay-legacy -- POSES.json --port /dev/ttyUSB0 --run
```

Первая команда предварительного просмотра; `--run` движется. Идентификаторы берутся из файла позы; другие двигатели на адаптере остаются в покое. Кастомная прошивка переключается в Legacy режим. Программа установки кратковременно отключает и re-enables каждый выбранный двигатель, сначала устанавливая его текущее положение.

| Вариант | По умолчанию | Значение |
| --- | --- | --- |
| `--speed` | 1000 | Максимальная скорость, 1–32767 энкодер counts/s. |
| `--acceleration` | 5000 | Counts/s², 100–25400 кратно 100. Действуют сохраненные ограничения. |
| `--hold-ms` | 1000 | Удерживать после каждого запланированного хода, 0–600000 мс. |
| `--baud` | 1000000 | Скорость передачи данных адаптера. |

В каждой позе используется групповая команда и скорость distance-scaled для примерно одновременного прибытия. Цели ограничены сохраненными пределами позиции. Воспроизведение ожидает завершения внутренних профилей движения, а затем приостанавливается; для этого не требуется нулевая ошибка измеренного положения. Ход длительностью более 30 секунды не удался.

Завершение сохраняет крутящий момент в конечной позе. В отличие от воспроизведения расширения, **Ctrl+C пытается выполнить torque-off**, как и неудачные попытки. Сообщается о сбоях очистки.

<a id="logs-and-visualization"></a>
## Журналы и визуализация

Обе команды воспроизведения сохраняют журналы в игнорируемом `logs/motion/`, включая калибровку, идентификацию источника, команды и обратную связь. Запустите [просмотр телеметрии](../simulation/README.md) один раз, затем запустите повторы в другом терминале:

```sh
mkdir -p logs/motion
tools/simulation/.venv/bin/python tools/simulation/viewer.py live logs/motion --model so102
```

Используйте `--model so101` для другой связанной модели и соответствующего сопоставления кодировщика. Расширенный повтор считывает подробную информацию о движущейся ссылке, показанной зрителем. Чтобы уменьшить трафик, добавьте `--compact`; измеренное движение и компенсация остаются активными, но тень показывает пункты назначения вместо промежуточных положений планировщика. PID условия и применяемые компенсационные взносы также опущены. См. [обратная связь и время](../../host/arm-control/README.md#checks-and-timing).

Запускайте автономную запись, расширенное воспроизведение и тестирование Legacy воспроизведения с помощью `npm run test:poses`.
