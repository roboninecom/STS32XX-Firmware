# Тестирование шины и телеметрическая диагностика

Два инструмента command-line для сервоприводов STS: измерение производительности связи и проверка стационарной телеметрии на наличие необычных показаний. Требуется Node.js 20 или новее. Из корня репозитория установите зависимости с помощью `npm install`.

Держите двигатели неподвижными, отключив крутящий момент и заблокировав настройки. Остановите другие программы, использующие последовательный порт. Оба инструмента проверяют выбранные сервоприводы до и после запуска. Ни один из них не включает крутящий момент, не перемещает двигатель, не обновляет прошивку и не сохраняет настройки.

<a id="bus-benchmark"></a>
## Бенчмарк автобусов

```sh
npm run bus-benchmark -- --port /dev/cu.usbmodemXXXX --ids 1,2 --repetitions 1000
```

По умолчанию измеряются запросы PING и READ разных размеров. В каждом случае выполняется 20 попыток прогрева, затем 1,000 измеренных попыток на каждый двигатель. Порядок моторов меняется между раундами. Неудачные попытки остаются неудачными; повторные попытки никогда не заменяют их.

Полезные опции:

- `--list`: список случаев без открытия порта.
- `--cases ping,read-table-87`: запустить выбранные случаи.
- `--warmup 20`, `--repetitions 1000`: попытки по каждому случаю и двигателю.
- `--gap-ms 1`: пауза между запросами; по умолчанию нет добавленной паузы.
- `--results DIR`: родительский элемент вывода; по умолчанию — `tools/diagnostics/results`.
- `--include-writes`: также эталонная запись подтверждена в регистры RAM и 51–54. Эти регистры недокументированы в других прошивках; используйте эту опцию только на проверенном совместимом сервоприводе. Исходные значения восстанавливаются при завершении, сбое или плавном прерывании. Подтверждения записи должны быть включены.

При каждом запуске создается новый каталог, содержащий `summary.csv`, `report.json` и `samples.jsonl`. Сводка включает медиану, p95, p99 и максимальную задержку, а также время ожидания и количество ошибок. Необработанные записи включают обмены разминки и очистки.

Задержка начинается от вызова последовательной записи до соответствующего декодированного ответа. Он включает в себя задержки USB и operating-system; это не время отклика firmware-only или измерение максимальной пропускной способности шины. Тайм-ауты учитываются отдельно и не включаются в процентили задержки.

<a id="telemetry"></a>
## Телеметрия

```sh
npm run telemetry -- --port /dev/cu.usbmodemXXXX --ids 1,2 \
  --samples 1000 --interval-ms 20 --output tools/diagnostics/results/telemetry-check
```

Считывает 17 байт, начиная с регистра 56, один раз для каждого двигателя за раунд. По умолчанию установлено 100,000 выборок на двигатель без дополнительной паузы. Используйте новый выходной каталог для каждого запуска; существующие файлы примеров никогда не перезаписываются.

- `--interval-ms 20`: минимальный интервал между стартами раундов. Пропущенные слоты пропускаются и учитываются в `missedDeadlines`; отложенные раунды не вызывают очередей.
- `--gap-ms 1`: вместо этого делайте паузу после каждого запроса двигателя. Невозможно объединить с `--interval-ms`.
- `--voltage-min 5.5 --voltage-max 8.4`: ожидаемый диапазон напряжения в вольтах; по умолчанию — 8–16 В. Установите это значение для подключенных двигателей и источника питания.

Выходы: `samples.csv` содержит все попытки, `anomalies.jsonl` содержит помеченные показания и необработанные обмены, а `report.json` содержит счетчики, диапазоны, статистику времени и before/after настройки. CSV напряжение измеряется десятыми долями вольта; положение, скорость, ток и усилие сохраняют свои исходные единицы измерения.

Проверяет изменения напряжения и температуры флажков, неправдоподобные показания, ненулевое состояние и усилие при отключенном крутящем моменте. Для обнаружения скачков температуры требуется три последовательных действительных ответа; отсутствующий или неверный ответ нарушает последовательность. Эти флаги обозначают показания, которые необходимо проверить, а не являются доказательством неисправности встроенного ПО или датчика. Идентичные стационарные показания являются нормальными и не свидетельствуют об устаревших данных.

<a id="common-options-and-tests"></a>
## Распространенные варианты и тесты

Оба инструмента принимают `--baud 1000000`, `--timeout-ms 100` и `--help`. Идентификаторы по умолчанию равны `1,2`; укажите фактически подключенные двигатели. Тайм-аут ответа начинается после истощения последовательной записи. По истечении времени ожидания инструменты ждут, пока шина успокоится, прежде чем продолжить, поскольку ответы не содержат порядковых номеров.

Ctrl+C останавливает выполнение и выполняет очистку. Ошибки, неполные прогоны и помеченные образцы приводят к ненулевому коду выхода. Результаты ниже `results/` игнорируются Git.

```sh
npm run test:diagnostics
```

Эти автономные тесты не подключаются к оборудованию.
