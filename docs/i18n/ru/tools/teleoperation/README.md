<a id="teleoperation"></a>
# Телеоперация

Переместите приводного ведомого, перемещая неприводного лидера вручную. Поддерживает пары соединений 1–6 на двух отдельных последовательных шинах. Лидер может использовать заводскую прошивку; ведомому требуется прошивка v9 из этого репозитория.

<a id="run"></a>
## Беги

Установите Node.js 20 или новее, затем запустите `npm install` из корня репозитория. Скопируйте [example.json](../../../../../tools/teleoperation/example.json) рядом с оригиналом как `controller.local.json`. Установите порты, скорость передачи данных и идентификаторы соединений. В примере используется [профиль двигателя](../../../../../host/arm-control/profile.example.json) с повтором и настройкой. Скопируйте его для своих настроек и обновите его путь или вставьте в свои профили. Пути указаны относительно файла контроллера. Примеры выигрышей иллюстрируют формат; используйте настройки, проверенные на вашем механизме.

Предварительный просмотр отображения без изменения настроек двигателя:

```sh
npm run teleoperate -- CONFIG.json
```

Проверьте сообщаемые позиции и цели, поддержите оба механизма и оставьте место для ведомого, чтобы он мог двигаться к позе лидера. Запустите управление явно:

```sh
npm run teleoperate -- CONFIG.json --run
```

Каждая шина должна содержать именно свои настроенные идентификаторы. Оба механизма требуют сохраненных, непустых пределов позиции и обычного режима позиции с единичным разрешением. Настройки подчиненного устройства должны быть заблокированы без отложенной записи. Крутящий момент ведущего устройства уже должен быть отключен; этот инструмент никогда не пишет лидеру. Запуск ведомого устройства автоматически управляет включенными и отключенными двигателями.

Выполнение продолжается до нажатия Ctrl+C, если вы явно не установили `durationMs`. **Обычный выход сохраняет удержание с электроприводом.** Запуск, гравитация и устранение сбоев соответствуют [поведению общего контроллера](../../host/arm-control/README.md#control-behaviour).

<a id="mapping-and-control"></a>
## Картирование и контроль

Каждая запись `joints` содержит `leaderId`, `followerId` и `mapping`:

| Настройка | Значение |
| --- | --- |
| `mapping: "angle"` | Сохранение смещения энкодера от центра сохраненных пределов. |
| `mapping: "range"` | Масштабируйте каждую половину путешествия лидера до соответствующей половины ведомого. Полезно для захватчиков. |
| `direction` | `1` (по умолчанию) или `-1` для обратного движения. |
| `leaderMiddle`, `followerMiddle` | Дополнительные центры для картографирования дальности, строго в соответствующих пределах. |

Цели ограничены сохраненными лимитами последователя. `angle` работает с числом энкодеров, поэтому предполагает совместимые шкалы и передачу энкодера.

Центром отображения является средняя точка сохраненных пределов, которая может отличаться от эталонного значения калибровки на 2048. Таким образом, сопоставление поз калибровки само по себе не гарантирует совпадение целей, когда пределы ведущего и ведомого асимметричны. Предварительный просмотр сопоставления перед перемещением. `leaderMiddle` и `followerMiddle` переопределяют центры только для отображения `range`.

Предоставьте профиль для каждого ведомого и общие настройки acceleration/ramp, как описано в разделе [Настройки двигателя](../../host/arm-control/README.md#motor-settings-files). Добавьте `gravityModel`, чтобы включить [компенсацию гравитации](../../host/arm-control/README.md#enable-gravity).

<a id="timing-and-checks"></a>
## Сроки и проверки

| Дополнительная настройка | По умолчанию | Значение |
| --- | --- | --- |
| `hz` | 60 | Запрошенная частота обновления, 1–60 Гц. Пропущенные месячные пропускаются. |
| `maxAgeMs` | 100 | Максимальный возраст лидерного кадра перед отправкой, 10–10000 мс. |
| `responseTimeoutMs` | 100 | Тайм-аут очереди ответа и транзакции, 25–10000 мс. |
| `durationMs` | Безлимитный | Продолжительность работы, включая запуск управления, 1–86400000 мс. |

Каждый кадр должен включать каждую позицию лидера и оставаться в пределах `maxAgeMs` до отправки. Пропущенные периоды обновления пропускаются. Обратная связь, гравитация и регистрация используются в одном контуре управления; Достигнутая скорость зависит от производительности шины и компьютера. См. [совместные проверки и время](../../host/arm-control/README.md#checks-and-timing).

Журналы сохраняются в игнорируемом `logs/motion/` как newline-delimited JSON. Они содержат конфигурацию, выбранный сеанс ID, предварительный просмотр, предполагаемые команды, отправленные кадры, отзывы и stop/error записи. Сама по себе запись команды не доказывает, что цель была отправлена или принята. Записи ожидаются без накопления неограниченной очереди журналов; медленная регистрация может вызвать проверку frame-age.

Воспроизведите журналы без подключенного лидера, используя команду [recorded-session replay](../poses/README.md#replay-a-recorded-session).

Запустите автономные тесты с помощью `npm run test:teleoperation`.
