<a id="automated-tuning"></a>
# Автоматизированная настройка

Запустите ограниченную серию возможных настроек, сравните повторяющиеся ходы и более длительные удержания и получите рекомендацию machine-readable. Использует тот же драйвер, контроллер и калиброванную гравитационную модель v9, что и при воспроизведении и телеуправлении. Никакие настройки не записываются в EEPROM и ни один победивший кандидат не устанавливается автоматически.

<a id="start"></a>
## Старт

Из корня репозитория установите Node.js 20+ зависимости с `npm install`. Скопируйте `controller.example.json` и `example.json` рядом с оригиналами как `controller.local.json` и `plan.local.json`. Установите от `config` до `controller.local.json` плана, затем отредактируйте порт, идентификаторы двигателей, профили, пары безопасного перемещения шарниров и ограничения для вашего механизма. Примеры достижений и поз являются показательными. Контроллер ссылается на общий [профиль двигателя](../../../../../host/arm-control/profile.example.json); скопируйте его для своих собственных настроек и обновите его путь или встройте в профиль. Включите каждый вспомогательный двигатель как `{ "followerId": ID }` в `joints`; сопоставление лидеров не требуется. Выполните [калибровку](../settings/README.md#choose-the-reference-pose) перед выбором тестовых положений. Позиции используют исправленные счетчики кодировщиков; новое смещение меняет их физический смысл. Обновите тестовые пары, записи и гравитационную модель после повторной калибровки. Для гравитации добавьте `gravityModel` точно так, как описано в [общем руководстве по контроллеру](../../host/arm-control/README.md).

Путь плана `config` относится к плану. Профиль контроллера и пути `gravityModel` относятся к этому файлу контроллера. Ту же конфигурацию контроллера можно использовать для воспроизведения позы. Опустите `durationMs` для настройки: бюджет партии принадлежит плану. Обеспечьте механизм запуска и изменения профиля. Изменение профиля ненадолго освобождает этот двигатель; новая настройка может освободить всех настроенных подписчиков.

```sh
npm run tune -- inspect tools/tuning/plan.local.json
npm run tune -- preflight tools/tuning/plan.local.json
npm run tune -- run tools/tuning/plan.local.json
```

Инструмент продолжает поддерживать суставы в соответствии с существующими целевыми значениями прошивки. Только `probeId` проходит через заявленные тестовые пары. Автоматического изменения положения whole-arm нет. Текущие цели и измеренные положения регистрируются для сравнения между прогонами. Используйте проверенные пути соединения для текущей конфигурации рычага.

Используйте одну и ту же команду для первого пакета и каждого последующего пакета:

```sh
npm run tune -- run NEXT_PLAN.json
```

Изменения при запуске и профиле используют [жизненный цикл общего контроллера](../../host/arm-control/README.md#control-behaviour). Не запускайте другой контроллер на той же шине.

`inspect` не подключается. `preflight` считывает прошивку, калибровку, сохраненные лимиты, работоспособность и профили без смены моторов. `run` перемещает их. Цели ограничены сохраненными пределами позиции; предполетная подготовка сообщает эффективный путь. Пара, свернутая в одну позицию, не может использоваться в качестве упражнения по настройке.

<a id="tuning-order"></a>
## Порядок настройки

1. **Базовый уровень**: проверьте калибровку, безопасное перемещение, температуру и повторяемость с существующими настройками. Используйте `stage: "baseline"` и никаких кандидатов.
2. **Гравитация**: сохраняйте умеренный прирост обратной связи и сравнивайте замедленное движение в обоих направлениях в нескольких позах и как минимум на двух скоростях. Начните с откалиброванной модели. `stage: "gravity"` собирает идентификационные данные без изменения выигрыша.
3. **Упреждение по скорости:** после проверки гравитации сравните прирост скорости по направлению при устойчивом движении на нескольких скоростях.
4. **P/D и фильтрация по скорости:** отбирают небольшой явный набор кандидатов. Включите позы как с высокой, так и с низкой гравитационной нагрузкой, затем используйте более длинные удержания, чтобы подвергнуть колебаниям. Небольшая партия факториалов может вместе сравнивать P, D и фильтрацию; проверьте лучшую комбинацию на парах held-out.
5. **Встроенный:** только в том случае, если сохраняется постоянная ошибка; сравните точность перемещения, а также длительность удержания. Включите небольшие реверсы: одни только длинные проходы могут пропустить интегральный предел, который не позволяет неподвижному суставу преодолевать трение. Сохраняйте интегральный ноль, если только результат не поддерживает его включение.
6. **Ускорение и время линейного изменения:** при фиксированном коэффициенте усиления используйте `stage: "motion"` для сравнения ускорения и сглаживания на требуемых скоростях.
7. **Комбинированное движение**: воспроизведите записанную траекторию, которая тренирует каждый сустав и включает как сложенные, так и развернутые конфигурации. Усиление, которое работает при неподвижных опорных соединениях, может колебаться при движении всего механизма. Еще раз проверьте измененные соединения на этом же пути, прежде чем принять их настройки.
8. **Проверка**: заморозьте выбранную конфигурацию, повторите маршрут на каждой необходимой скорости и ускорении, а затем дольше удерживайте репрезентативные позы. Записывайте точность, перерегулирование, стабилизацию, температуру и выходное насыщение для каждого двигателя. Повторную проверку после изменения полезной нагрузки или калибровки.

`stage` ограничивает поля-кандидаты: `velocity` разрешает `velocityFeedforward`; `pid` позволяет `kpQ8`, `kdQ8`, `velocityFilterQ8`; `integral` позволяет `kiQ8` и `integralLimit`; `motion` позволяет `accelerationLimit` и `rampTimeMs`. Этапы базового уровня, гравитации и проверки собирают данные без изменений кандидатов. P/D/I и коэффициент усиления скорости используют единицы встроенного программного обеспечения Q8: разделите на 256 для получения соответствующего усиления. Пределы вывода остаются явно заданными пределами контроллера на протяжении всего пакета.

Сохраняйте фиксированное время ускорения и линейного изменения при сравнении результатов. Затем сравните настройки движения на необходимых скоростях. Максимальное настраиваемое ускорение составляет 30,000 counts/s²; полезная стоимость зависит от пределов нагрузки и усилия. Проверьте фактическую опорную и измеренную скорость: короткие ходы могут никогда не достичь требуемой скорости.

Интегральный коэффициент усиления и его предел необходимо тестировать вместе. Большая накопленная коррекция может продолжать приводить в движение сустав после прекращения трения, вызывая перерегулирование. Интегральный предел ограничивает только эту поправку; общая мощность двигателя контролируется отдельно с помощью `effortLimit`. Предпочитайте стабильную остаточную ошибку повторному поиску и сообщайте о любых критериях точности, которым выбранные настройки не соответствуют.

<a id="reuse-settings"></a>
## Повторное использование настроек

Профиль контроллера может представлять собой отдельный файл JSON, например `"profiles": {"1": "motor-1.json"}`. Пути указаны относительно файла контроллера. Файлы двигателей содержат те же поля, что и встроенные профили; необязательные `accelerationLimit` и `rampTimeMs` переопределяют общие настройки по умолчанию. Реплей, телеоперация и настройка загружают эти файлы через один и тот же загрузчик. Настройки применяются к RAM во время настройки расширения, а не сохраняются в EEPROM.

Экспортируйте контроллер в новый каталог, содержащий по одному файлу для каждого двигателя, `controller.json`, необязательный `gravity.json` и манифест:

```sh
npm run tune -- export CONFIG.json NEW_DIRECTORY
```

Экспорт не подключается к двигателям и не подтверждает настройки. Используйте экспортированный `controller.json` для повтора, телеуправления или плана настройки.

Чтобы применить принятые настройки и сохранить текущую позицию:

```sh
npm run tune -- apply NEW_DIRECTORY/controller.json
```

Запуск автоматически управляет включенными и отключенными двигателями. В существующем сеансе только измененные двигатели на короткое время отключаются и перенастраиваются по одному. Вспомогательные двигатели остаются включенными, а существующие цели сохраняются. Исключение модели гравитации приводит к удалению оставшегося гравитационного усилия. Воспроизведение автоматически применяет свою конфигурацию, поэтому эта команда необходима только для применения настроек без повторного воспроизведения.

Сохраните принятые настройки, гравитационную модель, калибровку, описание payload/mounting и доказательства проверки вместе. Другая рука нуждается в собственной калибровке и проверке. Не восстанавливайте смещения энкодера другого рычага.

<a id="how-a-batch-works"></a>
## Как работает пакетная обработка

Для проверки инструмент запускает базовый уровень → все кандидаты → базовый уровень. Каждый блок тренирует каждую пару и скорость в обоих направлениях, чередуя первый подход в повторах. Если две базовые линии выходят за пределы `driftRatio`, пакет заканчивается как безрезультатный и сохраняет свою активную позицию. Дрейф положения позволяет выполнить квантование за один отсчет энкодера. Подходящие кандидаты ранжируются, и до `finalists` повторяют сравнение между общими базовыми показателями в разных парах проверки с более длительным удержанием. Рекомендация требует прохождения проверки и превышения базового уровня.

Метрики включают отслеживание перемещения RMS, постоянную ошибку положения и диапазон, перерегулирование, время установления, общее время отклика и долю насыщения. Для урегулирования требуется заключительный непрерывный период внутри группы; раннее пересечение не в счет. Если удержание проверки короче, чем разрешенное время урегулирования плюс выдержка, показатели удержания и урегулирования сообщаются как отложенные. Затем при скрининге ранжируются ошибки перемещения, выбросы и насыщение. Прежде чем будет дана рекомендация, более длительная проверка должна пройти все метрики. Используйте удержание валидации достаточно долго, чтобы охватить допустимое время установления и постоянный интервал наблюдения. Пределы приемки указаны в плане. Неудачный, но действительный ответ может быть засчитан; устаревшие образцы, сигналы тревоги, превышение контроля, чрезмерная ошибка рассогласования, движение поддержки, ограничения temperature/voltage или сбои регистрации, остановите партию и используйте [очистку общих ошибок](../../host/arm-control/README.md#checks-and-timing). Неудачная партия не дает никаких рекомендаций.

Обратная связь и гравитация используют [общий читатель](../../host/arm-control/README.md#checks-and-timing). План оценивает использование проводов и отклоняет запросы при номинальной мощности 50% или выше; Фактические зазоры проверяются во время пробега. Визуализация читает журнал.

**Изменение профиля на короткое время снижает крутящий момент этого двигателя.** Вспомогательные двигатели остаются под контролем. Контроллер ожидает паузы перед изменением и после этого подтверждает гравитацию; см. [изменения профиля](../../host/arm-control/README.md#api-and-tests).

Уже завершенное удержание конечной точки используется повторно перед изменением направления; инструмент не отправляет дублирующую цель настройки и не добавляет еще одну задержку настройки.

Обычное завершение восстанавливает настроенную базовую линию и сохраняет механическое удержание с окончательной компенсацией гравитации. Ctrl+C прерывает пакет настройки и пытается нажать torque-off; поддержите механизм, прежде чем прерывать. Отключенный или убитый процесс может привести к тому, что прошивка удержит последнюю цель. Инструмент не возвращается в исходное положение автоматически.

<a id="results-and-agent-workflow"></a>
## Результаты и рабочий процесс агента

Запуски сохраняются в игнорируемых каталогах `tools/tuning/logs/<run>/`:

- `events.ndjson`: точное plan/configuration, хэши реализации, гравитационная модель, калибровка, изменения профиля, команды, измерения и результаты испытаний.
- `summary.json`: статус завершения, сравнения, проверка и рекомендации.

Отправьте один план, содержащий несколько явных кандидатов, дайте всей партии закончиться, а затем просмотрите сводку. Используйте необработанные события для невыполненных критериев или неоднозначных результатов. Это позволяет избежать одного раунда обработки и анализа для каждого параметра. Бюджет продолжительности всегда ограничивает работу. Неполная партия не имеет рекомендации.

Пересчитать результаты или извлечь окна идентификации steady-motion:

```sh
npm run tune -- analyse tools/tuning/logs/RUN/events.ndjson
node tools/tuning/cli.js extract tools/tuning/logs/RUN/events.ndjson > tools/tuning/logs/dataset.json
node tools/tuning/cli.js fit tools/tuning/logs/dataset.json
```

Для извлечения требуются завершенные прогоны gravity/velocity в обоих направлениях и на нескольких скоростях как при скрининге, так и при проверке. Он отвергает ускоряющиеся, насыщенные, плохо измеренные и moving-support окна. Подгонки разделяют целые траектории между обучением и проверкой и используют гравитационную основу времени выполнения. Они возвращают непроверенные коэффициенты effort-space, а не измеренный крутящий момент сустава или развертываемую модель. Обновите модель и сознательно повторите независимые проверки оборудования.

Используйте [просмотр моделирования](../simulation/README.md) в том же файле событий, чтобы проверить руку во время или после пробежки. Это не добавляет автобусного движения.
