<a id="hardware-comparison-tests"></a>
# Сравнительные тесты оборудования

Сравните заводскую и кастомную прошивку на сервоприводах STS. Пакет охватывает Legacy протокол, настройки, движение, калибровку и защиту. Он не проверяет управление протоколом расширения v9. Тесты используют [общий драйвер](../../host/servo-driver/README.md).

**Используйте специальный стенд с закрепленными сервоприводами и свободными валами.** Некоторые тесты требуют длительных или непрерывных перемещений и заменяют сохраненные настройки или калибровку. Сначала сделайте резервную копию каждого сервопривода. Обеспечьте возможность немедленно отключить питание двигателя.

<a id="setup"></a>
## Настройка

Установите Node.js **20 или новее**, затем запустите из корня репозитория:

```sh
npm ci
npm run test:diff
npm run diff -- --list
```

Эти команды выполняются в автономном режиме. `--list` показывает стадию каждого сценария, классификацию движения и точное название. Используйте `--help` для всех параметров команды.

Подключайте только тестовые сервоприводы: в некоторых случаях используются широковещательные передачи. Закройте другие программы с помощью адаптера и обеспечьте подходящее питание двигателя. Соединения по умолчанию:

| Настройка | По умолчанию |
|---|---|
| Заводской сервопривод ID | `1` |
| Сервопривод кастомной прошивки ID | `2` |
| Скорость передачи данных | `1000000` |

Установите разные значения с помощью `--factory-id`, `--candidate-id` и `--baud`. Идентификаторы должны быть разными; оставьте идентификаторы **250 и 251** неиспользованными, поскольку тесты используют их временно. Запуск с отключенным крутящим моментом, настройки заблокированы, активных сигналов тревоги нет. При сравнении движения используйте сопоставимые двигатели, источники питания и нагрузки.

```sh
export SERVO_PORT=/dev/cu.usbmodemYOUR_ADAPTER
```

Замените порт на свой. Linux обычно использует `/dev/ttyUSB0`; в Windows передайте порт напрямую, например `--port COM3`.

<a id="run-tests"></a>
## Запуск тестов

Начните с проверки связи:

```sh
npm run diff -- --port "$SERVO_PORT" --case test_ping
```

Запустите группу по умолчанию:

```sh
npm run diff -- --port "$SERVO_PORT" --stage safe
```

Группа `safe` проверяет PING, чтение регистров и отказ от записи в регистр read-only. Он не приводит в движение двигатели, но отправляет пакет WRITE.

Выберите группу с помощью `--stage` или один конкретный сценарий с помощью `--case`:

```sh
npm run diff -- --port "$SERVO_PORT" \
  --case test_motion_write_order_gap_matrix --allow-motion
```

`--case` переопределяет `--stage`. Целенаправленные запуски используют существующие настройки сервопривода; они не устанавливают тестовую конфигурацию полного пакета. Проверьте указанные предварительные условия дела, если оно не может начаться.

| Разрешение | Позволяет |
|---|---|
| `--allow-motion` | Включение привода или выдача команд движения |
| `--allow-persistence-write` | Сохраненные настройки пишет, калибровка и restore-defaults |
| `--allow-template-write` | Замена сохраненного шаблона сброса |
| `--allow-current-protection` | Пройденные current-protection тесты; также требуется разрешение на движение |

Для полного пакета требуются все четыре разрешения и начальная скорость передачи данных 1000000:

```sh
npm run diff -- --port "$SERVO_PORT" --stage all \
  --allow-motion --allow-persistence-write \
  --allow-template-write --allow-current-protection
```

Добавьте `--fail-fast` для остановки после первого случая non-passing. В противном случае независимые случаи продолжаются после обычных сбоев. Невыполнение предварительных требований, сбои очистки и потеря связи останавливают дальнейшие тесты.

<a id="settings-and-cleanup"></a>
## Настройки и очистка

**Полный пакет не восстанавливает исходные настройки.** Он устанавливает сохраненную тестовую конфигурацию и завершает загрузку шаблона сброса сервопривода. Тест шаблона заменяет этот шаблон настройками пакета.

Эти целенаправленные тесты также имеют долгосрочный эффект:

- `prerequisites` включает restore-defaults и калибровку. Его тест смещения сохраняет новое смещение, которое помещает отображаемую позицию в 2048.
- `restore-defaults` загружает сохраненный шаблон сброса (`0x06`), который может отличаться от исходных настроек производителя.
- `template` заменяет шаблон сброса (`0x09`) активными настройками pre-test. Этот пакет не может прочитать или восстановить старый шаблон.

Другие случаи сохранения пытаются восстановить измененные ими настройки. Всегда проверяйте ошибки очистки перед следующим запуском. См. [руководство по резервному копированию и восстановлению настроек](../flash/README.md#restore-factory-settings) для получения информации о командах резервного копирования и восстановлении заводских настроек.

**Ctrl+C не гарантирует очистку или сохранение отчета.** У средства выполнения нет корректного обработчика прерываний. Если движение должно немедленно прекратиться, отключите питание двигателя; затем проверьте связь, настройки и состояние крутящего момента, прежде чем продолжить.

<a id="compare-against-a-saved-factory-run"></a>
## Сравните с сохраненным заводским запуском

Используйте те же случаи, версию пакета, скорость передачи данных и сопоставимые стендовые условия:

```sh
npm run diff -- --port "$SERVO_PORT" --mode factory --case test_ping

npm run diff -- --port "$SERVO_PORT" --mode candidate --case test_ping \
  --reference tools/hw-diff-tests/results/FACTORY_TIMESTAMP/report.json
```

Замените путь ссылки на отчет о первом запуске. Оставьте оригинальный заводской ID в `--factory-id`; кандидат должен иметь другой ID, даже при тестировании одного и того же физического сервопривода после прошивки. Пакет не меняет для вас ID. В режиме single-device случаи Pair-only пропускаются. Без `--reference` проход single-device проверяет только утверждения этого сценария, а не заводскую эквивалентность.

<a id="results"></a>
## Результаты

Отчеты сохраняются в папке `tools/hw-diff-tests/results/` или в каталоге, указанном в `--results`. Результаты и журналы игнорируются Git.

Откройте `report.json` для наблюдений, сравнений, переданных пакетов, полученных ответов и времени каждого устройства. Проверьте `fatal`, `cleanupError` и `closeError`, а также результаты кейса.

| Результат | Значение |
|---|---|
| `passed` | Утверждения и все доступные сравнения пройдены. |
| `mismatch` | Наблюдения фабрики и кандидата различались. |
| `failed` | Не удалось выполнить проверку утверждения, связи или восстановления. |
| `inconclusive` | Фабрика не дала нужного для сравнения эффекта |
| `skipped` | Дело не было возбуждено |

Код выхода **0** означает отсутствие сообщений о сбоях; пропущенные случаи могут остаться. **1** означает ошибку argument/setup или необработанное исключение. **2** означает, что отчет содержит сбой, несоответствие, неубедительный результат или ошибку cleanup/connection-close.

Синхронизация включает планирование хоста, USB и последовательные задержки; это не прямое измерение времени выполнения прошивки. Сохраните отчет и воспроизведите конкретный случай, прежде чем приписывать разницу в движении прошивке.
