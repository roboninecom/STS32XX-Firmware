# البرامج الثابتة فلاش

قم بفلاش البرامج الثابتة المخصصة أو المصنع على أجهزة متوافقة **GD32F130 STS TTL**. يقوم أحد القائمين بالتحميل بالتعامل مع كليهما؛ يحدد بيان الإصدار عمليات التحقق من التطبيق.

**تحذير: قد يؤدي تفليش البرامج الثابتة إلى إتلاف المؤازرة لديك أو مسح المعايرة أو تركها غير صالحة للاستخدام. استخدم هذه الأداة على مسؤوليتك الخاصة. الاسترداد غير مضمون.**

استخدم صورة البرنامج الثابت للناشر والمطابقة `release.json`، المحفوظة في نفس المجلد. إصدارات البرامج الثابتة الأولية غير مدعومة. تحقق من توافق أجهزة الإصدار قبل التفليش.

<a id="install"></a>
## تثبيت

يتطلب **Python 3.10 أو أحدث**. تشغيل من جذر المستودع:

```sh
python3 -m venv tools/flash/.venv
source tools/flash/.venv/bin/activate
python -m pip install -r tools/flash/requirements.txt
```

على نظام التشغيل Windows، قم بالتنشيط باستخدام `tools\flash\.venv\Scripts\Activate.ps1` بدلاً من ذلك.

<a id="choose-firmware"></a>
## اختر البرامج الثابتة

| البرامج الثابتة | واضح |
| --- | --- |
| ملحق مخصص v9 | قم بتنزيل صورة الناشر و`release.json` معًا في `tools/flash/releases/`. |
| مصنع **SCServo21-GD32-TTL 3.10** موديل **9.3** | مجمعة في [`factory/release.json`](../../../../../tools/flash/factory/release.json)، بجانب صورتها. |

صورة المصنع مخصصة فقط لمطابقة الأجهزة. استخدم البيان المحدد مع `inspect` أو `flash` أو `recover`؛ ليست هناك حاجة إلى أمر أو وضع منفصل للمصنع.

<a id="prepare"></a>
## الاستعداد

- يعمل التفليش العادي على إعادة ضبط المحرك المحدد ID فقط. قد تظل المحركات ذات المعرفات الفريدة متصلة؛ تفليشها بالتتابع بينما يعمل الآخرون بشكل طبيعي. لا power-cycle ناقل الاتصال أو تشغيل أداة تحميل أخرى أثناء النقل.
- من أجل **الاسترداد**، قم بتوصيل المؤازرة المقصودة فقط. لا يحدد الاسترداد محركًا بحلول ID، ولا تتم معالجة عمليات نقل أداة تحميل التشغيل.
- قم بتأمين الآلية، واستخدم قوة محرك ثابتة، وأغلق البرامج الأخرى باستخدام المنفذ التسلسلي.
- للتفليش العادي، قم بتعطيل عزم الدوران، وكتابة إعدادات القفل ومسح أي إنذار نشط باستخدام أداة التحكم المعتادة. معرفة التيار المؤازر ID ومعدل الباود.
- عمل نسخة احتياطية من المعايرة والإعدادات الهامة. ابدأ بالإعدادات المحفوظة في المؤازرة؛ يمكن أن تختفي التغييرات المؤقتة بعد إعادة التشغيل.

استبدل المنفذ و ID بالقيم الخاصة بك. معدل الباود الافتراضي هو **1,000,000**; أضف `--baud 500000`، على سبيل المثال، إذا لزم الأمر. المنافذ النموذجية هي `/dev/cu.usbmodem…` على نظام التشغيل macOS، `/dev/ttyUSB0` على Linux و`COM3` على Windows.

```sh
python tools/flash/settings.py backup \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2 \
  --file backups/servo-2-settings.json
```

احتفظ بهذه النسخة الاحتياطية لهذه المؤازرة بالضبط. لا تتم الكتابة فوق ملفات النسخ الاحتياطي الموجودة.

<a id="flash"></a>
## فلاش

التحقق من الإصدار المخصص الذي تم تنزيله وإصداره:

```sh
python tools/flash/flash.py inspect \
  --manifest tools/flash/releases/release.json

python tools/flash/flash.py flash \
  --manifest tools/flash/releases/release.json \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2
```

لتثبيت البرنامج الثابت المجمع للمصنع، حدد البيان الخاص به بدلاً من ذلك. عزل المؤازرة لهذه العملية: قد يغير بدء تشغيل المصنع ID إلى 1، مما يتعارض مع محرك آخر في ناقل الاتصال.

```sh
python tools/flash/flash.py flash \
  --manifest tools/flash/factory/release.json \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2
```

`inspect` يتحقق من حجم الملف والمجموع الاختباري والبيان دون الاتصال بالمؤازرة. اكتب `FLASH` عندما يُطلب منك ذلك. حافظ على توصيل الطاقة حتى انتهاء الأمر. تقوم الأداة بفحص المؤازرة، وحفظ لقطة الإعدادات الخاصة بها، وتحميل البرنامج الثابت، ثم التحقق من التطبيق ومقارنة الإعدادات. يؤدي التحقق الناجح إلى تعطيل عزم الدوران.

بعد تفليش المصنع، تتحقق الأداة من ID/baud السابق، ثم ID **1** عند **1,000,000** الباود إذا لزم الأمر، وتطبع اتصال العمل. رمز الخروج **2** يعني أن البرنامج الثابت للمصنع استجاب ولكن تم تغيير الإعدادات. تابع إصلاح الإعدادات أدناه بدلاً من التفليش مرة أخرى.

<a id="recover-an-unresponsive-servo"></a>
## استعادة أجهزة لا تستجيب

تحقق أولاً من الطاقة والأسلاك وID ومعدل الباود. إذا كانت هناك حاجة إلى الاسترداد، قم بتوصيل **فقط المؤازرة المقصودة** واستخدم البيان المحدد. على سبيل المثال، للاسترداد باستخدام البرامج الثابتة للمصنع:

```sh
python tools/flash/flash.py recover \
  --manifest tools/flash/factory/release.json \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 1
```

بعد التأكيد، **power-cycle المؤازرة عند المطالبة**، مع ترك المحول USB متصلاً. تنتظر الأداة ما يصل إلى 60 ثانية حتى يتم تشغيل أداة تحميل التشغيل.

استخدم ID ومعدل الباود المتوقع بعد التعافي. لا يمكن للاسترداد التحقق من النموذج الحالي أو نسخ الإعدادات احتياطيًا قبل التحميل، لذا تأكد من توافق الأجهزة بنفسك. تحقق من المعايرة وحدود الموضع قبل تمكين عزم الدوران بعد ذلك.

<a id="restore-factory-settings"></a>
## استعادة إعدادات المصنع

بعد العودة إلى البرامج الثابتة للمصنع، قم باستعادة النسخة الاحتياطية لهذا المؤازرة حتى لو كانت الإعدادات تبدو صحيحة في البداية. قد تستخدم البرامج الثابتة للمصنع الإعدادات الافتراضية built-in عندما تكون إعداداتها المحفوظة غير صالحة؛ قد لا تؤدي عمليات كتابة التسجيل العادية إلى إصلاح هذا الأمر.

استخدم **التيار** ID/baud المطبوع بعد التفليش. على سبيل المثال، إذا كانت الإجابة الآن بالشكل ID 1:

```sh
python tools/flash/settings.py restore \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 1 \
  --file backups/servo-2-settings.json
```

اكتب `RESTORE` للتأكيد. هذا يدعم المصنع **3.10** ويرفض البرامج الثابتة المخصصة المكتشفة. فهو يستعيد الإعدادات، و**يستبدل قالب إعادة التعيين المحفوظ**، ويصلح الإعدادات المحفوظة، ويقفل عمليات الكتابة، ويعيد تشغيل المؤازرة. إنه يتبع أي تغييرات ID/baud ويتحقق من إعادة القراءة دون إرسال أوامر الحركة.

ثم **power-cycle المؤازرة** وتحقق باستخدام **المستعادة** ID/baud:

```sh
python tools/flash/settings.py verify \
  --port /dev/cu.usbmodemYOUR_ADAPTER --id 2 \
  --file backups/servo-2-settings.json
```

حافظ على عزم الدوران بعيدًا حتى يتم التحقق. يمكنك أيضًا توفير فلاش عادي `report.json` يحتوي على لقطة before-flash كـ `--file`. لا يمكن للنسخ الاحتياطية التي تم التقاطها بعد فقدان الإعدادات استعادة المعايرة الأصلية. بدون نسخة احتياطية صالحة، احصل على إعدادات النموذج الدقيق وأعد معايرة هذا المؤازرة.

في حالة الفشل، يحاول الإصلاح إعادة قفل الإعدادات ولكنه لا يتراجع عن عمليات الكتابة الجزئية أو يعيد محاولة الإصلاح تلقائيًا. احفظ التقرير قبل التحقيق.

<a id="results-and-options"></a>
## النتائج والخيارات

يتم حفظ تقارير الفلاش ضمن `backups/flash/`؛ تقارير الإعدادات ضمن `backups/settings/`. يتضمن كلاهما لقطات الإعدادات المتاحة. يتضمن التحميل الناجح فحوصات التطبيق؛ ولا يقرأ صورة البرنامج الثابت الكاملة. لا تتم استعادة الإعدادات تلقائيًا.

- `--output DIRECTORY`: اختر مكان حفظ التقارير.
- `--yes`: تخطي رسالة التأكيد؛ كافة الشيكات لا تزال قيد التشغيل.
- `--help`: إظهار خيارات الأمر.

إذا فشل التحقق من صحة الملف، احصل على زوج إصدار مطابق. إذا تمت مقاطعة التفليش، فقد يحتاج السيرفو إلى الاسترداد. إذا انتهى النقل ولكن فشل التحقق، فافحص التقرير وتحقق من ID ومعدل الباود والإعدادات قبل إعادة المحاولة.

بالنسبة لمؤلفي الإصدار، يعرض [release.example.json](../../../../../tools/flash/release.example.json) بيانًا مخصصًا و[factory/release.json](../../../../../tools/flash/factory/release.json) بيان المصنع. المثال المخصص ليس إصدارًا قابلاً للاستخدام للبرنامج الثابت.
