# تسجيل وإعادة يطرح

سجل المواضع المسماة مع إيقاف عزم الدوران، ثم أعد تشغيلها إما باستخدام الإعدادات القديمة المحفوظة أو إعدادات الامتداد المضبوطة. يتم تشغيل الأوامر من جذر المستودع.

| الأمر | الإدخال | البرامج الثابتة |
| --- | --- | --- |
| `npm run record-poses` | تحديد المواقع يدويا | المصنع أو العرف |
| `npm run replay` | يطرح اسمه أو جلسة العمل عن بعد | ملحق v9 |
| `npm run replay-legacy` | يطرح اسمه | مصنع أو مخصص v9 |

<a id="record-poses"></a>
## سجل يطرح

قم بتثبيت Node.js 20 أو الأحدث، ثم قم بتشغيله من جذر المستودع:

```sh
npm install
npm run record-poses -- --port /dev/ttyUSB0 --ids 1,2,3
```

استبدل المنفذ والمعرفات الخاصة بالإعداد الخاص بك. الأعلام الاختيارية هي `--baud` (الافتراضي 1000000)، `--output DIR`، و`--timeout-ms` (الافتراضي 1000).

قم بإنهاء [معايرة الإزاحة والحد](../settings/README.md#calibrate-joint-offsets-and-limits) أولاً. الأوضاع المسجلة هي نقاط طريق للحركة. التقاط الوضع المسمى `home` أو `reference` لا يغير معايرة المحرك.

1. ادعم الآلية حتى لا تسقط عند تحرير عزم الدوران.
2. اضغط على Enter في رسالة التأكيد. يقوم المُسجل بتعطيل عزم الدوران في المحركات المحددة والتحقق من إيقاف تشغيله. لا يتم تغيير المحركات الأخرى.
3. حرك الآلية، وأمسكها بثبات، ثم اضغط على Enter لالتقاط الوضع. يمكنك كتابة اسم فريد بدلاً من ذلك؛ تصبح الأوضاع غير المسماة `position-1`، `position-2`، وما إلى ذلك.
4. كرر حسب الحاجة. اكتب `done` للإنهاء أو اضغط على Ctrl+C للمقاطعة.

يظل عزم الدوران متوقفًا بعد التسجيل. تكون القراءات متسلسلة، لذا فإن كل وضعية هي لقطة لآلية ثابتة، وليست قياسًا متزامنًا للحركة. تؤدي القراءة المفقودة أو التنبيه أو المحرك الممكّن إلى إيقاف الجلسة. عند الخروج، تحاول الأداة تعطيل عزم الدوران مرة أخرى وتبلغ عن أي فشل في التحقق.

<a id="saved-files"></a>
## الملفات المحفوظة

يتم إنشاء ملف JSON جديد في `tools/poses/recordings/` لكل جلسة. كل عملية التقاط ناجحة تحل محل هذا الملف ذريًا؛ تظل الأوضاع المحفوظة مسبقًا متاحة في حالة فشل الالتقاط اللاحق. يتم تجاهل التسجيلات بواسطة Git.

يحدد التنسيق `sts-poses` الإصدار 1 المواضع حسب المحرك ID، وليس ترتيب المصفوفة:

```json
{
  "format": "sts-poses",
  "version": 1,
  "units": "encoder-counts",
  "ids": [1, 3],
  "readMode": "sequential",
  "poses": [
    {
      "name": "home",
      "capturedAt": "2026-10-24T12:00:00.000Z",
      "durationMs": 4.2,
      "positions": {"1": 2048, "3": 3100}
    }
  ]
}
```

تتضمن الملفات أيضًا وقت الجلسة والمنفذ التسلسلي ومعدل الباود. وضع علامة الطوابع الزمنية عند بدء القراءة؛ `durationMs` يقيس الاستحواذ الكامل. يتم توقيع الأعداد على المواضع المُبلغ عنها، بما في ذلك بالفعل إزاحة المحرك وإعدادات الاتجاه، دون التحويل إلى زوايا. لا يحتوي الملف على إعدادات السرعة أو التسارع أو توقيت التشغيل، ولا يحتوي على لقطة للمعايرة. Re-record الوضعية بعد تغيير معايرة جهاز التشفير؛ لا يمكن لإعادة التشغيل اكتشاف أن ملف الوضع القديم يستخدم إزاحات مختلفة.

<a id="replay-poses"></a>
## إعادة يطرح

انسخ [replay.example.json](../../../../../tools/poses/replay.example.json) بجانب النص الأصلي، على سبيل المثال `tools/poses/controller.local.json`. اضبط `followerPort` وقم بتوفير إدخال `profiles` واحد لكل محرك مسجل. المعرفات تأتي من التسجيل. ليست هناك حاجة إلى قائد أو رسم خرائط مشترك. يشير المثال إلى [ملف تعريف المحرك](../../../../../host/arm-control/profile.example.json). انسخ ملف التعريف هذا لإعداداتك الخاصة وقم بتحديث مساره، أو قم بوضع الإعدادات في السطر. جميع مسارات الملفات الشخصية والجاذبية مرتبطة بملف وحدة التحكم. توضح مكاسب المثال التنسيق؛ استخدم الإعدادات التي تم اختبارها على آليتك.

```sh
npm run replay -- CONFIG.json POSES.json
npm run replay -- CONFIG.json POSES.json --run
```

يقوم الأمر الأول بمعاينة المسار الكامل دون تغيير الإعدادات وتقارير الأهداف المحددة بالحدود المحفوظة. `--run` يبدأ الحركة، بما في ذلك الاقتراب من الوضع الحالي إلى الوضع الأول. يتم فتح منفذ التابع فقط. يتم قبول الملفات التي تصل إلى 64 MiB والتحقق من صحتها قبل فتح المنفذ.

تطبق [وحدة التحكم المشتركة](../../host/arm-control/README.md) ملفات التعريف، وتتعامل مع الجلسات الحالية التي تعمل بالطاقة، وتوفر تعويض الجاذبية عند تكوين `gravityModel`. **الإكمال العادي مع الاحتفاظ بالضغط على Ctrl+C.** تستخدم الأخطاء عملية تنظيف وحدة التحكم؛ Ctrl+C ليس توقفًا طارئًا. اختياري top-level `durationMs` ينهي التشغيل مبكرًا؛ حذفه لإعادة تشغيل الملف بأكمله.

يتم إرسال كل وضعية في أمر مجموعة واحدة. يتم قياس سرعات المفاصل مع مسافة السفر، مع مراعاة سرعة إعادة التشغيل والحد الأقصى لسرعة كل محرك. يولد كل محرك S-curve خاصًا به، لذا يكون الوصول تقريبيًا ولا يتم دمج نقاط الطريق. ينتظر التشغيل حتى انتهاء المخططات ودخول جميع المواضع المقاسة `toleranceCounts`، ثم يبدأ التعليق. فشل التحرك الذي يتجاوز `moveTimeoutMs`. الطوابع الزمنية المسجلة يدويًا لا تحدد سرعة التشغيل.

| `replay` الإعداد | الافتراضي | معنى |
| --- | --- | --- |
| `speed` | 1000 | السرعة القصوى، 1–65535 التشفير counts/s. |
| `holdMs` | 1000 | توقف مؤقتًا بعد الوصول، 0–600000 مللي ثانية. |
| `repeat` | 1 | عدد التمريرات، 1–1000؛ تعود كل تمريرة إلى الوضع الأول. |
| `moveTimeoutMs` | 30000 | مهلة الوصول، 1–600000 مللي ثانية. |
| `toleranceCounts` | 10 | خطأ الموضع المقاس المسموح به، 0–32767. |

<a id="replay-a-recorded-session"></a>
## إعادة تشغيل جلسة مسجلة

إعادة تشغيل سجل العملية عن بعد دون توصيل القائد:

```sh
npm run replay -- CONFIG.json SESSION.ndjson
npm run replay -- CONFIG.json SESSION.ndjson --run
```

يجب أن يحتوي التسجيل على `preflight` مع حدود القائد ورسم الخرائط المشتركة، متبوعة بأحداث `command` ذات طوابع زمنية رتيبة وجميع مواقع القائد. استخدم نفس التعيين المشترك في التكوين الحالي. يتم تعيين مواقع القائد المسجلة من خلال حدود القائد المسجلة والحدود الحالية للتابع. يتم تطبيق الملامح الحالية والجاذبية. لا يتم إعادة استخدام الإعدادات والجهود التاريخية. قد لا يصل الأمر المقصود في السجل الفاشل إلى المحركات أبدًا.

يحافظ التشغيل على الفجوات المسجلة؛ تؤدي المعالجة إلى تأخير التوقيت بدلاً من إرسال رشقات نارية catch-up. تستمر التعليقات وتحديثات الجاذبية أثناء فترات التوقف المؤقت. `replay.repeat`، `moveTimeoutMs` و`toleranceCounts` تنطبق؛ `speed` و`holdMs` تنطبق فقط على الأوضاع المسماة. يجب أن يصل الإطار الأخير قبل الانتهاء.

<a id="legacy-replay"></a>
## إعادة تراث

استخدم إعدادات PID المحفوظة للمحركات دون تغذية سرعة التمديد أو تعويض الجاذبية. ليست هناك حاجة إلى ملف وحدة تحكم ولا تتغير الإعدادات المستمرة. تحتاج المحركات إلى وضع الموضع المطلق ودقة تشفير الوحدة.

```sh
npm run replay-legacy -- POSES.json --port /dev/ttyUSB0
npm run replay-legacy -- POSES.json --port /dev/ttyUSB0 --run
```

معاينات الأمر الأول؛ `--run` التحركات. تأتي المعرفات من ملف الوضع؛ يتم ترك المحركات الأخرى الموجودة على المحول بمفردها. تتحول البرامج الثابتة المخصصة إلى الوضع القديم. يتم تعطيل الإعداد لفترة وجيزة وre-enables كل محرك محدد، مع تحديد موضعه الحالي أولاً.

| الخيار | الافتراضي | معنى |
| --- | --- | --- |
| `--speed` | 1000 | السرعة القصوى، 1–32767 التشفير counts/s. |
| `--acceleration` | 5000 | Counts/s²، 100–25400 في مضاعفات 100. تنطبق الحدود المحفوظة. |
| `--hold-ms` | 1000 | انتظر بعد كل خطوة مخططة، 0–600000 مللي ثانية. |
| `--baud` | 1000000 | معدل الباود محول. |

يستخدم كل وضع أمرًا جماعيًا وسرعات distance-scaled للوصول المتزامن تقريبًا. يتم تقييد الأهداف بحدود المواضع المحفوظة. ينتظر التشغيل حتى تنتهي ملفات تعريف الحركة الداخلية، ثم يستمر في الانتظار؛ لا يتطلب خطأ موضعي مقاس صفر. تفشل الحركة التي تستمر لأكثر من 30 ثانية.

الانتهاء يحتفظ بعزم الدوران في الوضع النهائي. على عكس إعادة تشغيل الامتداد، **Ctrl+C يحاول torque-off**، كما تفعل الفاشلات. تم الإبلاغ عن فشل عملية التنظيف.

<a id="logs-and-visualization"></a>
## السجلات والتصور

يقوم كلا أمري إعادة التشغيل بحفظ السجلات في `logs/motion/` المتجاهلة، بما في ذلك المعايرة وهوية المصدر والأوامر والتعليقات. قم بتشغيل [عارض القياس عن بعد](../simulation/README.md) مرة واحدة، ثم قم بتشغيل عمليات الإعادة في محطة طرفية أخرى:

```sh
mkdir -p logs/motion
tools/simulation/.venv/bin/python tools/simulation/viewer.py live logs/motion --model so102
```

استخدم `--model so101` للنموذج المجمع الآخر ورسم خرائط التشفير المطابق. تقرأ إعادة تشغيل الامتداد التعليقات التفصيلية للمرجع المتحرك الذي يعرضه المشاهد. لتقليل حركة المرور، قم بإلحاق `--compact`; تظل الحركة المقاسة والتعويض نشطين، لكن الظل يظهر الوجهات بدلاً من مواضع المخطط المتوسطة. PID تم أيضًا حذف الشروط ومساهمات التعويض المطبقة. انظر [الملاحظات والتوقيت](../../host/arm-control/README.md#checks-and-timing).

قم بتشغيل التسجيل في وضع عدم الاتصال وإعادة التشغيل الإضافي واختبارات إعادة التشغيل القديمة باستخدام `npm run test:poses`.
