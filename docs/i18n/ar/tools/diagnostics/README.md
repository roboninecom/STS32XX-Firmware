# معيار ناقل الاتصال وتشخيص القياس عن بعد

أداتان command-line لـ STS الماكينات: قياس أداء الاتصال والتحقق من القياس عن بعد الثابت للحصول على قراءات غير عادية. يتطلب Node.js 20 أو أحدث. من جذر المستودع، قم بتثبيت التبعيات باستخدام `npm install`.

أبقِ المحركات ثابتة مع إيقاف عزم الدوران وقفل الإعدادات. أوقف البرامج الأخرى باستخدام المنفذ التسلسلي. تقوم كلتا الأداتين بفحص الماكينات المحددة قبل التشغيل وبعده. لا يعمل أي منهما على تمكين عزم الدوران أو تحريك المحرك أو تفليش البرامج الثابتة أو حفظ الإعدادات.

<a id="bus-benchmark"></a>
## معيار ناقل الاتصال

```sh
npm run bus-benchmark -- --port /dev/cu.usbmodemXXXX --ids 1,2 --repetitions 1000
```

افتراضيًا، يتم قياس الطلبات PING وREAD بأحجام مختلفة. تقوم كل حالة بتشغيل 20 محاولات إحماء، ثم 1,000 محاولات مقاسة لكل محرك. يدور أمر المحرك بين الجولات. المحاولات الفاشلة تبقى فاشلة؛ إعادة المحاولة لا تحل محلها أبدًا.

خيارات مفيدة:

- `--list`: قائمة الحالات دون فتح منفذ.
- `--cases ping,read-table-87`: تشغيل الحالات المحددة.
- `--warmup 20`، `--repetitions 1000`: محاولات لكل حالة ومحرك.
- `--gap-ms 1`: وقفة بين الطلبات؛ الافتراضي هو عدم وجود وقفة إضافية.
- `--results DIR`: أصل الإخراج؛ الافتراضي هو `tools/diagnostics/results`.
- `--include-writes`: يتم أيضًا كتابة المعيار القياسي إلى RAM السجلات 51–54. هذه السجلات غير موثقة على البرامج الثابتة الأخرى؛ استخدم هذا الخيار فقط على أجهزة متوافقة تم التحقق منها. تتم استعادة القيم الأصلية عند الاكتمال أو الفشل أو الانقطاع السلس. يجب تمكين إقرارات الكتابة.

يقوم كل تشغيل بإنشاء دليل جديد يحتوي على `summary.csv` و`report.json` و`samples.jsonl`. يتضمن الملخص الوسيط وp95 وp99 والحد الأقصى لوقت الاستجابة، بالإضافة إلى عدد المهلة والأخطاء. تتضمن السجلات الأولية تبادلات الإحماء والتنظيف.

يتم تشغيل زمن الوصول من مكالمة الكتابة التسلسلية إلى الرد المطابق الذي تم فك ترميزه. يتضمن USB و operating-system تأخيرات؛ إنه ليس وقت استجابة firmware-only أو قياس السعة القصوى للحافلة. يتم حساب المهلات بشكل منفصل، ولا يتم تضمينها في النسب المئوية لزمن الوصول.

<a id="telemetry"></a>
## القياس عن بعد

```sh
npm run telemetry -- --port /dev/cu.usbmodemXXXX --ids 1,2 \
  --samples 1000 --interval-ms 20 --output tools/diagnostics/results/telemetry-check
```

يقرأ 17 بايت بدءًا من التسجيل 56، مرة واحدة لكل محرك في كل جولة. الافتراضي هو 100,000 عينات لكل محرك بدون توقف إضافي. استخدام دليل إخراج جديد لكل تشغيل؛ لا يتم الكتابة فوق ملفات العينات الموجودة أبدًا.

- `--interval-ms 20`: الحد الأدنى للفاصل الزمني بين بداية الجولة. يتم تخطي الفتحات المفقودة وإحصاءها في `missedDeadlines`؛ الجولات المتأخرة لا تسبب انفجارات.
- `--gap-ms 1`: بدلاً من ذلك، توقف مؤقتًا بعد كل طلب للمحرك. لا يمكن دمجه مع `--interval-ms`.
- `--voltage-min 5.5 --voltage-max 8.4`: نطاق الجهد المتوقع بالفولت؛ الإعدادات الافتراضية هي 8–16 V. اضبط هذا للمحركات المتصلة ومصدر الطاقة.

المخرجات: `samples.csv` يحتوي على كل محاولة، `anomalies.jsonl` يحتوي على القراءات المميزة والتبادلات الأولية، و`report.json` يحتوي على الأعداد والنطاقات وإحصائيات التوقيت وإعدادات before/after. CSV الجهد بعشر فولت؛ يحتفظ الموقع والسرعة والتيار والجهد بوحدات التسجيل الأولية الخاصة بهم.

يتحقق من تغيرات جهد العلم ودرجة الحرارة والقراءات غير المعقولة والحالة غير الصفرية والجهد أثناء إيقاف عزم الدوران. يتطلب الكشف عن ارتفاع درجة الحرارة ثلاثة ردود صحيحة متتالية؛ الرد المفقود أو غير الصالح يكسر التسلسل. تحدد هذه العلامات القراءات التي يجب فحصها، وليس دليلاً على وجود خطأ في البرامج الثابتة أو المستشعر. القراءات الثابتة المتطابقة طبيعية ولا تثبت البيانات القديمة.

<a id="common-options-and-tests"></a>
## الخيارات والاختبارات الشائعة

تقبل كلتا الأداتين `--baud 1000000` و`--timeout-ms 100` و`--help`. المعرفات الافتراضية هي `1,2`؛ تحديد المحركات المتصلة بالفعل. تبدأ مهلة الرد بعد استنزاف الكتابة التسلسلية. بعد انتهاء المهلة، تنتظر الأدوات ناقلًا هادئًا قبل المتابعة لأن الردود لا تحتوي على أرقام تسلسلية.

يقوم Ctrl+C بإيقاف التشغيل وإجراء عملية التنظيف. تنتج الأخطاء وعمليات التشغيل غير المكتملة والعينات التي تم وضع علامة عليها رمز خروج غير صفري. يتم تجاهل النتائج الموجودة ضمن `results/` بواسطة Git.

```sh
npm run test:diagnostics
```

لا تتصل هذه الاختبارات دون اتصال بالأجهزة.
