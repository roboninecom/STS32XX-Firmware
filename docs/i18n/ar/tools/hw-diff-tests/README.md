# اختبارات مقارنة الأجهزة

قارن بين البرامج الثابتة الخاصة بالمصنع والبرامج الثابتة المخصصة على الماكينات STS. يغطي الجناح البروتوكول القديم والإعدادات والحركة والمعايرة والحماية. ولا يختبر التحكم في بروتوكول الامتداد v9. تستخدم الاختبارات [برنامج التشغيل المشترك](../../host/servo-driver/README.md)] الخاص بالمستودع.

**استخدم مقعدًا مخصصًا مزودًا بماكينات مؤازرة آمنة وأعمدة حرة.** تقوم بعض الاختبارات بإجراء حركات طويلة أو مستمرة واستبدال الإعدادات أو المعايرة المحفوظة. قم بعمل نسخة احتياطية لكل أجهزة أولاً. احتفظ بطريقة لفصل طاقة المحرك على الفور.

<a id="setup"></a>
## الإعداد

قم بتثبيت Node.js **20 أو الأحدث**، ثم قم بتشغيله من جذر المستودع:

```sh
npm ci
npm run test:diff
npm run diff -- --list
```

تعمل هذه الأوامر دون اتصال بالإنترنت. `--list` يعرض مرحلة كل سيناريو وتصنيف الحركة والاسم الدقيق. استخدم `--help` لجميع خيارات الأوامر.

قم بتوصيل ماكينات الاختبار فقط: تستخدم بعض الحالات عمليات البث. أغلق البرامج الأخرى باستخدام المحول وقم بتوفير مصدر محرك مناسب. الاتصالات الافتراضية هي:

| الإعداد | الافتراضي |
|---|---|
| سيرفو المصنع ID | `1` |
| أجهزة البرامج الثابتة المخصصة ID | `2` |
| معدل الباود | `1000000` |

قم بتعيين قيم مختلفة باستخدام `--factory-id` و`--candidate-id` و`--baud`. يجب أن تكون المعرفات مميزة؛ اترك المعرفات **250 و 251** غير مستخدمة لأن الاختبارات تستخدمها مؤقتًا. ابدأ بإيقاف عزم الدوران، وتكون الإعدادات مقفلة ولا توجد إنذارات نشطة. استخدم محركات ومصادر طاقة وأحمال مماثلة عند مقارنة الحركة.

```sh
export SERVO_PORT=/dev/cu.usbmodemYOUR_ADAPTER
```

استبدل المنفذ بمنفذ خاص بك. يستخدم Linux بشكل شائع `/dev/ttyUSB0`؛ على نظام Windows، قم بتمرير منفذ مباشرة، مثل `--port COM3`.

<a id="run-tests"></a>
## تشغيل الاختبارات

ابدأ بفحص الاتصال:

```sh
npm run diff -- --port "$SERVO_PORT" --case test_ping
```

تشغيل المجموعة الافتراضية:

```sh
npm run diff -- --port "$SERVO_PORT" --stage safe
```

تقوم مجموعة `safe` بفحص PING وقراءة السجل ورفض الكتابة إلى سجل read-only. إنها لا تقود المحركات، ولكنها ترسل حزمة WRITE.

حدد مجموعة تحتوي على `--stage`، أو سيناريو واحد محدد باستخدام `--case`:

```sh
npm run diff -- --port "$SERVO_PORT" \
  --case test_motion_write_order_gap_matrix --allow-motion
```

`--case` يتجاوز `--stage`. تستخدم عمليات التشغيل المركزة إعدادات المؤازرة الموجودة؛ ولا يقومون بتثبيت التكوين الاختباري للمجموعة الكاملة. تحقق من المتطلبات الأساسية التي تم الإبلاغ عنها للحالة إذا لم تتمكن من البدء.

| إذن | يسمح |
|---|---|
| `--allow-motion` | تمكين القيادة أو إصدار أوامر الحركة |
| `--allow-persistence-write` | الإعدادات المحفوظة تكتب ومعايرة وrestore-defaults |
| `--allow-template-write` | استبدال قالب إعادة التعيين المحفوظ |
| `--allow-current-protection` | اختبارات current-protection مدفوعة؛ يحتاج أيضًا إلى إذن الحركة |

يتطلب الجناح الكامل جميع الأذونات الأربعة ومعدل باود أولي قدره 1000000:

```sh
npm run diff -- --port "$SERVO_PORT" --stage all \
  --allow-motion --allow-persistence-write \
  --allow-template-write --allow-current-protection
```

أضف `--fail-fast` للتوقف بعد الحالة non-passing الأولى. وبخلاف ذلك، تستمر الحالات المستقلة بعد حالات الفشل العادية. تؤدي المتطلبات الأساسية الفاشلة وفشل التنظيف وفقد الاتصال إلى إيقاف إجراء المزيد من الاختبارات.

<a id="settings-and-cleanup"></a>
## الإعدادات والتنظيف

**لا تقوم المجموعة الكاملة باستعادة إعداداتك الأصلية.** فهي تقوم بتثبيت تكوين اختبار محفوظ وتنتهي عن طريق تحميل قالب إعادة تعيين المؤازرة. يستبدل اختبار القالب هذا القالب بإعدادات المجموعة.

هذه الاختبارات المركزة لها أيضًا تأثيرات دائمة:

- `prerequisites` يشمل restore-defaults والمعايرة. يحفظ اختبار الإزاحة الخاص به إزاحة جديدة تضع الموضع المعروض عند 2048.
- `restore-defaults` يقوم بتحميل قالب إعادة التعيين المحفوظ (`0x06`)، والذي قد يختلف عن الإعدادات الأصلية للشركة المصنعة.
- `template` يستبدل قالب إعادة التعيين (`0x09`) بالإعدادات النشطة pre-test. لا يمكن لهذا الجناح إعادة قراءة القالب القديم أو استعادته.

تحاول حالات الاستمرار الأخرى استعادة الإعدادات التي تم تغييرها. قم دائمًا بفحص أخطاء التنظيف قبل إجراء تشغيل آخر. راجع [دليل النسخ الاحتياطي والاسترداد للإعدادات](../flash/README.md#restore-factory-settings) للحصول على أوامر النسخ الاحتياطي واسترداد المصنع.

**لا يضمن Ctrl+C إجراء التنظيف أو حفظ التقرير.** لا يوجد لدى العداء معالج انقطاع أنيق. إذا كان يجب أن تتوقف الحركة على الفور، افصل طاقة المحرك؛ ثم تحقق من الاتصال والإعدادات وحالة عزم الدوران قبل المتابعة.

<a id="compare-against-a-saved-factory-run"></a>
## قارن مع تشغيل المصنع المحفوظ

استخدم نفس الحالات ومراجعة المجموعة ومعدل الباود وظروف المقعد المماثلة:

```sh
npm run diff -- --port "$SERVO_PORT" --mode factory --case test_ping

npm run diff -- --port "$SERVO_PORT" --mode candidate --case test_ping \
  --reference tools/hw-diff-tests/results/FACTORY_TIMESTAMP/report.json
```

استبدل المسار المرجعي بتقرير التشغيل الأول. احتفظ بالمصنع الأصلي ID في `--factory-id`؛ يجب أن يكون لدى المرشح ID مختلف، حتى عند اختبار نفس المؤازرة الجسدية بعد التفليش. الجناح لا يغير ذلك ID بالنسبة لك. Pair-only يتم تخطي الحالات في الوضع single-device. بدون `--reference`، يتحقق تمرير single-device فقط من تأكيدات هذا السيناريو، وليس معادلة المصنع.

<a id="results"></a>
## النتائج

يتم حفظ التقارير تحت `tools/hw-diff-tests/results/`، أو الدليل المزود بـ `--results`. يتم تجاهل النتائج والسجلات بواسطة Git.

افتح `report.json` لملاحظات ومقارنات كل جهاز والحزم المرسلة والاستجابات المستلمة والتوقيت. افحص `fatal` و `cleanupError` و `closeError` بالإضافة إلى نتائج الحالة.

| النتيجة | معنى |
|---|---|
| `passed` | تم تمرير التأكيدات وأي مقارنة متاحة |
| `mismatch` | اختلفت ملاحظات المصنع والمرشح |
| `failed` | فشل التأكيد أو الاتصال أو التحقق من الاسترداد |
| `inconclusive` | لم ينتج المصنع التأثير المطلوب للمقارنة |
| `skipped` | لم يتم تشغيل القضية |

رمز الخروج **0** يعني عدم وجود حالات فشل تم الإبلاغ عنها؛ قد تبقى الحالات التي تم تخطيها. **1** يعني خطأ argument/setup أو استثناء لم تتم معالجته. **2** يعني أن التقرير يحتوي على فشل أو عدم تطابق أو نتيجة غير حاسمة أو خطأ cleanup/connection-close.

يتضمن التوقيت جدولة المضيف، USB والتأخير التسلسلي؛ إنه ليس قياسًا مباشرًا لوقت تنفيذ البرامج الثابتة. احتفظ بالتقرير وأعد إنتاج الحالة المركزة قبل إسناد اختلاف الحركة إلى البرامج الثابتة.
